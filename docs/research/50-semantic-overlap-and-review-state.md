## 类型重叠的默认契约

[重叠规则](../../configs/tasks/slurp/type-overlap-contract-candidate-v1.json)将S定义为独立
语义谓词：同一表达在各自定义、存在政策和范围下均有证据时，允许多个true。无需
从原生单词段标注反推出一个全局“只能选一种类型”的优先级。

这也不等于语义上属于某类就自动继承所有上位标签。类型定义可以要求具体的角色，
不能因为知道某歌手是人，就不看请求与person定义直接补person。角色证据不足时仍
保持unresolved；不能把“可能是应用也可能是电台”改成两个true。显式互斥须来自
冻结的任务规则，不能从标注频率或某类型未出现来推断。

本轮以固定工作包重算全部9,192来源、40,513录音的原生实体关系：不同类型实体实例
对有3,434个，涉及201种类型对；词段相交为0，同词段多类型为0。这是原生标注结构，
不是语义互斥证明。计数单位是来源句中的实体实例对，不是录音数、唯一句对或复杂
推理样本数。证据见[全量审计](semantic-overlap-and-proposal-audit-v1.json)。

重叠规则是新Jev语义任务的候选，不能宣称完整重现原生token-span标注。当前55卡和
89边界规则中的未决项还须逐项对齐，不能仅引用通用规则就把所有歧义标成已解决。
三个配套人工例仅检验逻辑区别，没有音频，不当作数据集真值或模型理解成绩。

## 旧conflict状态混合了两个不同问题

既有`bind_slot_reference_adjudications.py`要求：若建议值与native不同，status必须为
conflict。现有训练投影也要求review与native一致，修改须另行发布。两者保留原行为，
不放宽校验。新的语义任务则需要单独保存：

| 字段 | 含义 | 当前值域/状态 |
|---|---|---|
| semantic_proposal | 在特定定义/政策下提出的语义判决 | proposed + bool，或 unresolved + null |
| native_projection | 原生标注投影及与建议值的关系 | agrees / disagrees / not_assessed |
| admission | 是否得到正式监督发布资格 | 全部pending，admitted value为null |

因此，CST/EST作为时区有一个明确true建议，同时原生缺少time_zone，可记为
proposed=true、native=false、disagrees；这不是自动认证原生错误，更不是准入训练。
“Pandora radio”是否明确指向电台尚未解决，则仍是unresolved，不强行生成负例。
