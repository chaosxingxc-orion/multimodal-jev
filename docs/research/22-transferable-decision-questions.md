# 同任务跨数据集的判决 Q

2026-11-12。依据用户进一步明确：研究核心是抽象不同任务的逻辑判决要素，定义可配置、
可跨数据集复用的Q，训练其判别能力并检验Final收益。补充21：语义规约不能只停留在
总体思考要求，必须落实为语义明确、可评分的判决变量。

## 1. Q的抽象单位

```
Q = 判决算子(任务配置提供的概念定义、关系定义、适用规则)
answer = Jev(音频query, 全部已配置Q及Final)
```

固定的是逻辑问法，变化的是定义参数。例如“query是否表达定义I的意图”，可以配置
SLURP的某项服务意图，也可以配置FSC的设备命令；无需提前知道query属于哪个主题。
“query是否包含定义S的槽位类型”以语义角色为依据，不是查标签名是否出现在语音中。
选哪些定义仍由任务配置确定，不能由gold、参考转写或离线复杂度选择。

## 2. 从原子到组合的逻辑要素

| Q算子 | 逻辑判决要素与示例模板 | 监督前提 | 对Final的作用 |
|---|---|---|---|
| 意图成立 I(query, definition) | query是否表达满足该定义的用户意图？ | 意图集合及标注范围明确；单标签不保证所有其他意图语义上不存在 | 单/多意图决策的基本单位 |
| 槽位类型存在 S(query, definition) | query中是否有满足该槽位角色定义的表达？ | 正例角色可靠；负例需该类型标注完备 | 类型集合预测；不能据此声称槽值抽取 |
| 意图—槽位绑定 B(query, I, S) | 该类型的表达是否服务于该意图？ | 意图与槽位之间真实绑定；单纯共现不够 | 多意图/多调用的参数归属 |
| 规则条件 C(query, rule) | 定义的条件是否在输入与允许上下文中成立？ | 每个条件可由可靠字段或独立标注确认 | 区分相似类别，表达适用/排除条件 |
| 条件覆盖 K(query, requirements) | 定义所要求的条件是否都具备？ | 必要条件和缺失证据可判定；缺标不能当缺条件 | 就绪/不足等任务状态，非执行成功 |
| 状态变化 U(query, history, slot) | 当前输入要求保留、更新还是清除该状态？ | 历史、状态差分及变更原因可核验 | 多轮状态判决 |

第一轮优先I/S，B作为有适当数据支持后的组合扩展。C/K/U不是要求全部立刻训练；
表中区分了共同逻辑与额外标注成本，避免再次凭空制造过程监督。
代码首版只构造I/S/B及单意图类别成员命题，不自动产出任何gold。

## 3. 必须锁定“是否出现”的语义

“意图成立”指用户表达该请求，不是提到相关词；“槽位出现”指有符合定义的语义角色，
不是该实体可以被猜测。例如说出一个城市未必是在给目的地槽位赋值。
同一词可在不同定义下承担不同角色，模型必须读取定义而不是记住数据集标签ID。

现有SLURP发布只认证单一joint intent分类。它可以支持“按该单标签协议，此query是否
属于类别I”的true/false投影；这称为intent_label_member，不能悄悄当作所有自然语义
意图均完备的intent_expressed标签。两者模板与监督依据分开登记。
多意图完整集合才可支持语义意图存在性的全候选负例；局部标注则按类型mask。

false是已知命题为假；unknown是任务明确支持的证据不足状态；缺标或冲突是监督mask。
三者不能互换。FSC location=none是合法类别，也不自动表示“不存在地点类表达”。

## 4. 数据集映射与当前限制

| 数据集 | 可用的共同Q逻辑 | 当前研究角色及限制 |
|---|---|---|
| SLURP | 单标签成员I；审核后的槽位S；具备绑定时B | 全量40,513条intent已准入；55类型不能全部自动生成负例；现有clean标签非逐条复听 |
| FSC | 命令成员I；有限action/object/location属性 | SLURP冻结权重的配置迁移；其三字段不是任意开放槽位检测标注 |
| MINDS-14 | 单标签意图成员I | 同任务跨语言迁移；自有划分需冻结，不能假设官方test |
| MAC-SLU | 多意图I、槽位S、意图绑定B | 较适合验证原子到组合；保留实例和绑定，TTS来源披露 |
| SFC/SpokenFC | 函数适用I、参数角色S、调用绑定B；可核验的覆盖K | 保留音频/历史与缺参规则；工具适用不等于参数齐全或执行成功 |
| Audio2Tool | 工具适用I、可评分参数S/B | 外部只测不训；缺附加参数标签时mask，不从TEST优化Q |
| SLUE NER | 实体类型存在S | 类型定义与SLURP语义角色可能不同，不能仅凭同名对齐；不冒称完整NER |
| SpokenWOZ | 类型/绑定及状态变化U | 需要合法历史和状态监督；不能用单轮槽位存在代替更新判决 |

这是一份任务适配矩阵，不是这些数据集都已转制/准入。迁移的是判决操作与定义消费能力，
不是默认不同数据集同名标签拥有相同含义。情感/DAC等也可定义类别命题，但不能因此
认定它们与请求意图属于同一语义任务，需分组报告。

## 5. 输入组织与监督制作

先为任务发布概念表：id、自然语言定义、包含/排除边界、标注范围及来源。再根据固定
算子编译Q；同一个任务配置对所有样本使用相同定义菜单。编译输入后，独立映射targets
与available/conflict/missing掩码，建立每种Q的正负数量与来源组支持。

不能为每条输入预放一个正确意图加几个负意图，让菜单泄漏答案。若完整I/S菜单超过
上下文预算，可先固定一个任务级菜单做共享Final的训练对照，或按与标签无关的日程轮换
覆盖全部菜单；必须同时报告覆盖、成本及推理协议。不能把额外多次调用包装成一次前向，
也不能不经实际processor检查就一次塞入60意图加55槽位。

实际成本预检已完成：固定16条学习录音、相同Final和规约，0/2/8个类别成员Q最大
长度2,189/2,479/3,369；60个Q达到11,138，全部超出4096。
见[证据](../engineering/slurp-predicate-menu-cost-v1-verified.json)。因此当前完整60Q
平铺方案不准入。有限菜单须预先配置，训练可按标签无关日程覆盖定义，Final保持完整。
8Q仅在这16条上通过长度检查，不代表长音频或全人口已准入。

I/S可以分别是独立任务Final，也可以是更复杂任务的中间读出；由任务定义确定。
若把全部意图成员命题和单一intent Final同时训练，其监督是冗余分解，不构成独立
多步推理证据。S对于intent是否有帮助也是实验问题：槽位共现可能形成捷径，需报告
同槽位不同意图、同意图不同槽位等可信切片。

## 6. 学习与收益验收

Stage1学习Q算子、概念定义、true/false或state读出、候选绑定和任务规约；优先大规模
可靠监督，不通过重复展开Q虚增独立音频数。按每录音归一化、多Q共享过程预算，
避免拥有更多标注或更多问题的样本无意获得更大梯度权重。平衡统计按算子与定义分别
报告；不能靠多数false的accuracy掩盖正例召回。缺标mask保持不变。

Stage2保持RL+衰减CE，主要奖励Final正确，可靠原子Q可增加固定预算辅助信用。
共享起点、数据人口、Final知识与训练预算，比较直接Final、添加固定定义Q但仅Final
信用、同Q加入辅助信用，报告其对最终任务的修复和退化。包含辅助CE时不能把全部
差值归因于过程reward；不增加RL/SFT胜负比较。

指标分三层：

- Q本身：逐算子/逐定义precision、recall、macro-F1、负例误报及完整监督覆盖；
  单一类别成员accuracy只是补充。
- Final：意图accuracy/macro-F1、多意图或类型集合EM/F1、绑定关系F1及整句全对率，
  按真实任务选择，不把类型指标换名为官方完整SLU成绩。
- 迁移：冻结权重与Q算子，使用事先冻结的目标任务定义，比较源训练前后同一目标协议；
  区分新数据集、新概念、新语言、新组合，不用测试集选择问法。

先验证“学会依据定义判别I/S”，再验证“这些判决改善Final”，最后验证“相同Q逻辑
换定义后跨数据集仍有收益”。三层证据不可用其中一层代替其余层。

| NGA 方法 | 实际行为及边界 | 语音 Jev 使用规则 |
|---|---|---|
| `t1` 名称变化 | 保留定义/id/gold，改显示名；超过26等级直接跳过 | 可检查符号依赖，但需反解为统一概念再比较；SLURP Final60不能继承跳过逻辑，所有人口及排除都须显式记录 |
| `t2` 相邻定义交换 | 固定id/name、交换定义文本，同时交换gold id | 仅完整、互斥、定义足以判定的候选才允许这种标签置换；不能把非互斥I_present或不完备native描述当作同一问题 |
| `t2` ordinal reversed | 定义保持原位置，id/name反转，gold却不变 | 当前实现存在绑定不一致，不能直接导入该变体；若改显示绑定，gold须随定义移动；若只改展示次序，id/定义/gold绑定应原样保留 |
| `t3` 问题前缀 | 添加1/3/5个问题文本，保留单个目标问题读出；未构造其他问题的Span或联合监督 | 可作为上下文干扰诊断，不能当作多Span决策或过程奖励收益证据；主实验仍比较Direct、Q-input、Q-credit |

反转问题已用源文件 AST 提取的原 `t2` 函数验证（未加载pyarrow、未访问数据镜像）：
三个等级定义为“恰好0/1/2条件成立”，原gold=`0`。反转后`id=0`绑定“恰好2条件成立”，
但gold仍为`0`；保持原语义的正确绑定应为`2`。这是构造机制的反例，不说明已有模型成绩
受到多大影响，也未修改 NGA 工程。

数据导入另有两项不能照搬：`src_typed_decisions`/`src_akhilaaa3`会把缺失答案经
`str(None)`变成字符串；`src_openjev_synth_score`直接对target取argmax。前者不等于
有效类别，后者不证明原分布是一热真值。语音数据必须保留明确的positive、negative、
unavailable、conflict、unassessed及来源；软标签若适用须另立损失协议，不能静默硬化。

本项目已补齐问句变换配置中的unassessed：肯定、改写、补命题三种目标全部为null，
仍计入覆盖分母；正负参考仅作参考，变换不升级为已准入监督。未知状态继续拒绝。
诊断变体不得默认加入RL奖励，避免以语言形式一致性替代正确的音频判决。

可复用的是“定义与输出绑定显式化、同输入配对干预”的研究方法。跨数据集收益仍需
冻结源训练模型、目标定义及完整评测人口后实测；以上代码核对没有提供模型收益证据。
