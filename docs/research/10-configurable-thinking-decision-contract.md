# 可配置思考要求与非文本决策策略

> 最新纠正：用户要求一次填充 `Q1,<SPAN1>,Q2,<SPAN2>,Final Q,<SPAN3>` 的结构/隐式 CoT，非 ReAct 或外部复核循环。本文有界复核、触发/停止学习的主线安排已被[一次 Span 契约](12-single-pass-span-cot-contract.md)取代；保留旧设计供追溯。

2026-11-11 用户明确修订：所有 Jev 模型应能接受可配置的思考要求，在推理时通过触发和决策提升能力；不把触发文本推理作为研究路线。
本文取代 [上一版策略分析](09-query-decision-learning-guide.md) 中把自由文本 CoT 列为主动实验臂的安排。单问/多问组织、来源隔离、原子/整任务指标继续保留。
这是已明确的研究要求；以下接口和计算机制为实施建议，尚未实现或验证收益。

## 1. 配置控制什么

输入分为音频/允许历史、业务任务定义、思考要求三个部分。前两者决定回答什么以及正确性标准；第三者决定模型应如何检查证据和分配判决计算。

- **证据要求**：整句语义、否定作用域、修饰关系、跨轮更正、声音证据与上下文的优先关系。
- **组合要求**：必须同时满足哪些条件，哪些结论互斥，哪些允许并存，最终判决依赖哪些前置判断。
- **复核要求**：遇到哪些已定义冲突/不确定状态需要重新判断，什么时候返回证据不足。
- **计算约束**：最多几轮判决、允许哪些复核操作、时间/计算预算及停止条件。

不能把这些要求简化成一个 `think=true` 或 `effort=high`。等级可以作为便利入口，但必须解析为可追踪的具体配置。
预算是上限，不是必须消耗完；定义遵循也不保证正确率随预算单调上升，需实测。

区分两种变化：只增加复核预算时，任务 gold 应不变；改变业务条件、证据优先规则或接受标准时，可能已经改变任务，必须版本化并重算 gold。
不能对后一种变化强求答案不变。思考要求和任务 schema 冲突时，接口应拒绝配置或按明确版本规则处理，不能让模型自行猜优先级。

## 2. 决策式思考，而非生成解释文本

建议主 actor 最终仍输出 typed value/state；内部可以使用以下待验证机制：

| 机制 | 实际计算 | 需要证明的能力 |
|---|---|---|
| 要求条件化直接读出 | 在音频模型中联合编码任务和思考要求，直接判决 | 模型确实遵循要求而非只背标签 |
| 多节点联合判决 | 根据配置输出或内部维护相关决策节点 | 共享证据后整任务正确，而非仅格式一致 |
| 有界判决复核 | 根据预测冲突/校准不确定性触发下一轮，保留原音频证据 | 复核能纠错，且不会大量改错或循环 |
| 隐状态迭代 | 在内部状态上增加计算，再进行 typed 读出 | 可训练、可重现、收益不是额外预算造成的混淆 |

优先实现要求条件化的直接决策及可测的节点复核；隐状态迭代属于架构研究，不冒充现有 ASR/verl/vLLM 原生能力。
结构状态是可验证的决策变量，不要求模型输出自由文本理由，也不把参考转写输入模型。
若多个判决步骤通过离散 state 连接，梯度不能自动穿过采样；须明确监督各节点或采用轨迹级策略优化。

同一策略应能接受不同思考配置；不为每种配置单独训练一个模型后声称实现可配置性。
单问与多问都支持同一思考要求契约，输出多少字段不决定内部计算复杂度。

## 3. 谁决定触发

外部配置规定允许的操作、预算、必须检查的条件；具体样本是否进入复核，由预注册控制器或学得的策略决定，二者分别做对照。
控制器只能看到输入、模型实际预测及允许的环境反馈，不能看 gold 或“该题答错了”的评测结果。
初版可以用可解释的冲突检查和独立校准阈值；后续比较学习到的触发策略。
不能把生成文本里的自报 confidence 当成已经校准的概率。连续复核使用同一来源时也不是获得了独立新证据。

若业务提供明确确定逻辑，执行器可组合节点状态，但必须分别报告节点正确率和最终任务正确率；规则执行正确不能证明模型理解正确。
预测意图不能无记录地删掉槽位问题；动态选择题目时保留最终任务覆盖与遗漏惩罚。

建议中间协议区分：语义决定、证据不足、运行错误、尚未判决；监督 unavailable/conflict 只在离线 target 中，不作为用户语义状态。
最终环境 success 只能来自真实执行验证，不来自模型自报。

## 4. 数据制作

在 source/question/decision/bundle 之上增加 thinking_spec、允许的 decision graph/operations、预算与终止规则。
配置及实际渲染后的语义要求进入 request hash；监督目标和内部质量 mask 保持独立，不泄漏给模型。
使用人工审查或可信原标注支持的条件构造不同配置，不凭空加入紧急度、取消、行动准备度等原数据没有的 gold。

配对样本包括：

1. 同任务、不同等价措辞/要求顺序：正确决定应保持。
2. 同任务、不同复核预算：评估质量和成本变化，不制造新的答案标签。
3. 同输入、不同明确业务规则：必须依新定义重新判决。
4. 相同要求、改变有监督的音频证据：必须具备区分性。
5. 配置要求与证据不足：只有存在可信标签和明确拒答契约时才监督拒答。

按思考要求族、规则组合族留出，不能只留出同一模板的改写。SLURP 首轮以可靠的意图、语义角色条件为主；多轮更正和工具行动依赖使用有相应监督的独立数据轨道。
数据原子格式与联合格式共用来源划分，不需要重新拆分已验收 clean TRAIN。

## 5. 强化学习要学什么

核心研究从“奖励正确答案”扩展为：**在可配置要求下，以可控成本作出正确且有证据支持的判决，并学会何时复核、何时终止。**

首轮仍先 SFT 建立音频/定义/要求的理解及合法决策，再做独立决策奖励与关系/整任务奖励对照。
复核策略的奖励以最终语义任务质量为核心，辅助考虑已核验的节点正确、关系满足和计算成本；不奖励文字长度、重复自检次数或仅表面一致。
未核验中间状态不能作过程奖励。全空、全拒答、始终复核和从不复核都要作为退化控制。
成本系数只在学习/选择协议内冻结，同时报未经成本折算的任务指标，避免加权总分掩盖准确率退化。

多步策略用同一完整初始输入与思考配置的多条 rollout 轨迹比较；若下一步依赖实际预测，必须保存动作、触发依据、策略版本、停止原因和每步概率/成本。
不同 question 或 thinking_spec 不能因共用音频而塞入同一 GRPO 组。原生 verl 多步轨迹接入和 vLLM 状态/缓存复用需实测，不能直接复用单次 JSON 响应代码后宣称完成。

## 6. 对照矩阵与成功标准

| 臂 | 作用 |
|---|---|
| 不使用思考要求的直接决策消融 | 衡量新增配置条件化是否有作用；它是研究控制，不是最终交付规格 |
| 同一模型接受配置、固定一次判决 | 验证要求遵循能力 |
| 接受配置、固定次数复核 | 测试增加计算本身的收益和成本 |
| 接受配置、规则触发复核 | 建立可解释的触发基线 |
| 接受配置、学习触发/停止策略 | 检验 RL 是否改善质量—成本以及跨任务迁移 |

以上逐步开展，不自动启动全矩阵。所有最终候选都具备思考配置入口；单问/多问为独立受控因素。
重点报告：最终正确率/集合与整任务全对率、要求遵循的配对正确率、未知要求族迁移、复核纠错率与改错率、触发覆盖、平均/p95 延迟、实际轮数与计算成本。
纠错率在初始错误样本上计，改错率在初始正确样本上计；gold 仅用于离线评分，不可用于线上触发。
同预算下与固定复核比较，排除只因算得更多获得收益；同语义任务增加预算不保证必然更准。
没有对比证据前，不声称已学会思考或已证明复杂策略优于简单策略。
