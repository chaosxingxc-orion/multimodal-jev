# 固定策略下扩大G的收益边界

基于[已绑定TRAIN真值的第74步记录](context-live-reward-support-step74-v1.md)，固定行为
概率不变，精确积分G16/32/64/128/256的奖励分布。没有新增模型前向、随机重放、参数
更新或采样温度调整；不是不同G训练后的效果预测。

“组内有奖励差异”概率为`1-sum_r P(R=r)^G`；“至少一个完整正确动作”为
`1-(1-P(exact gold set))^G`。后者不要求实际可观测gold用于部署；gold仅用于离线TRAIN诊断。

| G | 全128输入：组内有奖励差异 | 20条高全同错误：有奖励差异 | 同20条：至少一个完整正确动作 |
| --- | ---: | ---: | ---: |
| 16 | 12.300% | 1.296% | 0.119% |
| 32 | 15.879% | 2.555% | 0.238% |
| 64 | 20.055% | 4.962% | 0.472% |
| 128 | 25.643% | 9.375% | 0.934% |
| 256 | 33.634% | 16.830% | 1.826% |

20条是先前G16奖励全同概率>95%且阈值集合错误的固定子集，没有随G重新选样。
数值均为每query概率的平均；不能误称模型准确率。出现奖励差异也不保证梯度方向
或最终收益；未采到完整正确集合也不意味着所有局部纠错梯度均为零。

该批显示，G翻倍不能按比例增加有效组数量，增加16倍采样也不能保证纠正高确定性错误。
因此暂不据此启动G扫描。RLOO与GRPO在完全同奖励组上都没有组内信号，二者标准对照
仍按已冻结配置完成。后续探索约束或概率目标变体需要完整曲线支持，并固定原始harness
效用、NLL/Brier要求及成本口径后再派发。单纯提高采样温度会改变行为分布和logprob，
不能只改采样器而继续使用原概率的ratio；当前未实施这类变更。

G的增加主要扩展离散动作、logprob和surrogate的计算/内存，不能把G64说成4倍音频
forward。报告没有实测不同G的NPU代价，不能据概率数字宣称吞吐加速或成本最优。
精确期望reward候选虽可消除有限采样遗漏，仍有sigmoid梯度饱和及与GRPO目标不同的
限制，不能直接替换运行loss。

工具 `tools/reports/analyze_context_group_budget.py` 逐项复核源报告全部依赖hash，
重算256个原始behavior/reference信号后才输出反事实。结果见
[数值报告](context-group-budget-step74-v1.json)，包含全体/错误/高全同错误三个分层。
reference的错误子集按reference定义，与behavior子集不同，不作跨子集配对比较。
11项相关检查通过，包括小空间奖励分布穷举、至少一次事件穷举及极小概率数值检查。
没有更改正式算法、运行包、排队依赖或评测选模规则。
