# 候选集合评测协议与全量退化控制

状态：离线计分接口已验证，尚无新模型预测。承接
[目标指南](jev-candidate-set-objective-guide-v1.md)。本协议不替代真实语义任务或执行闭环。

## 计分契约

`src/multimodal_jev/candidate_set_metrics.py` 接收请求内候选的完整适用性概率，
以及 `true/false/null` 标签。`null` 仅表示监督缺失。概率不要求和为 1。
调用方负责验证请求、数据与预测身份；本模块检查候选集合、概率域及请求 ID 唯一性。

集合按预先规定的 `p >= threshold` 返回；本次退化控制阈值为 0.5，不是模型最优阈值。
评测器不拟合阈值。真实模型若需校准，应在另行登记的校准划分完成，然后冻结。

- micro precision/recall/F1 只覆盖已知标签，明确给出 TP/FP/FN/TN。
- macro 为逐请求平均，分别报告有效分母；请求内 ID 不能跨请求当作同一类别。
- 无返回候选时 precision 无定义；无正例时 recall 无定义，不用 1 填充。
- 整集合正确率、空集 precision/recall、非空 gold 的至少一项覆盖率仅使用完整标签请求。
- 记录总候选数、返回数量、返回但缺标数量、完整/缺标请求分母。
- Brier/NLL 在每个请求已知候选内取平均，再按请求等权平均，避免大菜单自动增权。
- NLL 对错误的确定性预测为无穷；JSON 使用 `binary_nll_infinite=true` 明示，
  不用 epsilon 静默截断，也不把 `null` 解释为 0。

部分标签下的高 precision 仅指已知部分，不能宣称整个返回集合可靠。全缺标请求仍计入
人口和返回数量，不能因为无法计分而消失。空集代表该任务的无适用候选，不能外推为
语义 unknown 或执行失败。

## 全量学习人口的控制结果

`tools/jev/evaluate_routing_set_controls.py` 使用既有官方 clean loader 验证发布，覆盖
40,513 录音、9,181 来源；人口 hash 与原规则支持报告一致。固定 seed317、四策略族。
结果见 [slurp-harness-set-controls-v1.json](slurp-harness-set-controls-v1.json)。

| 策略族 | 返回全部：precision | 返回空集：整集合正确率 | oracle 仅返回一项：recall | oracle 仅返回一项：整集合正确率 |
| --- | ---: | ---: | ---: | ---: |
| partition6 | 16.67% | 0% | 100% | 100% |
| partition12 | 8.33% | 0% | 100% | 100% |
| overlap6 | 33.33% | 0% | 50% | 0% |
| availability6 | 7.84% | 52.94% | 100% | 100% |

所有策略族的完整 oracle 集合正确率均为 100%。重叠任务中的单项 oracle 虽然始终
返回正确候选，却没有识别完整集合。部分禁用任务的空集先验很强，必须报告非空样本
覆盖和空集 precision/recall。报告同时保留“返回全部启用项”和“第一项启用候选”控制。

这些都是确定性控制，不是模型结果。oracle 读取 gold 仅用于验证指标，不能用于部署、
输入菜单构造或声称泛化。标签来自原事件的已声明规则投影，不是新增独立语义标注。

## 验证与接入边界

30 项相关 CPU 测试通过（集合计分、集合目标诊断和规则监督）。覆盖缺标、全缺标、空集、
候选换序/重绑定、大小菜单的请求等权、无效概率、重复请求和多正例退化。
另用原支持报告的每路正例计数独立核算全量 TP/FP、空集比例及 oracle 结果，全部一致。
原 RC2 的 1,360 个文件 hash 未改变。

下一步真实预测需在相同数据身份和候选定义下接入一次前向适用性 Span；在冻结校准/
选择协议、NPU 概率一致性和完整语义监督范围前，本报告不授权派发新正式训练。
真实评测还需配对规则改变、等价表述和目标域迁移；它们不能被这四个控制任务替代。
