# 第74步：节点条件积分信用的离线诊断

本次回答一个具体算法问题：采样组奖励全等时，完整可评分的决策任务是否仍存在可利用的
reward梯度？当前单标签集合F1下答案是存在；但这不是新算法训练或泛化结果。
正式GRPO/RLOO配置、动作空间、奖励、运行包和条件队列均未修改。

## 来源与方法

使用既有live-v13原始归档（actor第74次更新，behavior第73次更新），重新认证全量clean
TRAIN manifest、日程、128条来源、audio/tensor/gold绑定及四rank归档副本；同样本只计一次。
按原seed重建G16动作，128个action hash逐项匹配；不新增音频前向、不使用selection/TEST。
代码：tools/reports/analyze_context_counterfactual_credit.py。
完整来源hash及逐样本结果：context-counterfactual-credit-step74-v1.json。

对独立Bernoulli决策a、唯一正例g，集合奖励为
`R(a)=2*a_g/(sum(a)+1)`。用负例选中数量的Poisson-binomial递推计算精确期望：

`E[R] = p_g * sum_k P(K=k) * 2/(k+2)`。

对输出logit求导，得到当前概率下未标准化期望reward的精确上升方向；计算采用CPU FP64。
这不是actor参数梯度，不含KL、辅助监督、GRPO标准化或更新后的clip。

节点条件积分估计器固定归档中其他节点动作，直接积分当前节点的两种取值：

`g_j(a_-j) = p_j*(1-p_j) * (R(a_-j,1)-R(a_-j,0))`。

再对16组其他节点动作求平均。这里使用行为策略概率；未定义off-policy多epoch更新规则。
对于原始期望reward，在其余动作仍来自行为策略时，该估计器期望等于对应logit梯度。
它比仅对已采样动作减去节点baseline更进一步：把本节点动作的采样噪声也积分掉。
不能把它直接替换成GRPO advantage后仍称原算法，也不能声称已解决联合clip信用分配。

## 实际结果

| 统计 | 全批128条 | 恒奖励112条 | 恒奖励且阈值错误26条 |
| --- | ---: | ---: | ---: |
| 精确方向非零 | 128 | 112 | 26 |
| 条件积分方向非零 | 128 | 112 | 26 |
| 条件积分相对精确方向的平均平方L2误差 | 1.77367e-7 | 2.59487e-9 | 1.11642e-8 |
| 原G16 RLOO相对精确方向的平均平方L2误差 | 1.15514e-4 | 1.64289e-5 | 3.86023e-5 |

以上是同一批实际样本的描述性估计误差，不是独立重复采样估计的方差，也不构成总体性能排序。
GRPO的归一化目标不同，不将其方向与未标准化精确reward梯度做此误差比较。
恒奖励错误组的正确候选精确logit方向为1.60194e-6至0.0253257，最小值仍很小。

非零并不表示错误可以迅速纠正：乘子p*(1-p)仍会压低饱和节点的梯度。
当归档动作全部漏掉正确候选时，条件积分能给正确候选正方向，但错误候选的方向仍可能为零，
因为固定其余位时正确候选没有被选中。精确期望还能积分其他节点，但仅适用于当前可解析奖励。
不把这种条件积分声称为任意复杂任务的精确算法；过程缺标仍不允许补造reward。
