## 下一阶段的验证交付

本阶段验收三个维度：完整RL更新的效率、SLURP源任务表现、FSC/MINDS跨数据集
迁移。逐项标明提升、权衡、退化或待验证。复杂跨任务验证不作为本阶段完成门槛；
SFC、Audio2Tool、多音频历史、多意图组合和多步判决不再占用本阶段工作。
简单跨任务扩展须具备同一简单输入接口和独立可信标签，不为满足跨任务名义扩展
复杂数据集。FSC/MINDS结果如实称跨数据集迁移，不自动改称跨任务泛化。

执行顺序：完成既定效率窗口并选定工程配置；补齐正式训练和源评测准入，执行
源域正式训练；封存共同Stage1、源选模型和固定终点三个角色；完成目标候选数量
对应的实际后端一致性验收后，统一评测SLURP clean TEST、FSC和MINDS。
效率对照每组最多100步，正式收益预算另行执行；复杂任务评测留待下一阶段。
效率重点看rollout/reference、actor训练及权重同步/保存等大块耗时，在同条件下
优化microbatch、合批和数据准备，以完整更新吞吐、峰值显存及总成本验收。

源任务表现与迁移表现是共同交付项。当前100步实验只选工程配置；正式训练预算、

每个目标集评测相同的三个策略角色：共同Stage1起点、只按SLURP完整selection曲线

策略ID相同，只推理一次并复用经认证的预测。源选模和终点身份先封存，之后才打开
目标推理；不在目标集上扫检查点、选模板、调阈值或进行难例采样。

历史GRPO作为次级参照。它已有set-F1提升与NLL/Brier恶化，比较前须核对人口、定义、
阈值、输入和执行协议；历史分数不能直接充当新版runtime下的算法因果对照。
本轮核心对比是新版双信用GRPO相对于相同Stage1起点的配对变化。

结果表必须同时出现原始值、绝对增量、改善/退化条数、类支持、覆盖率和成本。
FSC按官方说话者做配对不确定性分析；MINDS缺乏可认证说话者分组，保留描述性结果，
不以录音独立假设包装强统计结论。不同候选数的NLL/Brier分集解释。MINDS各语言的
退化不能被大语言样本量或总均值遮盖，FSC近饱和无增益也必须保留。

结论按证据分级：源域提高但迁移不提高，记为源任务收益；部分目标提高而其他目标
退化，记为混合迁移；set-F1提高而NLL/Brier恶化，记为决策与概率质量的权衡。
单seed正增量是探索性结果，不能宣称稳定显著提升。没有新判决任务的真实评测时
不作跨任务泛化声明；这不阻塞本阶段简单任务效率、源表现与跨数据集迁移验收。

## 训练设计如何服务迁移

迁移的接口固定为“音频 + 与当前样本无关的任务规约 + 完整候选定义 → 每个候选的
prob”。同一个策略在不同数据集上复用主干、LoRA、共享概率head、processor和数值
执行协议；通过配置更换任务问句、候选定义与数量，以及预先声明的指标映射。
不能为每个目标集训练一个head再称零样本配置迁移。判决阈值在目标评分前固定。
目标候选数量变化需要实际后端一致性验证，不能只靠配置加载成功证明支持。

先完成当前排序+存在性双信用GRPO的源域与迁移基线。之后以同起点、同源数据、同
预算、同seed和同runtime比较排序信用、存在性信用及联合信用，辅助监督项保持一致，
这样才能判断排序改善和概率确定性改善各自贡献。该消融是后续待封存实验，不改动
当前正在运行的效率配置，也不增加RL与SFT胜负对照。

可迁移性训练只使用SLURP TRAIN：候选顺序变化检验位置记忆，经过审核且保持真值
的定义表达变化检验定义消费能力。仅更换措辞不能保证提升，必须单列对照；原生
单标签不能扩写为未经审核的多意图、拒识或语义存在性奖励。每轮难度刷新只访问
源TRAIN，保留均匀锚点和类覆盖，避免只优化少数难例而破坏概率质量。

如果看过本轮目标成绩后继续据此调整算法或模板，这些目标就产生开发暴露；后续
必须另设独立迁移开发与未用评测人口并如实披露。固定评测脚本和配置负责统计，
不以反复人工查看目标错误来选择下一版提示。

## 研究对比

每个候选方案在冻结发布前同时声明源数据指标、迁移任务、模型选择规则及成本。
第一组对比为相同 Stage1 起点、新版 GRPO 源 selection 选定模型及其固定训练终点。
历史 GRPO 仅作协议对齐后的次级参照。FSC 为简单控制，MINDS 为跨域/跨语言迁移；分别报告原生准确率、
macro-F1、概率评分及覆盖。MINDS 按已有冻结项目人口与语言报告，不称官方 test split。
不同候选数量下的 binary NLL/Brier 分集解释，不混合成一个看似更好的总分。

SLURP→FSC/MINDS 主要证明同类决策任务跨数据集泛化；函数适用性等新的决策任务才是
跨任务证据。SFC动态函数、历史输入与原生指标映射等工作已移至下一阶段。
已有意图模型可否按配置回答新问题必须实测；不能宣称架构通用
就等于已经具备零样本跨任务能力，也不把函数选择成绩替代参数生成/完整调用指标。

初始主轨为 SLURP-only 权重训练。目标数据不进入难例挖掘、reward、辅助监督或提示
选择；候选定义来自公开本体和预先固定的规则，不从目标测试语句反推。固定权重只换
任务模板与候选定义，不加数据集专属 head，不生成文本 CoT。

迁移前移指评测协议从现在固定、每个冻结候选包同时产出源与迁移结果，而不是反复
用目标测试成绩挑模型。第一版仍 source-only 选模，目标结果仅用于报告。若下一阶段
需要目标反馈调方案，必须先建立独立迁移开发人口、审计历史暴露，并保留另外的未用
测试人口；该轨如实称 target-development-assisted，不再声称完全未见目标域。
配对评测用同一人口和来源组；多数据集检验的多重比较与训练 seed 波动另行报告。
不能以 FSC 提升替代所有迁移提升，也不能以源域提升通过整体研究目标。

训练侧可研究源数据上的候选排列、定义表达和模板变化，保持任务真值不变、记录
视图来源及曝光。重绑定等改变真值的视图须单独审核；不自动引入缺候选拒识或多意图
标签。全量难度刷新继续只读 TRAIN，均匀数据锚点及类覆盖约束避免过拟合少数难例。

## 一次提交、一批完整交付

macro batch 起始为 128 个 query，每个 query 携带完整候选面板；不是 128 个候选，
也不是要求将 128×60 个独立音频请求发给引擎。训练控制器一次提交带唯一 batch_id、
固定 policy_id 和输入/候选清单的完整 manifest。两 TP1 实例为同一策略副本。

调度单位为完整 rollout 作业：一个 rollout 固定由一个推理实例处理到底，两个实例
并行处理不同 rollout。每个作业可包含多个 query；每个 query 的完整候选面板及其
G16 动作组只绑定该实例的一次策略前向，不跨实例拆候选或拆组，也不在运行中迁移。
G16 可在训练侧根据返回概率统一采样，不因此重复进行音频前向。
manifest 记录 batch_id→rollout_id→replica_id→request_id 的归属；长度预算用于
分配完整作业和实例内部合批，不打破上述边界。

引擎内部按文本 token 和音频帧预算真正合批，并行处理两实例。rollout 可以
分步完成，进度可流式记录；这些部分结果不对 actor 开放。整批收齐、恢复请求顺序、
校验完整候选、策略/runtime 身份、概率与实际 logits 后，才原子提交 COMPLETE 收据。
训练侧随后组装 G16 动作/reward/优势，完整组先归一化再做 DP2 分片和 microbatch
累积，一整个 macro batch 对应一次 optimizer step。label 不进入推理请求。

“一次性完成”是调用和结果交付的原子边界；允许内部多个有界 engine forward，
不能将一次 HTTP/RPC 包装下的逐 query 串行 forward 计为批处理优化。128 条输入
应都被接纳并处理；长度差异导致更多内部批次也不能静默截断/丢弃样本。

必须验证：

- 接纳的每个 request 都有且只有一个匹配结果；无漏项、重复、未知 ID 或错位候选。
- 一个 macro batch 只用一个 behavior policy；两实例不同版本时整批禁止交付。
- 子批失败或实例退出后，未完成整批不进入 optimizer，不缩小分母“先训成功部分”。
- 重复提交同一 ID 必须核对内容身份，不能造成重复消费；恢复前核对已有结果与准确
  进程句柄，不能把网络超时直接当作作业失败并另启一份。
- actor 更新后，两实例都确认新 LoRA/head 身份才接下一训练批；基座权重只读复用。
- reference 使用独立固定策略身份，冷建/热命中分列；不能把它混入 behavior 版本。

本阶段不引入跨更新的过期轨迹流水线。全 TRAIN 难度诊断可以由多个 macro batch
组成，其结果仅作选样索引；训练时用最新策略产生新动作。

## 现有工程的实际差距

旧 bulk RPC 只减少传输次数；当前双实例macro已通过固定策略真实音频四pass，
actual logits/prob/G16与serial参考一致，完整128条交付及rollout归属已核验。
更新策略后的实际NPU actor对齐、两步训练审计及新进程恢复已通过；当前缺口是匹配条件下的持续吞吐和源/迁移效果。
服务存活和固定策略一致不能替代这些训练证据。

本次在真实128条输入上发现FP32排序sigmoid饱和，新数值协议为
`dual-credit-cpu-pair-fp64-v2`：只把CPU小型排序概率/logprob/采样改为FP64，
存在性仍用实际backend FP32，进入verl的loss为FP32，主干执行BF16。
协议变更会改变排序随机采样轨迹，不能将旧FP32实验与新实验的整轮耗时差
直接归因于引擎部署。效率组必须从同一Stage1、相同数值协议和GRPO、相同日程前缀、
相同参考缓存状态及checkpoint频率出发，只改变明确声明的工程变量。
每组最多100个全局optimizer step，较短工程验证不扩到100；不要求完整epoch。

机器路径、设备和 endpoint 通过本地宏配置；本设计配置不写本机地址。已停旧 RLOO
及其后继，不恢复旧 RLOO 优先级。新统一基座在两路信用GRPO和上述数值协议下做匹配的工程对照，再按
固定预算加入难度刷新；历史GRPO仅作为研究效果参照，避免把算法差异计作硬件加速。

性能从提交整批到 actor 更新及两副本确认结束计时，包括排队、传输、reference、
所有 rollout 子批、组装、校验、训练和同步；启动、诊断全量扫描、评测另列总成本。
最终同时报告源/迁移质量和每设备小时成本，不能仅报服务端 tokens/s。
