# 固定容量过程奖励：消除尾部问句原始权重放大

doc109发现17面板候选日程若沿用“族预算÷当前面板题数”，最后单个I问题获得普通
四问中单题4倍信用。这里完成任务奖励设计修订，不修改训练实现或标准算法。
当前入口为[reward v3](../../configs/experiments/reward-contract-design-v3.json)，v2保留历史。

每族容量固定4、上限0.1，每个实际过程问题系数0.025。奖励为Final正确性加所有
有可靠监督的过程问题正确性×0.025。尾部空位不实例化动作、不转移预算，缺标mask
也不改变分母。最多8题时过程奖励上限0.2；相同输入的任意正确Final答案比错误Final
答案至少高0.8。这是奖励排序性质，不保证共享参数梯度或模型指标改善。

Stage2过程CE同步采用每题0.025，Q-input/Q-credit两臂完全一致，仍使用共同衰减；
Stage1的全本体平均及cap8极性CE设计不变。v2→v3同时改变过程reward和CE权重，
因此跨版本差值不能说成仅奖励收益；后续同v3下Q-input/Q-credit才是奖励单因素比较。

完整17面板中每个谓词恰好出现一次，等面板平均后每谓词系数1/680。I共65题，
族总系数13/136≈0.09559；S共55题，11/136≈0.08088；合计3/17≈0.17647。
保持的是每请求族上限与逐题相等原始权重，**不是每族完整一轮都恰好0.1**。
若为了每族平均0.1改用17×0.1/类型数，普通四问面板的S预算变为0.12364，
两族过程总和约0.22825，会突破原每请求0.2上限；首版不采用该方案。

GRPO组标准化仍能消除大部分奖励缩放：G16、Final恒定、8个过程答对时，
单题系数0.1与0.025分别得到约0.968227和0.968171的正优势；RLOO对应0.053333
和0.013333。减少原始奖励不能宣称控制了GRPO过程梯度。标准优势、联合裁剪和KL
均不变，不添加新算法配置；后续需同报Final恒定组比例、过程/Final梯度及任务曲线。

证据：7项相关测试通过，包括ragged尾部、缺标不重分配、动作支持不随mask改变、
重复问题/超容量拒绝、完整日程和Stage1目标等价；[精确审计](semantic-menu-fixed-capacity-budget-check-v1.json)
及[独立配置核验](semantic-fixed-capacity-config-check-v1.json)对当前配置、全部17面板
和所有有效正确性位模式枚举，确认奖励上界及每谓词系数。不含NPU或模型效果验证。

主task、算法及当前Stage1设计引用已对齐v3；历史v1/v2与运行结果不改。
