# 面向 agent harness 的语音 Jev：开源方案与训练目标

2026-11-14 UTC；基于直接获取的论文页面/全文和官方仓库源码。来源及抓取内容 hash 见
`jev-harness-decision-learning-sources-v1.json`。分支 URL 是本次内容快照，不冒称固定 commit。
对论文级开放与代码级开源分别标注；未复现实验，不将作者报告当作本项目已验证结果。

## 目标修正

用户要求：Jev 消费证据和运行时决策候选，供 agent harness 做稳定决策。
因此任务不是学习固定映射 audio→60个标签，而是学习
`(audio, declared state, decision specification, candidate set) → typed decision evidence`。
候选定义、约束、问题和状态是输入；标签和偏好只进入监督。核心迁移单位应是决策关系，
不是复用训练集类别编号。SLURP Final60仅保留为听懂音频和工程执行的受限基线。

模型输出可包括候选分数/相对概率、已定义且有监督的状态判决、拒判信号。harness负责
候选合法性检查、已知硬约束、成本/效用、阈值、执行及反馈。不可把一个softmax值同时
解释成意图正确率、执行成功率和操作授权。只给音频没有外部状态时，模型不能知道
设备权限、网络可达性等执行事实。

## 直接核查的路线

| 工作 | 目标与开放证据 | 可借鉴点 | 限制 |
| --- | --- | --- | --- |
| CLIP / CLAP | 论文与官方代码开放；CLAP `clap_module/loss.py`音频/文本相似度的双向对比项调用cross_entropy | 用候选自然语言定义匹配输入，避免固定类别输出头 | CLAP主要验证检索和音频分类；相似度不等于规则满足或执行成功，不直接证明复杂SLU能力 |
| Open-Jev | 官方源码 `jev/train.py` 415–416行为soft CE + Brier；多域说明为共享标量头，候选描述进入模型，无固定类别词表 | 动态候选、跨域共享评分、独立校准 | 训练每候选独立序列，多候选可能重复编码；不能直接照搬并声称符合本项目一次前向约束 |
| OneJev | 官方 `train/sft.py` 368–379行，对动态answer slots使用soft CE+Brier | 多模态typed概率接口；候选目标可与生成任务分离 | 代码目标本身不证明严格顺序不变或语音泛化 |
| Nimble | 官方README和训练指南；对比事实对，答案token LoRA监督 | 同问题/规则下只改关键事实，正确决策必须改变；缺证据不补false | 对比数据≠独立InfoNCE loss；文本反事实不能只改转写后拿未改音频训练 |
| DPO | NeurIPS 2023论文和官方 `trainers.py` 的相对参考logratio偏好损失 | 从harness选择偏好学习候选优劣，参考约束 | 排序偏好不提供绝对成功概率；不是本项目在线GRPO的自动替代，不直接保证校准 |
| SayCan | CoRL 2022论文、作者项目及开源演示入口 | 分开“任务有用性”和“状态下可执行性”，由外部控制流程选动作 | 原机器人系统与语言规划不能直接移植为语音单次Span模型；只借鉴接口分工 |
| Set Transformer | ICML 2019论文与官方PyTorch代码 | 集合建模的排列不变/等变结构 | 是架构原则，不是已经验证的Qwen-ASR/verl/vLLM实现 |
| Narrow Decision Models | 直接核查arXiv 2610.25553全文；本轮未确认作者实现仓库 | prefix-tree、block mask与逻辑位置；候选顺序不变、typed决策、none-of-these、proper scoring与拒判 | 窄域encoder的最小验证，不能外推多模态或照搬到causal语音基座 |
| LLM-as-Jev | 直接核查arXiv 2610.02076全文；本轮未确认作者实现仓库 | 候选评分、tree-factorized listwise目标、KL anchor；保留基础模型行为 | thinking路径不符合当前不解码契约；文本/视觉结果不构成语音验证 |
| RAPS / conformal prediction | ICLR 2021论文及官方代码 | 用校准集构造候选集合，把歧义交给harness | 覆盖依赖交换性等条件；不是每条保证，不保证任意跨域或动态菜单下覆盖不变 |

一个关键实证事实：Open-Jev没有固定类别词表，仍用soft CE；CLAP对比学习也调用CE。
因此必须改的是决策任务、候选语义和数据关系，而不是禁止某个API。另一方面，
“用CE也行”不能成为继续只训固定SLURP标签的理由。对比学习值得研究，但应定义
所比较的对象：音频与描述、同状态候选优劣、语义等价视图、或证据改变前后的决策。

## 稳定性应如何定义

1. 同一输入/权重跨actor、rollout、恢复及批量布局的数值一致性：已有工程验收继续保留。
2. 候选换序/ID重绑定后语义分数按映射一致；不能仅保证输出token不变。
3. 语义等价描述保持决策；证据或规则实质变化时，模型应正确改变判决。
4. 正确选项缺席、多个候选均可接受或证据不足时，不强制唯一高置信选择。
5. 候选数变化需单独测试。softmax归一化概率必然随集合变化；不能要求增加候选后
   所有概率原值不变。对独立候选评分可要求旧候选raw score不变；对依赖全菜单的相对
   问题不能强加该性质。重复同义候选会分走概率质量，harness需要候选去重/等价类策略。
6. 多Q只有声明独立时才要求隔离；用户配置的前置Span→Final依赖需要显式保留，
   不能把NDM的所有问题独立设计直接套在我们的相关Span上。

## 推荐的架构与目标设计

针对“提供候选给 harness”的进一步结论：候选适用性覆盖应独立于 Final 单选衡量。
两个合法候选时，模型只偏向其中一个也能获得很高的单选奖励，却可能无法提供完整候选集。
输出概率语义、集合目标的反例及 RL 含义见
[候选集合学习指南](jev-candidate-set-objective-guide-v1.md)。这里的核心输出是按定义支持的
候选及判决依据；并非让模型生成任意候选动作，或将所有候选概率强制归一成唯一类别。

保持端到端音频、LoRA、一次前向多Span，不引入转写→文本模型。近期优先建立
运行时候选语义及稳定性协议，复用当前共同计算profile，测量动态菜单的真实能力。
若严格顺序不变必须由结构保证，则将共享音频/state编码与候选分支/局部逻辑位置
列为独立架构候选，并同时修改actor/vLLM；现有causal菜单无法仅凭数据增强保证它。

训练可分为两阶段，但Stage1要学习决策接口：不同候选集合、语义定义、符号映射和
有可靠监督的状态判决。Stage2学习harness效用与偏好，沿用通用GRPO/RLOO作为算法基线。
监督部分候选形式：pairwise/listwise候选对比 + 等价视图一致性 + 概率质量目标。
权重、温度、margin及校准协议尚未冻结，不能提前声称最优配方。

对于单选且有完整正确标签的子任务，proper scoring（NLL/Brier）仍然有用途；它描述
预测概率质量，不要求模型拥有固定类别词表。对于多可接受候选，使用明确的偏好或
集合监督；只有可接受集合时不能虚造集合内真实概率分布。选择排序loss也不能把未经
校准的score称为成功概率。若只最大化正确动作奖励，策略可以变得很尖锐，RL不会
自动得到校准概率；需要独立校准评测或保留适当概率目标。

harness可在合法候选中优化预期效用：`E[U(action,outcome)|evidence]`，并将澄清/转交
作为有成本、可验证结果的动作。所需成功/失败、成本、澄清结果要由任务或环境提供。
仅SLURP意图标签不能提供这些奖励，不得把意图正确率叫agent任务成功率。过程奖励
只来自有监督的判决，最终奖励以任务真实结果为准，避免重复奖励同一投影标签。

## 数据和评测如何改变

本轮全量SLURP学习元数据审核：40,513录音、9,181来源、60类，提供3540有向类别对、
2,390,267个录音/负候选组合（非独立样本）。同scenario 113,010，同action 138,477，
其余2,138,780。它们是原任务互斥标签对比，不是新增语义规约监督，也未证明是困难负例。
四种既有候选映射已逐类验证对象、问题和requirements不变；尚未做新processor/NPU评测。
见 `slurp-contrastive-support-v1.json`。只能作为受限基线素材，不能用其规模宣称覆盖harness。

下一版数据应在每条记录显式区分：输入证据/状态、问题规约、完整候选定义、监督关系、
允许决策集合、不可判原因及标签来源。训练可用gold选择loss负例，输入菜单和问句不得
由gold路由。证据改动对必须有匹配音频；需人工或独立审核的合成语音应独立域报告。
全量人口、来源分组隔离和真实长尾保留，增加决策关系不等于只训一小撮示例。

评测轴：
- 固定SLU能力：原任务accuracy/macro-F1，作为保持音频理解的锚点。
- 候选决策：pairwise/listwise正确率、双方正确率、可接受集合命中及非法动作率。
- 稳定性：换序/重绑定、等价描述、候选增删/重复、定义互换与正确翻转。
- 概率与拒判：NLL/Brier/ECE、risk-coverage、错误执行率、澄清/转交率；使用独立校准划分。
- 迁移：未见任务定义/候选集合/数据集/音频域分开报告，明确目标域是否有任何训练或校准。
- harness闭环：成功率、成本、错误动作损失及重复运行一致性；需真实环境/可执行模拟监督。

当前工程结论只限既有基线。下一正式配方先完成此决策协议与数据可承载性，再实现训练，
不直接把刚提出的pairwise公式接入全量RL并声称解决了用户指出的任务定位问题。
