# 方案比较与研究切入点

## 研究定位

当前围绕**端到端语音 Jev 的强化学习与跨任务泛化**开展研究：输入语音、问题/函数定义和会话状态，输出有限选择、标量判断、开放参数及缺失状态；把声学事实、定义理解和执行时机分别验证。直接音频分类、类型化头、排列一致性和提前调用都已有研究，不能单独作为创新点。

当前执行顺序是冻结基座推理 → 离线远程教师提示优化 → 原生/Jev 对照；actor 使用本地 Qwen3-Omni，直接消费波形，权重训练继续暂停，不新增模型下载。后续算法方案见 [Omni SFC RL 设计](../../proposal/archive/raw/03-omni-sfc-rl-design-v1.md)，工程使用固定 verl + vLLM 镜像。Qwen3-ASR 的官方协议没有通用任务开关，本地 HF 模板会丢弃 user 普通文字，详见 [源码核查](../engineering/qwen3-asr-task-template-analysis-2026-11-10.md)。ASR 适配仅保留为未来研究候选，不能由 template 修改推定具备任务能力。

## 架构候选与公平对照

| 路线 | 实现要点 | 需要回答的问题 |
| --- | --- | --- |
| 冻结 Omni 原生/Jev | 同一 checkpoint 直接输入音频与 schema，分别输出原生答案和拆分决策 | 任务拆分的质量、完整性与额外调用成本是多少？ |
| 冻结 Omni + 教师提示优化 | 教师离线分析 learning 反馈，selection 选候选，在线 actor 仍直接听音频 | 不训练权重时，任务定义的改进能否提高完整任务表现？ |
| Omni 继续 SFT / 独立奖励 RL / 关系奖励 RL | 后续同初始化、数据来源和预算对照；当前不派发训练 | 收益来自额外监督、优化方法还是业务关系奖励？能否迁移？ |
| 冻结声学表征+任务头 | WavLM/Whisper 或 ASR AuT 特征池化，问题/候选编码后评分 | 简单 SLU 是否根本不需要完整语言解码器？ |
| 冻结完整 ASR+读出 | 音频特征进入 decoder，任务前缀最后有效位置接 Choice/Noul/Score 头 | ASR-only 后训练是否已损害任务条件理解？仅训练头是否足够？ |
| ASR LoRA+类型化头 | 先冻结音频编码器，适配 projector/decoder；动态候选 mask、缺失任务 mask | 新 schema、同名异义定义与语言迁移能否泛化？ |
| 同骨干 label logits | 保持训练数据、前缀、参数预算一致，使用原 LM head 评分候选标签 | 专用头的独立价值是能力、校准还是接口/成本？ |
| 原生音频生成模型 | Qwen Omni/AudioJev/SFC 作为参照，报告全部加载参数和调用次数 | 小型方案是否在质量—成本曲线上占优？ |

表中 ASR 任务头、LoRA 和其他模型是研究候选，不是当前执行清单。ASR→文本决策及人工转写替换仅保留历史文献/诊断，不再派发，也不计入端到端提示优化或 RL 收益。

Choice 应绑定候选身份，不能只学候选位置；Noul 使用适当二元目标；Score 要说明等级分布、期望或连续回归含义。候选超出容量时必须有明确策略，不能截断后继续报告无条件准确率。

开放槽位（姓名、地址、时间、数值）不能强塞入固定分类头。当前由同一音频 actor 直接输出结构化参数，严格检查类型、重复调用和参数绑定；未来候选检索或受约束生成必须保持音频输入，并报告候选召回率和参数完整正确率。`unknown`、缺参、冲突、超范围分别建模，不能都默认为负类。

## 分阶段验证与停止条件

1. **数据与接口复核**：固定模型/数据 revision；抽查波形、采样率、真实/合成来源、split 与 schema。完成一批真实前向后记录形状和有效位置；禁止用 padding 的最后位置读出。
2. **冻结 SLU 与学术比较**：FSC 原生 joint intent、SLURP 官方 SLU-F1、intent 和实体指标分别报告，完整 split 与官方 scorer 对齐；公开任务训练权重复测、作者论文分数和零训练 Omni 基座分栏。当前长任务未验收前不报告完整成绩。训练后的多 seed 比较在后续训练协议中登记。
3. **动态 schema 验证**：SFC ID/OOD 函数，保持官方划分；对名称置换、定义重绑定、同义定义和无关定义分别评测。若只会旧标签、定义变化不引起正确变化，则不声称可配置决策。
4. **声学与校准验证**：MMSU、MMAR 等外部集；同转写不同韵律、背景指令、冲突证据；温度仅在独立校准集拟合。联合报告 NLL/Brier、ECE、风险—覆盖曲线、最坏分组和置换方差。低方差常量预测不能通过。
5. **工具与时序验证**：Audio2Tool 离线调用、FDB-v3 真人录音，然后接 τ-Voice 固定任务版本。报告工具/参数 exact、执行成功、错误调用、澄清率、撤销失败、重复副作用和端到端时延。必要时退回大模型，但计入成本与失败。

RL 前需完成真实音频 actor/rollout 的 token 和概率对齐、微批/分布式梯度、导出重载与恢复验证。CPU 前向或合成奖励检查不能替代 NPU on-policy 证据。当前完整 learning 中无需调用函数占比高；先乘类别权重再做组内标准化会抵消该权重，后续平衡消融必须明确优势归一化和损失分母，不能仅改奖励系数就声称消除退化。

跨任务泛化按整个数据集/业务族留出。FSC、SLURP、SFC 已参与开发，应报告已知任务间迁移；SFC 官方 ID/OOD 不自动等于未见数据集泛化。Audio2Tool 全为 test，MMAR 等外部诊断集不得用于教师反馈、奖励设计或候选筛选。所有阶段均沿用已有划分和冻结协议，不因本建议重写运行中的实验。

每阶段只在对应证据通过后推进。ASR-only 模型若适配成本高于通用音频基线且质量没有补偿，应承认这一否定结果；无需为了维持 Jev 命名继续堆叠模块。

## 运行时边界

确定性执行层负责参数校验、工具白名单、幂等键和任务版本；模型负责语义判断。纠正或取消使旧版本计划失效，执行前与播报前分别检查。借鉴 Jarvis/Qwen-Audio-Agent/Omni 的分工，但不要把外围规则的可靠性归因于模型头。

成本同时报告冷启动、音频编码、问题条件前向、开放参数解码、回退调用和工具等待。共享一次音频编码可以摊销编码成本，但不等于任意问题均零增量开销。NPU/GPU、精度、批量、输入长度、流式窗口与缓存策略必须一并记录。
