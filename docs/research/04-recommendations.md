# 方案比较与研究切入点

## 研究定位

建议围绕**小型 ASR 骨干上的可配置语音决策**开展研究：输入语音、问题/函数定义和会话状态，输出有限选择、标量判断、开放参数及缺失状态；把声学事实、定义理解和执行时机分别验证。直接音频分类、类型化头、排列一致性和提前调用都已有研究，不能单独作为创新点。

当前先实现可证伪的低成本基线，再决定是否联合微调。Qwen3-ASR-0.6B 为主，1.7B 为规模对照；原始 qwen-asr 与 Transformers 原生 HF 格式分别固定环境。下载权重只表示资源准备完成，不表示当前 NPU 已支持相同算子或取得性能结果。

## 架构候选与公平对照

| 路线 | 实现要点 | 需要回答的问题 |
| --- | --- | --- |
| ASR→文本决策 | 同一 Qwen ASR 转写后，文本模型读 schema；另给人工转写上界 | 音频直连收益是否仅来自转写错误？整体延迟是否真正更低？ |
| 冻结声学表征+任务头 | WavLM/Whisper 或 ASR AuT 特征池化，问题/候选编码后评分 | 简单 SLU 是否根本不需要完整语言解码器？ |
| 冻结完整 ASR+读出 | 音频特征进入 decoder，任务前缀最后有效位置接 Choice/Noul/Score 头 | ASR-only 后训练是否已损害任务条件理解？仅训练头是否足够？ |
| ASR LoRA+类型化头 | 先冻结音频编码器，适配 projector/decoder；动态候选 mask、缺失任务 mask | 新 schema、同名异义定义与语言迁移能否泛化？ |
| 同骨干 label logits | 保持训练数据、前缀、参数预算一致，使用原 LM head 评分候选标签 | 专用头的独立价值是能力、校准还是接口/成本？ |
| 原生音频生成模型 | Qwen Omni/AudioJev/SFC 作为参照，报告全部加载参数和调用次数 | 小型方案是否在质量—成本曲线上占优？ |

Choice 应绑定候选身份，不能只学候选位置；Noul 使用适当二元目标；Score 要说明等级分布、期望或连续回归含义。候选超出容量时必须有明确策略，不能截断后继续报告无条件准确率。

开放槽位（姓名、地址、时间、数值）不能强塞入固定分类头。第一版比较转写 span、候选检索及受约束生成三种供给，报告候选召回率和参数完整正确率。`unknown`、缺参、冲突、超范围分别建模，不能都默认为负类。

## 分阶段验证与停止条件

1. **数据与接口复核**：固定模型/数据 revision；抽查波形、采样率、真实/合成来源、split 与 schema。完成一批真实前向后记录形状和有效位置；禁止用 padding 的最后位置读出。
2. **SLU 机制验证**：SLURP real train/dev/test，intent accuracy、slot F1、SLU-F1、全参数 exact match；MAC-SLU 多意图 exact match/F1。先冻结骨干，再小范围 LoRA。至少三 seed，语句/说话人聚类 bootstrap。
3. **动态 schema 验证**：SFC ID/OOD 函数，保持官方划分；对名称置换、定义重绑定、同义定义和无关定义分别评测。若只会旧标签、定义变化不引起正确变化，则不声称可配置决策。
4. **声学与校准验证**：MMSU、MMAR 等外部集；同转写不同韵律、背景指令、冲突证据；温度仅在独立校准集拟合。联合报告 NLL/Brier、ECE、风险—覆盖曲线、最坏分组和置换方差。低方差常量预测不能通过。
5. **工具与时序验证**：Audio2Tool 离线调用、FDB-v3 真人录音，然后接 τ-Voice 固定任务版本。报告工具/参数 exact、执行成功、错误调用、澄清率、撤销失败、重复副作用和端到端时延。必要时退回大模型，但计入成本与失败。

每阶段只在对应证据通过后推进。ASR-only 模型若适配成本高于通用音频基线且质量没有补偿，应承认这一否定结果；无需为了维持 Jev 命名继续堆叠模块。

## 运行时边界

确定性执行层负责参数校验、工具白名单、幂等键和任务版本；模型负责语义判断。纠正或取消使旧版本计划失效，执行前与播报前分别检查。借鉴 Jarvis/Qwen-Audio-Agent/Omni 的分工，但不要把外围规则的可靠性归因于模型头。

成本同时报告冷启动、音频编码、问题条件前向、开放参数解码、回退调用和工具等待。共享一次音频编码可以摊销编码成本，但不等于任意问题均零增量开销。NPU/GPU、精度、批量、输入长度、流式窗口与缓存策略必须一并记录。
