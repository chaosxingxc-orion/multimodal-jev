# Jev 前置问题、多字段判决与隐式计算：原始来源核验

本轮从 NGA 调研定位线索，再读取原论文及 Intern-Decision 官方源码。此前只检查 AnyJev 的 readout/question/tacit 局部代码，不能据此判断 Jev 生态缺少一次多 Span 案例；这一结论范围已纠正。下载的仅是论文页面和代码文本，无模型或数据权重。

## 已核实的不同机制

| 方法 | 问题与中间计算如何供给 | 推理次数/反馈 | 与当前任务的关系 |
| --- | --- | --- | --- |
| Intern-Decision | 所有问题、候选和含 `<decision>` 的完整 assistant JSON 骨架共同输入 | 一次因果前向，所有字段同时读出；不回填前置答案 | 最直接的多 Span 实现参照，但不等于已证明前置问题提高最终题准确率 |
| SemTree | 每个节点是带 Yes/No/Unknown 定义的前置问题，树结构组合结果 | 按节点判决，答案决定后续路径；最终结果由树给出 | 证明 Jev 的多步问题分解有实际案例；与一次填充全部 Span 是不同方法 |
| 并行子问题分解（内容审核） | 同一请求加入多个与分歧来源对齐的原子问题 | 读取各题预测分散程度，形成分歧信号 | 支持前置问题设计与数据属性必须匹配；不证明模型内部逐步 CoT |
| LAVOIR | 候选缺失信息槽位与答案选项同时输入，联合预测决策概率和各槽位信息价值 | 单次前向估计，但获取信息后的收益依赖真实追加回答 | 可参考联合读出，不将交互收益迁称为无新增证据的隐式思考收益 |
| SanSi / LEV | 对同一输入循环执行隐藏层，每一深度均有 typed 读出及训练信号 | 多次内部层循环，无文本生成；不必逐题外部调用 | 隐式计算深度的直接相关研究；依赖原生循环骨干，不能假定 Qwen3-ASR 原生支持 |

## Intern-Decision：与 Span 方案最接近的实现

论文：[2610.22131](https://arxiv.org/html/2610.22131)，§3.2–3.3、Figure 1–2。
官方代码：[InternLM/Intern-Decision](https://github.com/InternLM/Intern-Decision)，本次锁定 commit `565350244af860e1c276768cd80bdd9b8be93913`。

- 输入可为文本和图像，公开三字段示例是 team、urgency、refund_requested；不是语音模型。
- 每个字段的值位置为 `<decision>`。标签只在监督 tensor 内，改变 gold 不改变输入。
- 若占位符位置是 p，读取的是 p−1 的 native LM-head logits，训练采用相同 causal shift。不会逐个生成 JSON 字段。
- 早期占位符及其上下文对后续位置可见，但不会把早期 gold 或预测答案写回输入。共享隐藏状态与离散答案反馈要区分。
- 官方 `src/inference/hf_backend.py` 明确计算 marker positions − 1，然后一次 `self.model(..., use_cache=False, logits_to_keep=positions)`；训练 `src/inputs/masked.py` 将标签写在 marker 位置，并执行对应移位。
- 官方 `thinking.py` 是额外外部模型接管，不是上述一次多字段机制，不纳入当前端到端语音路线。
- 论文报告三字段 4B 在 RTX 4090、固定 289-token 请求下平均 44.16 ms；这是作者报告和特定负载，不是我们的 NPU 延迟。

这提供可复现的多位置判决设计，但本轮未见“同一 Final，只改变前置语义子问题”这一严格收益对照。不能把多字段能力或总体榜单成绩直接当成前置 CoT 收益。

## 多步分解确有案例，但效果取决于任务

[SemTree](https://arxiv.org/html/2610.13999) 在 ShARC 的 8,276 个测试案例上，Jev 执行树的作者报告准确率 67.70%，平均 2.99 问；直接问同一个 judge 为 68.23%。树的价值包含可检查和可修复，不是普遍准确率提升。换 judge 而沿用旧树只有 47.87%，按新 judge 重编译 12 个初始问题可达 64.39%，说明结构与执行模型必须协同。BANKING77 的节点修复从 82.04% 到 86.16%，应归因于所报告的修复设置，不能泛化成所有分解策略均有效。

§5.2 给出了具体前置问题案例：规则为“新申请 tax credits 的人需要申领表格”，用户询问自己是否需要表格，但情境仅说明居住地。树依次判断“情境是否确认必要条件？”→ Unknown，“问题是否属于规则主题？”→ Yes，“情境是否说明条件不成立？”→ Unknown，最终为 More（需要更多信息）。这是已有的多步 typed 决策案例；最终结果来自树的执行，不能描述为一次多 Span 的内部推理。§5.3 也报告了无效节点：某节点的全部答案都指向同一最终结果，说明增加前置问题本身不保证有用。

[内容审核分解研究](https://arxiv.org/html/2610.33258) 的并行子问题用于恢复人类标注分歧信号。改善集中在原始信心不敏感、且分解与分歧来源匹配的模型；强模型与域外条件不保证获益。这非常贴合本项目的数据协同要求：前置问题必须有与最终任务相关的真实结构，而非任意加几个辅助分类。

[LAVOIR](https://arxiv.org/html/2609.30706) 同时输出决策与缺失信息价值。作者报告 ABCD 上选择提问的子集经真实信息补充后提高 8.3 点。这是“新证据的价值”，不能用于证明相同音频内的多 Span 思考能获得同样收益。

## 隐式计算与一次调用的区别

[SanSi](https://arxiv.org/html/2610.07730) 和 [LEV](https://arxiv.org/html/2610.20951) 的机制是循环隐藏层、每个深度读出，不生成 token。LEV 报告 2.6B 在 JevBench 深度 1 到 4 从 63.2% 到 76.2%；SanSi 报告相同形状/数据配方下相较非循环对照提高 13.5 点，但计算量更多。以上是作者报告，不是本地复现。

还需保留 LEV 附录 A.3 的负面证据：作者把 Qwen3.5-0.8B-Base 的部分层改为带门控的重复执行，并训练 LoRA/选项读出；所测变体没有在任何面板取得置信区间整体高于零的准确率收益。默认门控训练后均值约 0.006，额外循环贡献很小。这不是 Qwen3-ASR 上的结论，但足以反对“给现有非循环骨干简单加循环就能复现 LEV 收益”的假定。

一次对外调用可以包含多次内部层计算。用户要求一次填充所有 Span、不采用 ReAct，不应被扩大解释成禁止内部隐式计算。首个工程候选可采用 Intern-Decision 式一次前向，循环深度作为独立候选；两者必须分别记录架构、计算预算与训练来源，不能混称同一方法。

## 本项目的修订

1. 将当前随机分类头 + marker 末位读出视为接线草案；它与 Intern-Decision 的原 LM-head + marker 前位并不相同，不能称为复现。早期真实 smoke 发现 Qwen3-ASR 模板丢弃 user 文本；随后改为完整 assistant 占位符上下文及 native head，v2 已通过真实前向，详见工程验收记录。
2. 首先实现并对照具有明确来源的完整占位符模板方案，保留音频前缀，核实 Qwen3-ASR 的 token 移位与输入身份；不预先锁死随机分类头。
3. 数据实验以“同一音频、同一 Final”固定目标，比较无前置问题、有相关前置问题、无关前置问题；再分别比较有无中间监督。完整并列多任务只是控制，不能把 date/time/timeofday 任意一项命名 Final 后声称构成推理链。
4. RL 仍面向完整 Span 输出的最终质量与可靠中间判决。不存在过程 gold 时，不强制指定思考顺序；不引入工具行动/外部停止策略奖励。

## 面向语音实验的证据要求

采用 Intern-Decision 式实现时，Final 在因果前向中能利用前置位置在较早层形成的隐藏表示；它不能读取本次前向结束后才由读出头得到的离散答案。早期位置同样不能看到排在它之后的 Final 问题，因此共享任务定义和关系约束应在问题序列之前给出。前置答案监督是否改善这条隐藏表示路径，需要实验判断。

锁定同一音频、同一 Final 及相同数据划分，至少比较：仅 Final；相关前置问题但仅最终监督；相同问题加可靠中间监督；等长度无关前置问题。报告 Final 指标、完整 Span 正确率、逻辑冲突率及真实计算成本。增加问题会增加输入长度，故一次前向不等于等计算预算。必要时用等长度占位输入控制额外位置的影响，并将问题选择限制在学习/选择集。

SLURP 原生意图和槽位类型可以承载联合判决，但并列标签不自动构成推理链。若以业务条件组合构造最终决策，必须明确标为派生任务，并加入“中间预测 + 确定性规则执行器”对照。只有在相同最终任务上超过这些控制，才有依据主张前置问题改善决策；否则按联合任务或辅助监督收益报告。
