### AudioJev 的方法与边界

对候选排列 π，将两个预测都还原到相同候选身份后计算：

`L = (CE(p,y) + CE(aligned(pπ),y))/2 + λ·SKL(p, aligned(pπ))`。

它约束语义相同候选在不同位置下的分布。若不监督正确性，常量分布也能使一致性损失很低；若候选文字依赖位置（如“以上全部”），排列不一定保持语义。模型卡区分了训练目标与 correctness calibration，并要求显式提供 fallback。我们的评价应在此基础上再扩展定义变化、语音变化和执行后果，而不是重复给顺序一致性换名。

论文报告三 seed MMAU/MMAR 均值 68.88%/55.33%；公开单 checkpoint 卡片为 69.41%/56.30%，二者口径不同。卡片还披露 MMAU 隐藏题中 119 项音源与拟合/开发资料重叠；因此不能用单个排行榜数字为“无污染泛化”背书。公开服务多问题共享音频编码，但按问题进行条件评分，问题数增加仍有成本。[R1]

### Qwen-Audio-Jev 的方法与边界

论文 v2 用最后输入位置的 decoder hidden state，三个头容量为 Choice 64、Noul 1、Score 10。Choice/Score 只对有效位置归一化，Score 由等级分布计算期望。模型为 40 层、2048 hidden、256 routed experts / 每 token 8 experts 的 MoE 主干，**不是 Qwen3-ASR 0.6B/1.7B 的结构**。

论文明确当前每个问题分别前向，因此“有三个 primitive”不意味着“一次前向同时回答任意多个问题”。其 RLCD 是作者给出的 sampled-action policy-gradient 方案，不能视为 TypeSafe 未公开训练算法的复现；对可微 proper-scoring 目标，应比较直接梯度与采样估计的方差、成本和结果。

v2 摘要 VoxCeleb1-O 93.76%，结论段 93.54%；本次记录这个内文不一致，不选一个数用于跨论文排名。NISQA 的 normalized MAE 与原始 MOS MAE 亦不能混用。[R2]

## 2. 技术谱系：哪些已经成熟

| 方向/代表工作 | 已建立的方法 | 对语音 Jev 的启示 |
| --- | --- | --- |
| 端到端 SLU；FSC（2019） | 声学预训练后直接预测语义标签 | “跳过 ASR 做意图分类”不是新方法；必须与其比较 |
| wav2vec 2.0、HuBERT、WavLM、SUPERB | 自监督语音表征、冻结编码器+轻量任务头 | 很强的便宜基线，检验是否真需要完整语言模型 |
| SpeechGPT、SALMONN、Qwen2-Audio/Omni | 离散语音 token 或连续特征与 LLM 对齐，多任务指令训练 | 直接音频语义理解的基础；输出改成类型化不自动提升语义 |
| Discrete Tokens or Continuous Features（2508.17863） | 同条件比较语音表示方式，报告连续特征通常占优 | 优先复用现有连续特征，但不能无对照宣称其普遍最优 |
| SLAM-ASR→SLU（2610.20844） | ASR projector 的零样本 SLU 行为诊断 | ASR 准确不保证指令遵循；需要区分编码、对齐、解码器瓶颈 |
| Speech-based Slot Filling with LLMs（2311.07418） | noisy ASR 的 ICL/SFT 和知识注入 | ASR→SLU 是必须保留的强对照；实体错误比平均 WER 更接近工具错误 |
| ClozeGER（2405.10025） | 带原音频的候选纠错、cloze 和 logits 校准 | 音频复核、候选限制可能比全句重生成更可控；也须测误修复 |
| SpeechRAG（2412.16500）/ ReListen | 直接音频检索或证据定位 | 长音频可先筛证据；评估召回上限与筛选成本 |
| MCR-BENCH（2508.15407） | 构造音频—文本冲突，揭示文字偏置 | schema 和上下文不应覆盖音频事实；做反事实冲突对照 |
| 温度缩放（1706.04599）、SelectiveNet（1901.09192） | 后验校准、风险—覆盖选择性预测 | 用独立校准集；ECE、Brier/NLL、风险—覆盖曲线联合报告 |

SLAM-ASR 研究中，改成数字选项提高格式/指令遵循，但语义性能仍远低于同 decoder 的人工转写输入。这个结果来自不同骨干和任务，不能直接作为 Qwen3-ASR 的性能预测；它提供的是需要检验的机制问题。[R10]

## 3. 类型化决策的学术与工程对照

- **Typed Decision Models: An Early Evidence Audit**（2609.32160）指出早期证据尚未显示 typed readout 相比同类 label-probability readout 的独立准确率优势。成本与接口益处应与语义能力分开。
- **Type-Safe Is Not Error-Free**（2609.26758）让选项名与定义重新绑定，展示类型始终正确仍可严重违背定义。对本项目需要测试“同语音，不同函数定义”的决策变化，而不只是原标签分类。
- **LLM-as-Jev**（2610.02076）提供冻结模型的 label-probability 推理与 KL-anchor 微调；表明专用头必须通过同骨干对照证明价值。
- **Kev / Nimble / Tev1**提供可读的训练、温度校准、接口和服务代码。Tev1 明确用既有语言头做选项标签 SFT，开发基准被复用；不能把其开发成绩当独立测试。
- **OneJev**将 typed decision 扩展到视觉/视频/文本。所查 README 的输入覆盖不包含原生语音，不能仅凭 multimodal 名称推断支持音频。
- **Laya/Vega**公开接口允许 `audio=`，但 README 明确音频先转写后文本决策；其音频 API 与音频原生读出不是同一方案。
- **TypeSafe Jev**官方发布博客可访问；文档域名本次返回代理提醒页，已标记阻断，未当作读到的文档。没有凭此逆向断言其内部训练算法或开放程度。

## 4. Agentic Speech 的最新机制不能遗漏

**Qwen-Audio-Agent**把前台全双工语音与后台长任务分离，并区分“打断说话”和“取消任务”；Jarvis进一步将任务版本、交接与交付检查做成显式运行时。它们比单一函数名分类更接近用户体验和外部状态正确性。[R7–R8]

**Heard Enough to Act**（2610.34653）研究 earliest actionable point；**Heartbeat Thinking**（2610.26233）研究监听期间持续推测计算并复用已完成结果；**VGBench/VoxGate**（2609.32536）研究 side-talk、自言自语与说话人变化时该不该执行。对本项目而言，“提前决策”“拒绝背景指令”“语音纠正后更新状态”均有先行工作，必须对齐任务定义及声学控制，不能把韵律、远场和声纹混作一个原因。

**APEX**（2611.09491，摘要层）采用意图原型选择候选，再检索演示。它主要在转写层比较 EMA，适合作为候选供给控制，不能把这类检索收益归因于音频 Jev。候选供给必须单独报告 gold recall@K，不然下游头的准确率没有可解释上限。

工业工程可借鉴 Pipecat / LiveKit 的实时传输、音频帧与打断机制，SpeechBrain / ESPnet-SLU 的数据/scorer，FunASR 的 ASR 组合，以及 workspace Omni 的持久队列与实验恢复。可复用的是组件和契约；这些库不会自动保证模型校准、语义一致或外部动作幂等。

## 5. 可以提出、但尚未证明的研究问题

1. ASR 专用后训练后，小型模型需要怎样的任务条件适配才能可靠读取未见 schema？与直接音频指令模型有何不同？
2. 共享语音表征下，有限选择与开放槽位如何协作，避免“意图对、参数错”的假成功？
3. 音频变化、候选排列和业务定义变化三种干预，是否可以同时保持该不变的稳定性与该改变的区分性？
4. 拒识/澄清能否在固定覆盖与调用预算下减少错误执行，而不是仅靠多回退掩盖能力不足？
5. 一个更便宜的小模型决策节点，能否在多轮纠正、取消、并发任务和真实语音中改善完成成本与可靠性？

这些是本项目的问题分解，并非已经证明文献空白。下一步需建立同条件基线和可证伪指标。[方案建议](04-recommendations.md)
