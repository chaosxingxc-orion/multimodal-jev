# 在未知输入主题时定义决策思考

> 最新定位见[语义规约驱动决策](21-semantic-decision-specification.md)：任务设计者提供
> 规约与思考决策范式，模型消费并使用它们，不要求模型自行生成链路。本页的输入独立性
> 及缺标约束继续适用，候选路线不再作为相互排斥的研究定位。

2026-11-12，依据用户对query-specific问题设计的纠正。取代19中的主题问句主实验建议。

## 问题所在

之前把“分析标签的混淆边界”过早转成“模型需要问这些具体问题”。这是不同层次：
离线知道一个样本属于alarm/calendar，并不意味着部署前可以为它提供这个问句包。
之前固定包对全人口使用，未实现gold路由，但仍只服务某个主题，大量样本只能回答
outside_family。该方案可作局部辅助分类，不能当作通用决策思考的主设计。
问句组合能唯一映射标签，也不能证明模型需要这些问题或能够借此提升Final。

## 构造问题时允许知道什么

允许：最终任务、完整候选及定义、公开任务本体、用户配置的思考要求与预算。
不允许：当前音频属于哪个主题、正确答案、参考转写、离线难度、预测后挑选的有利问题。
音频与合法历史可以进入模型作为待判别证据；首版问题构造器不读取其内容来选择问题。

```
问题模板 = compile(任务定义, 完整候选, 思考配置)
全部Span = model(音频, 合法历史, 问题模板)
```

同一任务配置下，换任何音频都得到相同的问题文本、候选和顺序；换音频不能改变模板，
更换或移除gold/参考文本也不能改变模板。最终候选始终完整。
任务配置可改变问题，不要求所有数据集共享一套完全相同的语义属性。
当前契约保持一次调用交付全部Span，不新增外部预测主题→挑题→再调用的步骤。

## 两条需要分别检验的候选路线

**全任务属性分解。** 若任务本体有完备属性，可对所有样本使用“请求涉及什么对象/领域？”
“请求执行什么操作？”“完整候选中哪个匹配？”等问题。取值覆盖全本体，不能预先只给
闹钟/日历或几个设备。现有SLURP全scenario/action视图满足样本无关性，但action包含
标签专用名称，许多值直接识别Final。它首先是辅助分类控制，不等于通用推理链。
重新抽象共享属性必须审查语义一致性和覆盖性，不能为追求组合数量强造分解。

**通用思考要求与内部计算位置。** 用户可以配置关注请求目的、区分提及与请求、核对
支持与冲突证据等要求。模型根据当前音频在隐藏状态中处理具体证据，模板不预知主题。
这是一条研究候选，不是把“检查一下”写进prompt便已实现推理。
若过程Span要输出可解释typed state，必须先定义其含义、可用值和可信监督；
SLURP的单一intent标签不能推出“证据充分”“无矛盾”“无需上下文”等过程gold。
若改用无语义过程标签的内部计算位置，则需另行登记结构及梯度路径，不能把任意状态
正确性写成过程奖励。用户要求的可配置思考不能退化成仅固定两个辅助标签头。

通用问题如“当前证据是否足以唯一支持候选”也可能是额外任务，未必能从现有标注验证。
“哪个候选最匹配”重复多次可能只是重复Final。两者都不能作为现成解决方案交付。

## 数据和训练的后果

保留完整SLURP学习人口、两阶段训练、RL+衰减CE、端到端音频和BF16约束。
当前Stage1的全本体视图仅用于指令/候选消费能力，不能称已在训练新的通用思考策略。
不改冻结的运行快照。主题模板候选保持未准入且明确禁止派发。

本体/语言/声学/模型经验四维复杂度分析仍有价值，用于离线报告与分析，不能参与输入选题。
复杂数据需在同一个通用问题模板下呈现不同推理负担；缺标或上下文不足不能用Final反推补齐。

近期先核查完整本体的可复用属性及已有全scenario/action控制，再确定通用思考结构。
只有Final监督时不伪造过程reward；有可信属性监督时可使用固定预算辅助CE/reward，
如实称为属性监督。保留同起点同数据的Final效果比较，但在新问题契约落实之前不派发
旧主题包D/Q/P矩阵。收益判定仍需独立评测、候选绑定稳定性、计算成本和退化统计。

## 验证准则

- 输入独立：同配置换音频、换gold、换离线切片，问题模板完全相同。
- 定义消费：候选定义改变时，模型依照新定义决策；重排序/符号重绑定不改变语义答案。
- 中间作用：控制额外文本、辅助监督和计算量，检验中间表示对Final是否有贡献。
- 复杂度承载：同模板在可信复杂切片及外部任务上报告收益，不能只报告特定主题成功。
- 证据边界：属性分类改善、隐藏计算收益、组合泛化分别命名，不提前统称CoT能力。
