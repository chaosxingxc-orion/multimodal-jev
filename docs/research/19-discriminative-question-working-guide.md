## 1. 什么算简单、什么算复杂

不能给每条音频直接贴一个“简单/复杂”总标签。首先分四个轴，再报告交叉切片：

| 轴 | 可落实的划分 | 当前证据及限制 |
|---|---|---|
| 标签判别结构 | 单属性可消歧；多个属性须组合；仍有多个兼容类 | 固定本体可精确复算；不等于实际推理步骤 |
| 语言证据 | 明确请求；省略/指代候选；否定/纠正候选；多个请求及绑定候选 | 参考文本仅离线筛查；需逐条审核才能成为过程监督 |
| 声学 | 时长、幅度、静音、噪声、可懂度 | 已有时长/幅度；其余未评级，不用短音频直接代表简单 |
| 模型经验 | 固定检查点预测对错、正确候选margin、不同模板/符号绑定稳定性 | 尚无本轮全量模型难度结果；学习数据可用于诊断，TEST不得反向设计规则 |

简单候选：单一明确请求、一个共享属性足以区分；还需确认声音和语言没有额外负担。
结构复杂候选：至少两个非冗余属性才能消歧。语言复杂候选需独立证据审核，不能靠出现
and/not自动判定。上下文不足、标注冲突应进入质量隔离，不能当作“更难”的训练目标。

正式SLURP学习集40,513条：单组件可解26,834条、联合消歧13,679条。
9,192条参考语句中，否定词触发91、纠正词触发7；不足以直接支撑大规模否定/纠正
推理主张。多录音重复同一语句不能增加独立语义样本数。

## 2. 优先做哪些问句

核心规则是把容易混淆的最终标签分成**可跨类别复用的判别属性**，并用不同属性共同
缩小语义歧义。最终读出仍保留60类，问句答案不用于硬裁剪或外部规则回填。

| 固定模板包 | 前置判别维度 | 训练录音支持 | 推荐角色 |
|---|---|---:|---|
| 闹钟/日历 | 服务对象；新增/查询/删除 | 6类、7,422条全部需两问组合 | 第一组机制实验 |
| 设备控制 | 音量/灯/插座；增减/开关/静音/颜色 | 共11类4,064条，其中8类2,808条需两问组合 | 第二组，适合向FSC迁移 |
| 音乐/邮件 | 各领域请求目的 | 9类6,597条；单问足以唯一确定族内标签 | 语义重述候选，不作组合主证据 |
| 食物/交通 | 各领域请求目的 | 8类3,517条；单问足以唯一确定族内标签 | 后续候选；cooking_query仅2来源 |

“组合”是相对于这套属性划分而言。原scenario/action中的audio_volume_up只凭action
就能确定，但在更可迁移的device/increase划分下，要同时识别设备与变化方向。
这正是设计问句的价值所在，也说明不能将模板划分当作数据的绝对难度。

教学示例（人为编写，非原始数据引文或新增训练样本）：

```
输入：音频“删除明天的日程提醒” + 完整候选定义
Q1：请求属于闹钟服务、个人日历，还是其他任务？ <SPAN1>
Q2：针对闹钟/日历，请求是新增、查询、删除，还是其他任务？ <SPAN2>
Final Q：完整60类中，用户请求的意图是什么？ <SPAN3>

目标：personal_calendar / remove / calendar_remove
```

再如“把灯调亮”：lighting / increase / iot_hue_lightup；“把音量调大”：
audio_volume / increase / audio_volume_up。共享increase，设备不同，Final不同。
不能仅因听见时间词就判calendar，或因提及邮箱地址就判sendemail。
实际训练使用配置中的英文问句和数据的真实音频。

所有Q及Span位置预先输入，一次前向同时读出；当前Final可以利用前序隐藏表示，
没有前置离散答案回填。因此应称“结构化判别辅助”，是否学会组合推理需要额外证据。

## 3. 问句制定与准入规则

1. **问请求关系，不问孤立关键词。** “用户要求对哪个对象做什么”比“是否提到灯”
   更贴近任务；提及对象不能自动映射成操作意图。
2. **一问一个主要维度。** 优先可交叉组合的对象/操作；避免Q1或Q2直接复述全部Final。
   用本体分区检查单问能区分哪些类、两问额外区分哪些类。
3. **固定、完备的状态集合。** outside_family表示已标请求不属于该任务族，不表示音频
   没有相关词。未知、冲突、缺标只mask监督，不伪造成outside或false。
4. **问题选择不能依赖答案。** 每个实验使用固定包，全人口相同；训练可用标签无关
   日程轮换。禁止按gold、离线复杂度或参考文本给单条样本挑最有利的问题。
5. **过程标签说明来源。** 当前对象/操作来自官方意图投影，属于辅助任务标签。
   否定作用域、纠正后的有效意图、指代解析和可听证据不能从Final反推。
6. **先核对定义和边界，再准入。** 按学习来源覆盖每个取值及相邻意图，核查对应原句
   与音频；发现冲突隔离相应监督。未审核的问句配置保持candidate状态。

无需为了问句实验等待新的否定/指代标注；第一轮先验证有可靠意图投影支持的两组。
当前已冻结Stage1日程只含direct、scenario、action及其structured视图，
上述新问句尚未接入；新问句需新版本准入与processor检查，不改正在运行的快照。

## 4. 分类均衡、Loss与Reward如何配合

主训练覆盖全部学习录音，不退回小数据子集。按类交错提升batch多样性；当前全覆盖日程
不保证每个batch严格均衡。类别最少2条、最多2,557条，重复稀有样本不能解决独立支持不足。
报告每类支持、来源组数和召回；测试保持原分布。

过程存在更严重的outside捷径：schedule恒答outside已达81.68%，device为89.97%，
其余问题91.43%–96.37%。这不是模型成绩。初轮沿用Final权重1、过程总权重0.2，
按有效问句分配，并分别记录族内/族外的CE、reward、召回和梯度贡献。
若需平衡权重，依据学习集频率预先冻结，设置上限；另立版本并验证有效分母，
不同时叠加过采样和逆频率加权，也不根据selection表现动态改奖励。

Stage1使用masked分类CE；Stage2使用有限候选PPO + 衰减CE，lambda从1到0.1为当前
默认协议。过程答对但Final答错可以获得少量辅助信用，但不会记作任务成功。
不奖励“预测之间自洽”本身，三个一致但错误的答案不得获得正确性奖励。
总reward可能因过程项增加而上升，所以最终判断始终看Final独立指标。

## 5. 怎么证明问句帮助最终决策

固定Stage1初始化、完整学习人口和预定更新预算，Stage2使用同样的RL+衰减CE框架：

- D：直接Final。
- Q：加同一套前置问题，但只给Final监督/信用。
- P：与Q完全相同输入，加入固定预算的过程CE和reward。

Q−D观察问题结构的收益；P−Q观察过程监督的合并收益。由于P同时增加过程CE和reward，
不能将差值单独归因于过程RL奖励；若后续需要该归因，再固定CE、只改变过程reward。
不增加RL与SFT的胜负比较。记录各自检查点完整曲线，避免只报最好的一步。

主要验收是9,226条内部selection的60类Final accuracy、macro-F1及逐类召回，
后续官方DEV/TEST遵守已冻结协议另报，不能把内部selection称为官方测试。
补充分组：原单/双组件、模板联合消歧子集、族外、长尾及已审核语言/声学切片。
以来源组做配对重采样区间，避免同一句多录音被当作独立证据。

机制诊断：过程全对但Final错的比例、过程错但Final对、修复/退化样本数、候选重排和
符号绑定稳定性，以及推理tokens、延迟、NPU时间。P−Q同输入能控制问题长度；
Q−D包含新增文本和计算的影响，若声称语义问题结构的专属效果，还需长度接近的无信息
问题对照。仅过程准确率或一致性提高，不构成Final收益。

## 6. 其他数据集可以承载什么

以下沿用[数据集工作基线](08-dataset-metrics-working-guide.md)与既有本体审计，
没有重新统计其他数据集人口或新增训练准入。

| 数据集 | 简单与复杂的可用区分 | 可问的属性及边界 |
|---|---|---|
| FSC | 31命令中9类单组件可解，22类需至少两组件，其中4类需三组件 | action/object/location；当前只作SLURP冻结模型配置迁移，不恢复FSC主训练 |
| MAC-SLU | 单意图；多意图及各自槽位绑定 | 每个意图是否成立、某类型属于哪个意图；必须保留绑定，不能只问全局类型集合 |
| SFC/SpokenFC | 单函数；相近函数、多调用、上下文依赖 | 函数适用性、已标参数是否具备；保留历史和音频，函数选择不等于执行成功 |
| Audio2Tool | 原生tier下的单/多工具与参数组合 | 工具适用性；缺参数标注mask；只测不训，不能用其测试错误设计问句 |
| SLUE | 单情感/DAC；多实体类型、需局部证据的判断 | 类别或类型存在性；情感不天然有可监督决策链，类型检测不能冒称完整NER |
| MINDS-14 | 单意图为主；跨语言/口音带来的迁移难度 | 服务目的与事务对象，需验证本体映射；多语言难度不是多步逻辑 |
| SpokenWOZ | 单轮明确更新；指代、修正、跨轮状态更新 | 某槽位需保留/更新/清除；必须提供允许的历史，开放值仍需其他读出 |
| MMAR/MMSU/MMAU | 原生有限选项；时间关系、多音源或声学关系 | 使用原始音频问题；额外过程证据缺标时不能从选项答案自动造链 |
| VoiceBench/FDB/τ²/EVA | 开放回答或交互决策 | 仅把有定义和标注的有限节点变成Jev；保持生成和环境成功指标，后续独立研究 |

近期主线以SLURP的两组可交叉属性验证Final收益，再用FSC检验可迁移的设备/操作定义。
更复杂的多意图绑定和上下文决策由MAC-SLU、SFC、SpokenWOZ承载，不能靠改写SLURP问句
凭空制造这些能力的监督。
