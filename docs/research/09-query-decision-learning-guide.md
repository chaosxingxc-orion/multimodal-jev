# 单问题、多问题与推理策略：语音 Jev 学习设计 v1

> 用户后续明确修订：不采用触发文本推理路线；所有 Jev 模型应接收可配置思考要求，通过触发与判决改善能力。本文文本 CoT 实验臂及其触发方案已被[当前契约](10-configurable-thinking-decision-contract.md)取代，保留为讨论历史。单问/多问、来源与决策包的区分继续有效。

日期：2026-11-11。回应“一个 query 对一个决策，还是多个问题/决策，以及是否引入显式思维链”的研究讨论。
与 [数据集和指标指南](08-dataset-metrics-working-guide.md) 配套。本文是建议与待验证假设，不是模型能力、性能收益或训练启动声明。
参考 NGA 的来源隔离、问题集合扰动和规则判别方法，以及本项目已验的 SFC/Audio2Tool 退化控制；没有将 NGA 的研究假设当作已证结论。

## 1. 建议：原子决策作为监督单位，决策包作为任务单位，依赖图作为复杂策略扩展

不建议在“全都单问”与“全部一次多问”之间二选一。
数据保留可独立验证的原子目标及它们的关系；同一份数据可渲染成单问、多问和有监督的依赖任务。
首轮建立单问直接决策基线，随后比较共享音频的多问直接决策；复杂任务优先增加可核验的中间状态，显式自由文本思维链作为独立消融。
不预设多问一定更强，也不预设推理文本越长决策越正确。

| 层次 | 单位 | 作用 | 不应混淆的概念 |
|---|---|---|---|
| 来源层 | 音频/会话及允许历史 | 去重、划分、独立样本统计 | 一个录音生成 100 题不是 100 个独立来源 |
| 问题层 | question + 定义/候选 + 输出类型 | 给出明确判定标准 | 问句文本不等于规则语义 |
| 决策层 | 有 ID 的一个语义变量 y | 监督、错误归因、缺标 mask | JSON 一个字段/一个数字不一定是简单任务 |
| 任务层 | 同一业务规则下的 decision bundle | 整体目标和关系约束 | 同音频不同竞争规则是不同上下文，不能互相要求答案一致 |
| 策略层 | 根据观测状态选择下一步判定/行动 | 处理依赖、澄清、执行与终止 | 一次输出很多标签不自动是规划或 Agent 策略 |

`query` 在这里指一次用户语音请求及可见历史；一次 actor request 可以包含一个或多个 question。
“输出数值”还应区分：类别 ID 是符号；有真实等级定义的数值才是 Score；概率是模型估计；任意金额/日期通常是抽取/归一化。
`state` 是一组有定义的状态变量或状态标签，必须说明它们表示用户意图、当前证据还是执行后环境状态。模型不能通过输出 `success` 就认证工具执行成功。

## 2. 四种模型组织方式

令 x 为音频，h 为可见历史，S 为规则与 schema，Q={q1,…,qm} 为问题集合。

| 方案 | 条件化方式 | 优点 | 风险和成本 |
|---|---|---|---|
| A 单问直接决策 | p(yi\|x,h,S,qi) | 可解释归因、mask 简单、便于验证定义遵循 | 重复编码/前向；独立错误可能造成整体矛盾 |
| B 多问直接决策 | p(y1,…,ym\|x,h,S,Q) | 共享音频证据、可利用问题关系、减少重复工作机会 | 题序干扰、长 schema、负迁移、整包格式失败 |
| C 依赖状态决策 | p(z\|x,h,S)，p(y\|x,h,S,z) 或确定规则 g(z,S) | 可检查中间证据与业务组合、定位错误 | z 不充分或错误传播；oracle z 只能作诊断 |
| D 中间文本推理再决策 | p(r\|x,h,S,Q)，p(y\|x,h,S,Q,r) | 可能支持例外、组合、跨轮更正 | 增加解码、伪推理、教师偏差、前错后承、低延迟受损 |

B 可以是并行多个读出，也可以是自回归 JSON；二者不能都笼统叫“一次前向”。
共享声学 encoder 不等于 decoder 计算免费；长定义交互仍有注意力成本。
并行头形式即使条件在全部 Q 上，输出分布也可能是因子化的，并不自动学到联合依赖。
自回归联合输出建模 p(yi|x,h,S,Q,y<i)，会受输出顺序和训练 teacher forcing 的影响；必须用实际预测前缀评价，不能用 gold 前缀评测。

C 中若 g 为确定执行规则，应与直接模型用同一个规则接口比较，并分别报 z 的语义正确、g 的组合正确、最终任务正确。
不能把运行时硬约束带来的合法率提升全部归因于模型推理。
中间 z 若只保留预测意图和类型，可能丢失开放值、否定范围或声音线索；最终判定可以继续访问原音频，而不强制只读压缩状态。

## 3. 多问题是不是复杂策略？看依赖，不看数量

“识别意图、是否有人名、是否有时间”可以是三个并行判定，不必生成推理链。
“只有预订意图且必要信息齐全、没有取消/更正、满足业务限制时才发起调用”有依赖关系，适合决策图。
“听到后半句更正后撤销旧计划、等待工具结果再回应”是带时间与环境反馈的策略，静态多问训练不足以证明。

因此建议按可观测任务属性分层，而非根据模型做错与否事后定义难度：

| 复杂度层 | 任务性质 | 可用数据 | 优先方案 |
|---|---|---|---|
| C0 | 直接单目标、有限分类 | FSC、MINDS、SLURP intent | A；无需默认 CoT |
| C1 | 多标签并列、局部绑定 | SLURP types、MAC-SLU 多意图 | A/B；加关系指标 |
| C2 | 明确合取/例外、跨意图参数绑定、多个证据条件 | 经审查的派生规则、SFC 多函数/缺参 | B/C；D 作消融 |
| C3 | 跨轮更正、取消、状态继承 | SFC 多轮、SpokenWOZ、Audio2Tool 对应 tiers | C，保留完整上下文；D 作消融 |
| C4 | 部分观测、动作反馈、实时等待/恢复 | τ² voice、FDB、EVA | 真正时序策略；独立闭环评测 |

上表是本项目工作分类，不是文献公认定理。数据原标注不支持取消、执行准备度或政策条件时，不擅自构造这些 gold。
SFC 的 `NAN` 可以支持发布协议内的缺参判定，但“缺参就必须追问”仍需业务规则；某些工具允许缺省参数。

## 4. SLURP 应如何落地

同一来源保存意图、可用的类型存在标签及监督状态。首轮核心决策可按 **1 个 scenario/action Choice + 55 个类型 Noul** 组织，最终数量以通过定义审查的任务 bank 为准。
这与原始 intent 字段的 91 类不同；不是重新定义原生标签。
旧 v1 的 168 项包含三个意图视图、55×(present/absent/values)，不必全部作为一次训练输出。
值抽取是独立任务；反向问题和排列/重绑定用于成对检验或预注册训练增强，不把同一个事实重复几遍当成更丰富监督。

示意输入与输出（仅说明结构，不是发布样本或已验收的 schema）：

```json
{
  "input": {
    "audio": "shared://example.wav",
    "questions": [
      {"id": "q_intent", "type": "choice", "definition": "按本次提供的意图定义选择", "candidates_ref": "bank-v1"},
      {"id": "q_person", "type": "noul", "definition": "按本次语义角色定义判断是否提及人物对象"},
      {"id": "q_time", "type": "noul", "definition": "按本次时间类型定义判断是否存在对应证据"}
    ]
  },
  "output": {
    "q_intent": {"value": "candidate_b"},
    "q_person": {"value": true},
    "q_time": {"value": false}
  }
}
```

具体定义必须完整解析后提供给模型，不能只给内部 bank ID 让模型背标签；候选与 gold 隔离。
模型输出只给被询问的决策；target 单独保存缺标/冲突 mask，不能在 input 告诉模型某题 gold 不可用。
原子表示和 bundle 表示同时保留，来源闭包只做一次；训练时可以按来源抽取固定预算的问题子集，评测保持事前冻结的完整问题集合。

首轮不根据预测 intent 裁剪类型问题，否则意图错误会让应该回答的槽位消失。
若研究稀疏路由，单设实验：未选择的问题仍按完整请求集合判定遗漏，并报路由 recall；不能只统计被模型挑中的题。

## 5. 问题由谁提出、最终判决由谁作出

有三种不同研究任务，建议先实现前两种：

1. **外部定义问题，模型回答**：业务 schema 给出问题及候选。适合首轮 Jev；最终输出是可消费决策或决策包。
2. **外部定义依赖图，模型判断节点**：图明确哪些事实支持哪项动作；确定逻辑由执行器组合，语义节点由同一音频模型判断。节点按真实预测执行，最终正确性覆盖所有必需条件。
3. **模型自主提出子问题/选择下一步**：模型还负责分解、验证、停止。它需要问题合法性、证据覆盖、分解完整性及成本的监督/反馈，不能只用 SLURP 原意图标签证明训练有效。

“先生成问题再回答”可能只挑容易题或生成直接泄漏答案的问题；必须保留外部定义的最终任务和固定评测分母。
动态澄清需要真正追加用户信息，静态数据只能验证有标注的分支；不能假定问了问题就自动获得正确答案。

建议数据可保存 DAG/关系图，但先限定可核验的依赖，避免循环自证。被跳过的条件是明确的业务“不适用”还是遗漏，必须由规则区分。
运行状态区分 pending/answered/error/skipped_by_rule；语义标签、拒答和 gold unavailable 不能都混成同一个 state。

## 6. 显式思维链：应该研究，不宜默认进入主路径

直接输出也可能依赖模型内部复杂计算；看不到文字理由不等于简单策略。
相反，输出一段合理解释也不证明它对最终决策有帮助或真实反映证据。
Qwen3-ASR 原模型是 ASR-only，不能通过新增“请逐步思考”就假定具备可靠推理；需要端到端任务适配和比较证据。

建议把中间信息分为三类：

- **可监督结构状态**：意图、角色存在性、规则条件是否满足、明确更正关系。有标注/确定规则时可逐项验真，最优先研究。
- **简短证据说明**：指明哪些观察支持判定；新增说明必须依据音频/可信标注复核。无时间对齐标签时不编造时间戳。
- **自由文本 CoT**：任意长推演，缺少可信过程标签。只作成本受控的实验臂，既不奖励长度，也不靠“讲得像”给正确性奖励。

允许同一音频 actor 生成中间文本再给 typed 决策，这仍可以是直接音频路线；不引入独立转写语言模型，也不输入 gold transcript。
但它不再是严格的无自回归推理、单前向决策，应分别报告架构和时延。
如果先输出最终答案再生成解释，这叫解释输出，对先前决定没有因果帮助，不作为 CoT 改善的证据。

远程教师可以离线提出 TRAIN 规则/中间状态草案；若教师没有音频，它生成的文本不是声学证据，不能监督“听到了某种语气/背景声”。
仅基于正确最终答案倒推的链可能是事后合理化；未经核验不能当过程金标，TEST 不用于生成或选择链。
强教师给直接答案与给链时要尽量控制额外信息和调用预算，否则不能把教师更强/监督更多解释为 CoT 收益。

### 推荐消融，不做昂贵的全笛卡尔积

| 臂 | 推理时输入→输出 | 用来回答的问题 |
|---|---|---|
| A0 | 单问题→直接决策 | 最小可学、可验基线 |
| A1 | 多问题→直接决策包 | 共享与联合条件化本身是否改善质量/成本 |
| A2 | 多问题→可核验中间状态→最终决策 | 显式结构分解是否优于直接决策 |
| A3 | 多问题→受长度预算约束的文本推理→最终决策 | 文本推理相对 A1/A2 是否有额外收益 |
| A4（后续） | 训练时使用核验过程监督，部署直接决策 | 过程知识能否蒸馏，保留部署时效率 |
| A5（后续） | 直接决策，校准路由到 A2/A3 | 仅难例追加计算是否改善质量—成本曲线 |

先做 A0/A1；仅在 TRAIN/selection 的预定义 C2/C3 任务确有空间时扩 A2/A3。
A4 必须训练并评价真正不依赖推理前缀的模型，不能把 A3 的文本隐藏起来就叫无推理。
A5 的难度/不确定性路由来自模型可见信息及独立校准，不能用 gold 判断难题；阈值在 selection/calibration 冻结，计算基础路径加所有升级路径的总成本。
固定同骨干、来源、规则、训练初始化；单独做监督机会匹配和部署预算匹配，无法同时匹配的维度如实披露。

验证 CoT 收益至少要看最终决策正确率、依赖任务全对率、未知规则泛化、平均与 p95 延迟、音频前向数及生成 token。
中间状态可做删除/扰动的受控诊断并重新生成最终答案；性能变化不等于证明所有文本链都忠实。
无改善、只改善格式或只增加预算时应据实收缩结论，不默认长链更强。

## 7. 学习目标：原子监督与整任务目标共同存在

建议先 SFT，后对齐奖励。原子标签保证可学习，关系与整包目标让局部正确转化为任务正确。
全部只用整包 0/1 奖励可能过于稀疏；只平均小题正确率又可能被多数负例支配，两者都需要控制。

可作为新协议起点的符号目标（权重尚未冻结，未声称已实现）：

L = 平均来源 [按决策类型归一的 masked L_atom + λ_rel L_verified_relation + λ_final L_final]。

每个来源先归一，再按任务类型/规则族采样；不能让问题多的录音或大量无关工具主导梯度。
mask=0 表示缺监督，不是负例；正反命题的损失不得不加说明地重复放大同一个事实。
关系约束只施加在已验证关系上，真实不同规则允许不同答案；必须保留独立语义监督，避免“逻辑一致但全错”。
完整 state/图推理首轮应沿真实预测评估；训练若 teacher-force 中间 gold，需要披露暴露偏差，不能把 oracle 过程成绩当推理成绩。

RL 分组边界取决于实际 policy action：单问方案对同一完整单问 request 的 K 个采样分组；联合方案对同一完整问题包的 K 个响应分组。
同音频不同问题不是同一个 GRPO prompt；不同题答案不能混成彼此的相对优势组。
图式策略若包含多个模型调用，是轨迹/多步信用分配问题，不能复用单响应奖励后宣称已解决。

SFC 已有数值审计发现：对同 prompt 的奖励统一乘正类权重，在标准差归一化 GRPO 中会抵消；需要明确采样或策略损失层面的加权，而非只改奖励前的系数。
见 [数值证据](../engineering/sfc-reward-balance-numerical-v1.md)。这些是夹具/代数验证，不是新训练效果。

## 8. 多问和复杂推理必须新增的评测

保留原有单题正确率、类型集合 EM/F1、整包全对和原生完整任务分数，并增加：

| 轴 | 检验方式 | 防止的错误结论 |
|---|---|---|
| 单问 vs 多问 | 同一题独立回答与放入包内，比较配对正确性和语义一致性 | 仅看多问平均分掩盖退化 |
| 问题集合变化 | 排列；添加/删除预注册的语义无关问题；不同包长 | 被题序/邻题答案带偏 |
| 有关信息变化 | 改规则/补证据时按新 gold 判定 | 误把一切“不变”当可靠 |
| 依赖传播 | 前置节点错/对条件下的最终错误；oracle 节点仅诊断 | 用真实 gold 中间状态夸大效果 |
| 分解/路由 | 必需问题覆盖、遗漏、无效子问题、额外调用数 | 只答容易题抬分 |
| 结构推理 vs 文本链 | 同任务同预算最终指标、过程可核验率和失败类型 | 文本更长/更流畅被当作更正确 |
| 难度迁移 | 预注册规则深度、例外数、跨轮跨度；整族留出 | 记住规则模板就声称复杂推理 |
| 效率 | 完整任务时延、音频编码/decoder 次数、token、显存 | “一次请求”被误写为“一次前向” |

无关问题扰动不应偷加真正相关的新证据；只有语义任务不变时才要求答案不变。
同一包增加所需决策数会自然降低 all-correct，比较时固定包定义或按同一包长/规则复杂度切片，不能直接对比任意包。
统计仍按来源组/会话聚类，多题不是独立样本。

## 9. 首轮落地建议与证据边界

数据层现在就保留 source→question/decision→bundle→relation 的结构，但不要求首轮 actor 自主生成问题或自由规划。
SLURP 清理与类型定义通过后，以 A0 建立直接音频可学习基线，再用同一数据比较 A1；FSC 只做小型控制。
MAC-SLU/SFC 提供绑定、规则和多轮复杂度；使用其 TRAIN 做过程监督时，明确改为适配轨道，不能继续称纯迁移。
Audio2Tool 的复杂 tiers 保持外部评测，不根据该 TEST 的表现设计链或路由阈值。

如果 A1 主要节省成本而不改善准确率，也有清晰价值；如果 A2 对 C2/C3 有益而 A3 无额外收益，保留结构状态路线；若 A3 在未知规则和同预算下持续改善，再研究 A4 蒸馏或 A5 自适应计算。
以上均是可证伪的选择准则，不是对未来结果的预言。
