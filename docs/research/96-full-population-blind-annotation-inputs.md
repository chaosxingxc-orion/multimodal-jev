# 全量独立语义复核输入与实际规模

发布`blind-semantic-annotation-workpack-v1`，位于共享SLURP Jev数据目录，
覆盖全部9,192学习来源、40,513录音、65个I_present和55个S_present谓词。
工具为`tools/jev/build_blind_semantic_annotation.py`，输入目录v4和槽位包v13不变。
这次交付是完整离线标注输入与日程，不是完成标注或准入训练。

每个来源都接收相同的16个面板：9个意图、7个槽位，每面板最多8个待判决谓词。
每轮147,072请求、1,103,040坐标；两轮294,144请求、2,206,080判决。面板按任务ID
固定排序，不按native、历史正负、样本主题或模型预测选择。每个请求只含一个来源，
语义监督可在来源级复用，但不能宣称同参考的全部录音已听审。

`sources.jsonl`只保留内部review_id与原始参考文本；`templates.jsonl`只投影当前
语义字段。`render`再以白名单构造实际请求正文，不传source_id、native标签、历史
建议或录音路径。完整来源和录音映射存在`bindings.offline.jsonl`，调度身份存在
`schedule.jsonl`，两者都不属于标注正文。参考文本明确当作待判数据，不能作为对
标注器的指令。此处的离线文本标注不是模型推理路线；actor仍直接消费音频。

槽位面板保留每个待判类型的全部相邻边界及邻居定义，使用已有runtime_field_groups
明确选定的语义字段，剔除历史例子/原生支持计数。每个待判谓词必须返回明确
positive/negative/unavailable及理由；漏项、重复、额外项被拒绝，绝不从缺少正例
推导负例。响应结构正确仍只是建议，不自动授予独立复核或训练权限。

输入体积测量发现：意图面板最大请求JSON约15,736–21,647字节，槽位为
190,468–405,268字节。后者有大量重复规则，说明即使每面板只问8题也不能假定
上下文安全。这里只测量UTF-8 JSON字节，不把字节折算为token，不声称教师上下文
通过。下一步复用现有shared_rules_v1做可逆共享，再核对选定教师tokenizer、输出
额度和调用费用。不得截断规则或减少全量人口来假装满足预算。

现有Omni远程教师入口绑定提示词反馈协议，不直接用于本次标签标注。尚未选择标注
服务或发API，也没有新NPU任务。两轮复核为计划，需分别记录真实审核者/模型版本、
输入身份及是否看过前轮答案；不能把同一作者重读、两个文件或模型一致当作独立真值。
原有标注建议保留为对照，独立输入不展示它们。最终还需要分歧裁决、参考与音频证据
边界、selection语义标注及有效覆盖验收。
