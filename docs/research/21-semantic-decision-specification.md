# 语义规约驱动的 Jev 决策

> 用户进一步明确核心需落实为[可迁移判决Q](22-transferable-decision-questions.md)：
> 先抽象共同逻辑判决要素，再配置概念定义，训练Q并评测Final收益。总体规约不能代替Q设计。

2026-11-12。依据用户最新定义：研究对象是供模型理解、参考和使用的语义规约与思考
决策范式。链路由任务设计者供给，模型消费音频与规约作出决策；不要求模型自己生成
思维链。本文更新12/20的研究定位，保留端到端音频、配置化、一次交付typed Span的接口。

## 规约包含什么

| 部分 | 定义内容 | 与当前样本的关系 |
|---|---|---|
| 判决目标 | 最终需要决定的变量、单/多标签、输出类型 | 任务级固定 |
| 概念及边界 | 完整候选含义、必要区别、包含/排除条件 | 根据合法任务本体配置，不预知答案 |
| 证据规则 | 允许的音频/历史、提及与请求的区别、可推断范围 | 模型从实际输入判断如何适用 |
| 组合与优先级 | 哪些条件需联合满足、冲突时如何处理 | 配置定义关系，输入提供事实 |
| 决策范式 | 判断目的→绑定对象与操作→核对定义及排除条件→综合判决 | 提供计算的语义组织，不输出自由文本过程 |
| 读出契约 | Final与可选过程Span的类型、候选、未知/缺标处理 | 只填配置要求的值或state |

语义规约不等于把所有常识写成硬规则，也不等于堆叠冗长提示。可先用自然语言和显式
字段表达，最终实现是否采用图、专用节点或内部循环另行验证，不因称为“链路”就预设
外部执行器或架构已经存在。

## 与输入无关的范式，作用于输入相关的证据

以单意图请求识别为例，规约可以预先表达：

```
目标：根据完整候选定义识别用户请求的任务。
证据：音频及明确允许的上下文；不引入参考转写或未提供的上下文。
理解：区分用户要求执行的行为与仅被提及的实体、事件或行为。
关系：操作必须与其作用对象正确绑定，不能只按主题词匹配。
核对：结合候选定义、适用条件与排除条件作出完整候选判决。
输出：填写所配置的typed Span，最终给出intent。
```

如任务确实定义了否定/纠正的处理规则，可加入“被明确撤销的请求不作为有效请求”等
规范；数据是否支持这种现象的效果评测须单独确认。不能将一句规则的存在当作新增了
否定作用域标签，也不能把“最后提到的操作一定有效”当作通用优先级。

这套范式在未听音频时即可构造。涉及日历、音乐或设备由模型听取证据后处理，无需
预先选择主题问句。最终是模型学习如何使用规约，不是离线先判断答案再定制问题。

## Span与内部链路的边界

```
输入：音频 + 任务语义规约 + 配置的决策链路 + 全部Span定义
模型：理解证据并利用规约组织内部计算
输出：一次交付配置要求的中间typed state及Final
```

可以继续使用Q1/<SPAN1>/Q2/<SPAN2>/Final/<SPAN3>形式；Q描述规约中的判决变量，
不是引导模型撰写解释。也不要求规约中每条规则都对应一个监督分类头。
是否输出过程Span由任务配置决定；缺乏可靠过程标签时只训练有标注的读出，不把
未标注状态补成“通过”。若某节点只作为内部计算组织，需要通过结构和干预验证其作用。
当前实现仍是一次前向多位置读出，没有离散答案回填；不得假装在顺序执行已经预测的state。

## 对两阶段学习和奖励的影响

Stage1的目的细化为学习消费任务定义、语义规约、读出要求及候选绑定。需要检验同义
规约、候选重排/重绑定及留出表达，而不只背熟SLURP的固定标签名称。
现有全量日程是指令/本体属性的工程起点，未覆盖上述完整规约能力；新规约需要独立
版本的数据/输入验收，不原位替换运行快照，也不退回小样本主训练。

Stage2使用RL+衰减CE提升在规约下的任务表现。Final正确性是主要信用来源；过程
奖励仅来自可靠的节点标签或可核验关系。不得奖励看起来遵循范式的表面state，亦不
根据模型自述、Span数量或模板长度给奖励。只有Final标签时，可以先优化最终判决，
不以补齐虚构过程标签作为开训前提。

## 核心研究判据

1. 同义规约、符号重绑定及候选重排保持语义判决稳定。
2. 业务语义规则实质改变时，模型作出与新规则一致的判决。此类测试需重新核验目标，
   不能在改变规则后仍沿用旧gold。规则只在本体及证据足以支持重标注时变化。
3. 相同任务定义下，完整范式相对最小规约提高Final，且复杂样本有可测收益。
   两组保留相同候选知识和判决目标，控制额外文本与计算量，避免知识不等量对照。
4. 冻结SLURP训练模型后，用目标数据集自己的概念、候选及规约配置验证迁移；FSC
   不强套SLURP属性表，不根据FSC测试反馈优化模板。

因此工作主线表述为“语义规约消费能力、决策范式的效果、跨任务规约迁移”。历史
CoT/D/Q/P描述仅在与此契约一致时复用，不再把生成推理过程或主题问句包作为目标。
