# 一次填充的 Jev 决策 CoT 契约

> 原始文献核验后的澄清：一次对外调用/一次交付全部 Span 不自动等于一次固定深度前向。Intern-Decision 是一次前向多占位符实例；SanSi/LEV 是无 token 生成的内部循环实例。两者均须与外部 ReAct 区分。下文“一次前向”是首个候选实现，而非用户禁止隐式内部计算的约束；参见[案例核验](13-jev-multistep-evidence.md)。

用户最新纠正：不是 ReAct。输入给定一系列前置问题及最终问题，由 Jev 一次性填充对应 Span。本文取代 09/10/11 中以外部触发、复核、停止为核心的策略安排。尚未实现的设计不能描述为已有模型能力。

## 1. 输入和输出

输入为原始音频、允许的历史、全部问题及定义、各 Span 的输出类型、可配置思考要求。例如：

```text
Audio: <audio>
Thinking requirements: <本任务要求与关系约束>
Q1: <前置问题及定义>       <SPAN1>
Q2: <前置问题及定义>       <SPAN2>
Final Q: <最终问题及定义>  <SPAN3>
```

三个 Span 均为模型的待判决位置，不填入正确答案或离线质量状态。一次模型调用输出 `{span1: value1, span2: value2, span3: final_value}`；JSON 可由外围代码序列化 typed 读出，不要求模型自回归生成 JSON。业务消费最终 Span，其他 Span 可用于训练和诊断；需要时也可一并提供给业务。

实现目标是一次前向的多个判决位置读出，不调度 Q1→调用模型→Q2→再次调用模型，也不将问题交给外部控制器选择。不增加工具调用、复核动作、停止动作。语音始终直接进入同一个多模态模型，不使用转写后另调用文本模型的路线。

## 2. 显式结构 CoT 与隐式 CoT

结构 CoT：前置 Span 是有语义、可监督的中间决策，例如某项条件成立与否；最终 Span 是目标判决。通过模型内部注意力/隐藏状态联合计算，不将上一 Span 的离散预测重新塞回模型逐步解码。

隐式 CoT：前置问题仍可配置，内部推理位置的隐藏状态参与最终读出；中间语义监督可以只在训练时使用，也可以不设过程标签。隐藏状态如何连接、使用多少位置/层、是否共享判决头，需要单独实现和实验。仅把可见答案藏起来不能称为实现隐式 CoT。

重要实现边界：如果只在相互独立的隐藏向量上加三个分类头，这是多任务读出，不足以证明中间链帮助最终判决。候选设计是在同一前向内，让最终位置可关注前置问题与 Span 隐藏状态；因果 Transformer 可通过后续层传播前面位置的表示，不能声称最终头已读取同一层刚产生的离散前置答案。注意力可达性、梯度与实际干预效果均须验证。

当前 Qwen3-ASR 单问 JSON 生成式 SFT、vLLM 概率诊断保留为历史工程工作；它们没有实现多个 Span 的一次性 typed 读出。vLLM 生成接口不能自动当作新契约实现。后续需明确自定义多位置读出、采样/概率接口与 verl loss 的接入，不能靠隐藏自回归生成来宣称完成。

## 3. 数据必须承载真实依赖

每个样本保存 audio/source、所有 questions、Span 类型及候选、独立 targets 和质量 mask、最终任务定义、依赖依据。前置问题必须能由音频及合法上下文回答；目标不能泄漏进输入。只有可靠标签才能用于中间监督/奖励，缺标不自动作 false。

SLURP 的 date/time/timeofday 三个并列角色不天然构成 Q1→Q2→Final Q。现有三问只能作为联合读出控制，不能将其中一个换名为 Final 就宣称推理任务。可研究的派生示例是 Q1 判断日历日期、Q2 判断时钟/时长条件，Final 判断显式业务规则“二者是否都满足”。必须标为派生规则任务，并与“预测两项 + 确定性执行器”比较，不能以简单合取作为核心复杂推理证据。

主证据需继续从清理后的 SLURP、SFC、MAC-SLU/SpokenWOZ 的可核验关系选取：前置条件覆盖、绑定关系、最终监督和捷径控制同时成立才准入。SFC 的缺参状态可作候选；轮次捷径及缺少更正/取消监督的限制不变。不能因模型结构更新而放松标注审核。

## 4. 学习及比较

采用同音频、同最终问题与最终标签比较：

1. 只有 Final Q 的直接 typed 判决。
2. 完整 Q1/Q2/Final Q 模板，一次填充全部 Span，最终监督为主。
3. 同模板及一次读出，加经过审核的中间监督。
4. 隐式中间状态参与最终读出的候选结构，单独登记架构和监督差异。

2026-11-12 修订：固定已有 RL 初始化，比较直接问题 RL、结构问题 Final-only RL、结构问题加可靠过程信用；不新增 SFT 效果对照，也不以超过 SFT 为验收条件。奖励不包含复核/停止动作。联合 Span 的随机策略和 logprob 分解须按真实架构定义：独立分类头条件分布的乘积与有条件联合分布不是同一个策略，不能借用生成 token 概率冒充。GRPO 同组是相同音频、完整问题模板、思考配置的多份完整 Span 输出，不混入不同前置问题。具体 Loss/Reward 与 FSC 配置迁移见 [RL 协议](14-rl-decision-credit-and-transfer.md)。

主指标为 Final 正确率、完整 Span 包全对率，辅助为中间判决正确率、配置遵循、未见问题/规则族/任务的泛化与一次前向成本。区分只增加问题文本、只增加辅助监督、内部依赖结构、RL 四种贡献。测试前固定问题选择；测试错误不得反向挑选前置问题。

前置问题无关替换、顺序控制、内部连接屏蔽可检验中间计算的作用；保持业务规则时才要求 Final 不变。仅得到多任务收益或辅助监督收益，应按实证命名，不直接宣称 CoT 因果有效。

## 5. 执行修订

停止扩展外部多轮复核/停止策略方案。已启动的实时 HF 音频概率诊断保留到终态，用于确认旧工程链路的已知问题；不据此自动派发旧单问生成式 RL 或微批实验。下一项主要工程工作转为对照 NGA 的实际多 Span/typed 读出实现，落实本项目一次前向的任务契约、数据样本及训练/推理接口，再确定 verl/vLLM 的适配范围。
