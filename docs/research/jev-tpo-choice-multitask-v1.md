# 同一音频模型的 Noul、封闭 Choice 与开放列表 Choice

源任务为 clean SLURP 单录音原生意图。Stage1 起点、音频特征、LoRA、六卡优化器、6,248 条训练录音、全局 batch 384、microbatch 8 和 34 次更新与 v0.0.195 相同。按配置轮换整个 batch 的任务，保持每种请求内部 marker 数相同。不增加总曝光；不同任务会看到不同的训练曝光，不能声称每条录音都训练过三种接口。对照是 reward-only Noul；多任务候选同时改变输入和目标，只能归因于组合。

| 模式 | 实际供给的上下文 | 监督及训练人口（两轮曝光） |
|---|---|---|
| Noul | 原有完整成员判决模板 | 复用同输入 Stage1 Bernoulli 奖励投影，4,224 |
| 封闭 Choice | 完整原生意图集、新单选指令 | 对 gold 动作增加效用，3,944 |
| 开放 Choice | 5 个实际候选、一条覆盖判决；不显示其他候选名称 | 命中 2,980 条，训练覆盖与条件排名；缺席 1,348 条，只训练覆盖 |

脚本在贴标签前用源 Stage1 完整面板分数召回，有种子的候选丢弃和展示乱序；缺席不补入 gold。这里模拟两段业务路由，要求部署方提供候选；如果部署也用 Stage1 召回，必须计入第一次听音频的成本。既不估计业务漏召回率，也不证明发现了新意图。冻结难例视图的人口先前使用了 TRAIN 标签，**列表生成**不读每条的标签，不能引申为训练人口无选择偏差。

Choice 的原始 head logits 按当前候选集合归一化；封闭集动作目标为 softmax(z_ref/T + reward/β)。开放集的覆盖 marker 使用独立 Bernoulli TPO，以集合是否实际包含 gold 作为正负奖励依据。条件排名只在命中样本上产生梯度；两项分别投影。不把这一分解等同于单一联合动作空间的 KL 最优解。部署以 g·softmax(z/T) 与 1−g 拼成和为 1 的分布，其中 NONE 表示列表缺席，不能替代对模糊语音的拒判策略。

变更 prompt 后重新编译全部输入文本；使用原生输入逐条重构校验、相同音频特征，按真实新输入的张量身份在冻结 Stage1 做独立 reference 前向。统一驱动按 reference → 2 次有限更新 → 34 次正式更新顺序执行；正式训练只读冻结 reference。任一环节失败即停止。CPU 测试覆盖 NONE 分布归一化、漏召回条件排名梯度为零、命中奖励方向和子集构造。

复现入口：先用 `python -m tools.reports.build_tpo_choices configs/portable/operations/tpo-choice-v1.json <本地宏>` 构造训练视图，然后按统一的 `prepare_tpo_windows` 与 `native_seal_operations` 入口封包和派发。运行环境将 src 与仓库根加入 PYTHONPATH。宏只绑定本地路径、目标主机、镜像与产物。原轮的三套冻结评测为 Noul 接口。

效果评测预登记：沿用原有 Noul 评测人口与指标，另对同一测试音频、相同候选生成器，用旧端点与新端点分别执行实际 Choice 指令。封闭集报告 top-1 macro-F1、准确率和多类 NLL/Brier；开放集分开报告候选召回率、命中时条件选对率、缺席时误接率、整体含 NONE 的决策正确率及覆盖命题 Brier。显式记录是否使用候选丢弃，压力测试和无丢弃策略分开。参数不依测试结果调整；SLURP、FSC、MINDS 各报各的分母与表现。

## v0.0.197：统一 Choice 与候选长度验证

仍采用上述冻结 TRAIN 视图与预算。所有 Choice 都提供 NONE，Noul 的 4,224 次曝光保留。用微批轮转控制 K，使 1、2、4、8、16、32、60 均有曝光；候选身份、召回方式和展示顺序按种子及录音/轮次确定。共 5,558 条录音进入 Choice，8,272 次曝光中 5,443 次 gold 在集合、2,829 次缺席；1,120 条录音同时经历过两种监督。原 196 在带 NONE 的 5 项面板上该数为零。各长度的（命中，缺席）分别为 (348,836)、(582,602)、(727,457)、(804,380)、(857,327)、(949,227)、(1176,0)。数据清单按长度留存每类命中数、缺席数、候选出现数和正确位置。数据来自带难例富集的 TRAIN，不能替代业务流量。

冻结评测另在同一批录音上用 5、10、15、20 和完整数量的真实候选，各搭配一个 NONE；超出原生标签数时仅计算完整面板一次。报告每档命中时误拒、缺席时误接、条件排名正确率和覆盖 Brier，并区分候选召回来源。SLURP 的 60 项参加过训练，称完整面板验证；5、10、15、20 是训练宽度之间的未见长度。全量原生集一定包含正确意图，故误接率没有分母。

## 现行正式评测

v0.0.197 用动态候选训练，正式验收改用各数据集的完整测试人口及全部原生候选。将 v0.0.196 和 v0.0.197 的终点在相同输入下重评。每条音频分别执行 Noul 和完整候选加 NONE 的 Choice。Noul 的二元 NLL、Brier 与 Choice 的多类 NLL、Brier 各按自己的事件空间报告。Choice 以原生意图的 Top‑1 macro‑F1 为主，附准确率；选中 NONE 计错，并记录误拒率。完整集缺少正确标签缺席的样本，故不能估计缺席时的误接率。按长度的面板已退出 v0.0.197 正式队列。

SLURP 衡量源任务表现，FSC 和 MINDS 分别衡量在未参与训练的标签体系中的迁移效果，两者同属意图识别。真正的跨任务证据还需要不同判决目标和独立监督。各目标集沿用冻结策略，分别报告与 v0.0.196 的差值。
