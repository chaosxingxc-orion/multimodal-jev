## 来源关系得到确认

SLURP论文3.1明确：先以约200个预设任务提示收集文本，人工标注scenario、action、
entity，作为Liu等人2019年的文本NLU benchmark发布，再由参与者读出文本采集语音。
对应[NLU仓库](https://github.com/xliuhw/NLU-Evaluation-Data/tree/f6071b496b17d71e6eb43f543af0707f4ff30557)
README说明上传指南确实用于其标注，指南署名Xingkun Liu、Verena Rieser，日期
01/08/2017。它是上游标注依据，不是最终SLURP本体的完整定义手册。

指南提供的重要规则：按用户想达成的目标标意图；如果预设场景/意图与句意不符则修改；
标注帮助完成目标的关键信息；允许新增跨句/跨场景复用的实体类型；有些句子无实体。
它没有给出所有多请求的唯一主意图优先级，也没有为所有未标类型提供完备缺席语义。

原始elicitation question是采集来源，不能作为在线输入补足音频缺失的信息，不能用于
按gold主题选前置Q。这里只读指南示例，没有下载或分析其训练/测试样本CSV。

## 逐类来源映射

[映射配置](../../configs/tasks/slurp/upstream-definition-crosswalk-v1.json)覆盖当前全部
60意图、55类型，记录历史ID、指南段落及未决关系，没有改动现有候选定义或原生标签。

| 当前定义 | 来源关系 |
|---|---|
| 43个意图 | 历史指南有相同ID；同名不等于语义等价 |
| 12个意图 | 示例支持重命名候选，例如calendar_delete→calendar_remove；仍非认证映射 |
| 5个意图 | 未建立直接映射：cooking_query、general_quirky、iot_hue_lighton、qa_currency、qa_factoid |
| 48个槽位类型 | 历史实体表有相同ID；不证明最终存在政策相同 |
| 4个槽位类型 | artist_name/person/personal_info/place_name存在历史角色映射候选 |
| definition_word | 历史示例出现，但实体清单没有，保留原文内部不一致 |
| currency_name、meal_type | 未建立直接类型映射 |

历史表为63意图、101实体，不能作为当前60/55本体直接导入。SLURP论文表4的实体数
也不用于替换当前固定发布本体；历史统计口径与当前学习人口须分开。

## 对任务设计的具体影响

1. **已有边界的依据更强，但监督未自动成立。** 指南分别给出联系人添加/查询及交通
   查询/订票示例，支持这些任务的操作差异。它没有解决“查询后添加”“找便宜票”等
   所有边界，更没有证明当前104条定义不匹配是官方错误。
2. **当前S政策包含明确的新任务范围。** 上游要求提取服务用户目标的关键信息；当前
   候选S_present覆盖整句中的背景、转述和否定提及，范围更广。它不能称为对原生
   entity.type集合的无损重命名。保留这一研究任务时，必须单独标注其覆盖及缺席；
   不能为了沿用原生标签而把背景提及自动当负例，也不在此轮静默更改候选政策。
3. **MASSIVE不能补上英文审核缺口。** 固定revision README明确en-US没有localization
   judgments。其他语言的slots_score问的是“括号中的词是否匹配类别”，并不认证所有
   未标类型不存在。不能把这项分数套给SLURP英语负例。
4. **全量工作包的先后顺序明确。** 先利用来源映射修订定义和范围；新版定义会使旧
   definition_hash绑定的裁决失效，须明确复核，不能搬运旧标签。定稿后统一完成全量
   来源监督，而不是继续添加大量互相独立、缺共同标注政策的局部案例。

本轮推进的是任务依据与逐类来源映射。未运行模型、未重标数据、未准入新语义监督，
不认为任务冻结或学术基线复现已完成。
