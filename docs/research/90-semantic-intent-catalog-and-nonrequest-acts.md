# 统一语义意图目录及非请求行为政策

已形成[65张语义卡候选目录](../../configs/tasks/slurp/semantic-intent-catalog-candidate-v1.json)，
61张本轮撰写、4张联系人/交通卡按对象hash原样引用。全部60个原生类别都有离线审核
入口，但这些对应关系不是语义真值、不是运行时Q路由，也不要求一一映射。
原生Final仍保留60类；没有把训练任务缩成四张已审核案例卡。

目录是完整的任务清单候选，不是已认证本体或可训练发布。“覆盖60类审核入口”不能
等同“覆盖所有真实表达”：general_quirky仍可能有目录未表示的行为，必须独立记录，
不能将它们强行塞入兜底卡或从原生类补出全负例。

## 从原生标签到可判定语义

| 原生标签或难点 | 目录中的处理 |
|---|---|
| cooking_query / cooking_recipe | 共享食物制作指导语义；不合并原生Final标签 |
| general_quirky | 不设同名兜底谓词；助手人格信息只是其中一个审核方向，每条来源仍按全部定义判断 |
| audio_volume_other | 拆为音量信息、音量调整、打开控制界面；不以“不是其他三类”定义 |
| datetime_convert | 分开时区换算信息和时区设置操作 |
| iot_cleaning | 分开清洁设备操作与设备信息/使用咨询 |
| music_likeness / dislikeness | 分开正负评价、评价记录、音乐内容保存；导航/播放另有定义 |
| qa_factoid | 定义事实属性信息，不再定义为其他领域的补集；允许与明确领域查询重叠 |

每张新增卡写明定义、包含/排除、行为政策及共存规则。排除作用于不匹配的行为，不
否决同句其他行为；不以首句、末句或native类别建立主意图优先级。请求类共用已发布
request-policy-v1；问候与偏好使用本轮[非请求政策](../../configs/tasks/intent-nonrequest-semantics-candidate-v1.json)。

## 非请求规则的证据与决定

完整读取原生general_greet 18来源、music_likeness 96来源、music_dislikeness 11来源，
合计125来源、596录音。原始metadata身份、source target与录音关联已重建。
[证据登记](../../configs/reviews/slurp-nonrequest-catalog-evidence-v1.json)保留完整来源清单
及15项规则观察；它们没有生成逐条语义训练标签，不代表听审或独立语义复核。

- 问候是当前对助手实施的社交行为。裸助手名/注意提示不自动算问候，`who are you`
  可是身份请求。常规`how are you`可作为寒暄，若实质性人格询问与寒暄无法区分则保留歧义。
- 喜欢/不喜欢需要明确评价极性及音乐领域证据。`I like it`、`I don't like it`不能
  凭所在数据集推断it是一首歌。领域已明确但具体歌名缺失，不一定妨碍偏好判断。
- 保存歌到普通播放列表不等于喜欢；保存一个未给出的意见不等于正面评价。
  明确favorite/thumbs-up提供正面证据。请求记录评价与表达评价分别判断。
- 数字评分缺少量表或附带评价时不自动推正负，包括three stars和five stars。
  记录评分的请求仍可被识别。`good but too slow`可能同时含正反评价，不强制单极性。
- `skip this song`表达播放导航，不必然是不喜欢。消息正文或转述的意见也不能自动
  当作当前说话者的立场；这些限制不改变槽位对正文内容的单独范围政策。

这些规则直接避免用原生music_likeness标签给“保存歌曲”“记录意见”统一发正面偏好reward。
它们是新的可迁移语义契约；历史类别正确性仍按原生标签独立评分。

## 尚需集中审阅的跨卡问题

目录允许重叠，但不能用允许重叠掩盖定义矛盾。下一步审核固定在以下范围，不先增卡：

| 边界组 | 需要明确/验证的内容 |
|---|---|
| 广义信息与领域信息 | factual_property_information与天气/人物/市场等的包含关系；重复监督程度与过程reward预算 |
| 操作方向与绝对值 | 未知当前状态下绝对音量/亮度不能凭空产生up/down；调整与方向卡的共存 |
| 通用集合与专用集合 | 一般list、联系人、音乐收藏、日历的操作边界，防止用槽位list_name范围直接推意图 |
| 请求、问候、偏好 | 间接请求、寒暄/实质问题、裸片段、评分量表缺失、报告或正文作用域 |
| 媒体/设备领域 | 名称或品牌的外部知识不能默默补类型；表达的操作与只是内容提及分开 |

相关边界先用学习来源核查；不以selection/test反馈修改定义。固定I族总奖励并不使
高频宽泛谓词的梯度影响自然均衡，需在准入监督上报告正负覆盖与重复标签关系。
不得把目录层级闭包自动当正例，更不能用I/S共现硬过滤Final。

## 与工程和训练的连接

主任务仍是直接音频、同模型一次Span读出。目录中的related_native_classes、审核
来源、计数与证据hash只用于离线管理，不进入actor。显示符号绑定与定义内容分别管理。

65是当前候选语义卡数，不能立即改旧Stage1分母60为65或宣布旧15面板可用；还需完成
边界审核、准入监督、固定面板与完整输入资源验收，再统一发布目标和配置。
原有四卡参考建议保持原身份，不因目录包含它们就自动进入正式监督。

[结构核验](semantic-intent-catalog-check-v1.json)确认65个唯一ID、完整卡字段、四卡
原样引用、60类审核入口、政策与证据hash及非请求队列原始绑定。JSON与文档引用检查
通过；这不能替代语义正确性、音频一致性、处理器长度或NPU训练验收。本轮未改训练
实现、未启动模型任务，语义监督准入仍为0。
