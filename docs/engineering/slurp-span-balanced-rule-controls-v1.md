# 互补规则的均衡 Span 开发批次

发布路径：`/mnt/cephfs/xingchao/datasets/slurp-jev-balanced-rule-controls-v1`。
原 `slurp-jev-rule-controls-v1` 保持不变。新版本包含 2,520 行候选输入，
在固定 seed=17 下形成 99 个 matched batch，每种输入 arm 各 792 个请求。
48 条真实音频没有增加，三个 arm 共 2,376 个调试请求不算独立音频。

## 如何同时保持类别均衡和真值覆盖

每个 batch 固定两个事实定义和一组互补规则 R / NOT R：

1. 从四种真实事实组合 00、01、10、11 中各抽取一个不同来源组。
2. 每条音频各提出 R 与 NOT R，形成八个请求；前置事实标签不变，Final 翻转。
3. Final-only、structured、reordered 三个 arm 使用相同的录音、规则及顺序。

于是三 Span arm 中的 Q1、Q2、Final 每个都正负各四条；Final-only 也各四条。
每条规则独立看仍保留四种事实组合，不以补造标签填齐八种三位签名。
每个基础规则按四个事实层的最小支持量下采样，24 个录音×规则实例未进
本轮 schedule；原始数据与评测分布不修改。每个 request 在本 schedule 的
同一 arm 内出现一次；同一录音会在不同规则和极性下复用，不能声称无来源复用。

## 模型输入及局限

补规则明确要求判断原规则是否为 FALSE；问题中完整保留原规则的定义。
补规则和原规则的答案不是靠不可见 ID 区分。gold、rule_id、来源、审核信息
都留在旁路监督，模型只读音频、问题、候选及思考要求。

均衡发生在 R/NOT R 混合 batch 内，**不代表每条规则单独正负均衡**。
AND/OR 及其否定仍可能被不听音频的规则先验猜中 75%；因此不能仅依靠
总体 50% 的多数类基线，必须看每条规则 balanced accuracy 和真值表分层。
显式否定模板也可能成为措辞捷径，必须对定义改写和互补响应单独诊断。
同一个基础规则及其互补、同来源的所有 arm 必须共同分组，不能跨训练/测试。

本轮只是 learning-only 的采样与推理开发发布，没有批准独立评测或自动接入
RL。原有三任务训练入口仍只接受已验收的固定 temporal 数据协议；新输入
需建立 HF/vLLM 概率验收，奖励、优化器及 SFT/RL 对照预算也要分别冻结。

## 验证及首个实际模型探针

采样测试覆盖每 batch 的三 Span 精确均衡、每条规则四种真值组合、三 arm
配对、重复请求/缺少规则极性/错标拒绝；指标测试覆盖常量预测、规则执行器
只使用预测事实、缺少输出和重复输出拒绝。相关采样/数据/指标测试共 15 项。
发布时独立遍历全部 batch 重算标签计数及覆盖；凭证见同名 verified JSON。

推理探针预先选定 schedule 中每个基础规则的第一个 batch，共九组、
216 个请求、27 条音频，包含三种 arm 和两种规则极性；不按模型表现选样。
该探针不改变 schedule，也不能用 27 条 learning 音频宣称泛化能力。
冻结基座、已有 SFT、已有 RL adapter 采用相同输入集分别登记。
