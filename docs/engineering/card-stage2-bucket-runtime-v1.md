# Stage2 全标签 TPO 的分桶训练候选

JEV-210 的 Stage1 用知识卡与语音配对，一条锚点展开 8 对；Stage2 对一条录音保留所有 68 个候选概率，每个候选仍然单独输入一张知识卡。以 181 上审核过的 Stage1 声学索引和本次 TRAIN 打分的 rules 卡片计算，109,610 条录音的最长单卡请求为 P50 108、P95 137、P99 159、最大 382 tokens。四个桶各有 83,163、20,635、5,126、686 条录音。这是全 TRAIN 的分布，Stage2 难例和回放子集的分布以正式视图为准。

| 每条录音最长请求的 token 数 | 每 rank 每次更新最多录音数 | 每 rank 每次前向最多录音数 |
| --- | ---: | ---: |
| ≤116 | 32 | 4 |
| 117–136 | 24 | 3 |
| 137–165 | 16 | 2 |
| >165 | 8 | 1 |

这些宽度是容量探测起点。短桶单次最多会展开 272 对，不能直接按 Stage1 的 32 条录音套用。分界线、两种宽度和排序窗口由 [候选配置](../../configs/portable/operations/card-tpo-package-endpoint-buckets-v1.json) 注入；推理卡也由本地宏注入。

- **目标固定。** 原批次用于构造 batch 内的双向 TPO 投影，目标仍按 (epoch, recording) 索引。新的优化器计划只重排这些索引，每个非空桶批次更新一次，零权重尾部补齐只保证各 rank 数量相同。新的全局 batch 随桶变化，梯度按真实录音数归一化。学习率与优化器沿用父配置；步数、更新顺序与旧固定 batch 不等价，效果由独立评测确认。
- **计算与准备并行。** 复用 Stage1 的只读 mmap 声学特征，核验索引哈希和实际使用的字节。CPU 有界预取同时完成卡片展开和 collation。每个 microbatch 右侧 pad 到本批最长请求，传入 attention mask 及有效位置；同一录音的 68 个候选共享一次冻结声学塔与 projector 计算，全部候选仍独立经过语言骨干和决策头。
- **验收与评测。** 计划哈希绑定有限验收、正式训练和断点。有限训练选高负载和最长序列的两个真实批次，训练前先和冻结的 Stage1 概率比较，更新后再用当前权重的原生路径比较，沿用既有概率误差和无阈值翻转要求。正式评测从同一计划读取实际更新数。每桶记录真实录音数、训练墙钟、输入等待、峰值显存及录音和卡片对的训练吞吐；训练吞吐不把输入准备和有限对齐计入分母。

候选接在原有统一入口的 Stage2 封包步骤。新派发应使用独立的运行目录及状态，并绑定本地宏 `CARD_STAGE2_INFERENCE_DEVICES`、`CARD_TPO_ACOUSTIC_MOUNT`（181 上声学分片目录）、`CARD_TPO_ACOUSTIC_INDEX`（封包机可读的同一索引；只需索引，不搬特征分片）。路径由执行环境配置，索引由 Stage1 终点审核收据的训练配置固定。候选封包根据审核收据解析实际 Stage1 checkpoint 路径。

CPU 测试覆盖固定目标复用、所有录音暴露、尾批、padding/mask、梯度，以及打包和评测步数接口；NPU 容量、实际吞吐和生产数值对齐仍需通过现有有限验收。
