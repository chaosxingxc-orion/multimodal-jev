# TPO 评测按样本块调度

在 JEV-205 和 JEV-206 的八卡留出评测中，最后一片都在约 32 分钟退出。SIB-FLEURS 和
MMSU 的卡在约一分钟内结束，此后无法接手 SLURP 或 MINDS。解决办法是让同一主机上的单卡
进程共享一份样本块清单。

- CPU 在申请卡之前绑定源策略、检查点和已审核的音频张量索引，从无标签的封存人口生成
  确定的清单。块只含一个数据集、一个检查点和若干完整的原批次。用编码后的 token 数、音频
  帧数及推理 pass 数估算权重。先按检查点，再把预计较重的块放前面。
- 每张卡只启动一个进程并加载一次主模型。进程领取尚未占用的块，完成后继续领；无需等待
  同一数据集的其它块或同一检查点的长尾。进程保留已打开的数据集索引，按配置预取音频张量。
  池的设备、本地目录及镜像由现有封包和本地宏绑定。
- 同一套批次边界由 `logical_partitions` 保留，它和卡数无关。逐类概率及全候选 Choice
  可共用队列；依赖分片序号生成候选的变长 Choice 保持原路径。源 TRAIN 校准仍独立执行，
  阈值使用原冻结口径。本次不改数据、候选、检查点、gold 或评分器。
- 完整块以一个文件原子提交，写在运行主机的本地盘。失败后在新的部署句柄配置
  `sample_blocks.resume_from` 指向已结束运行的 `sample-blocks` 目录，使用原代码、
  评测配置、镜像和数据身份；重建同一计划，审核并复用完整块，只补缺失。残留临时文件不视为
  完成，已提交文件损坏时停止并保留证据。更换检查点或块计划不能续用旧块。
- 全部准确容器退出后交还卡。CPU 收集逐块校验检查点、行序、候选宽度和摘要，再按数据集及
  检查点检查全量分母、重复和缺失并独立评分。`block-plan-collected.json`、每卡的
  `block-worker-*-collected.json` 和 `score-collected.json` 分别提供计划、实际工作分配和评分。

[JEV-204 统一入口](../../experiments/pipelines/JEV-204.json)先对五个 JEV-205 面板做有限
NPU 回放：取相同的冻结批次与尾批，逐样本、逐候选概率与已审核的旧预测精确对比。通过后进行
JEV-204 已登记的全量评测。全量资源计划：181，八个单卡进程，CPU 准备及评分不占卡；当前
训练审核为前置。验收沿用实验 ID，原有评测包不改写。

效果以同数据、同检查点、同输出范围比较从准备到评分审核的总耗时；报告留出推理关键路径、
每卡领取数和末端空档。历史推理卡分钟均摊只是排程估算，不是加速实测。
