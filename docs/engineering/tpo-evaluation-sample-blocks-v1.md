# TPO 评测按样本块调度

在 JEV-205 和 JEV-206 的八卡留出评测中，最后一片都在约 32 分钟退出。SIB-FLEURS 和
MMSU 的卡在约一分钟内结束，此后无法接手 SLURP 或 MINDS。解决办法是让同一主机上的单卡
进程共享一份样本块清单。

- CPU 在申请卡之前绑定源策略、检查点和已审核的音频张量索引，从无标签的封存人口生成
  确定的清单。块只含一个数据集、一个检查点和若干完整的原批次。用编码后的 token 数、音频
  帧数及推理 pass 数估算权重。先按检查点，再把预计较重的块放前面。
- 每张卡只启动一个进程并加载一次主模型。进程领取尚未占用的块，完成后继续领；无需等待
  同一数据集的其它块或同一检查点的长尾。进程保留已打开的数据集索引，按配置预取音频张量。
  池的设备、本地目录及镜像由现有封包和本地宏绑定。
- 同一套批次边界由 `logical_partitions` 保留，它和卡数无关。逐类概率及全候选 Choice
  可共用队列；依赖分片序号生成候选的变长 Choice 保持原路径。源 TRAIN 校准仍独立执行，
  阈值使用原冻结口径。本次不改数据、候选、检查点、gold 或评分器。
- 完整块以一个文件原子提交，写在运行主机的本地盘。失败后在新的部署句柄配置
  `sample_blocks.resume_from` 指向已结束运行的 `sample-blocks` 目录，使用原代码、
  评测配置、镜像和数据身份；重建同一计划，审核并复用完整块，只补缺失。残留临时文件不视为
  完成，已提交文件损坏时停止并保留证据。更换检查点或块计划不能续用旧块。
- 全部准确容器退出后交还卡。CPU 收集逐块校验检查点、行序、候选宽度和摘要，再按数据集及
  检查点检查全量分母、重复和缺失并独立评分。`block-plan-collected.json`、每卡的
  `block-worker-*-collected.json` 和 `score-collected.json` 分别提供计划、实际工作分配和评分。

[JEV-204 统一入口](../../experiments/pipelines/JEV-204.json)先对五个 JEV-205 面板做有限
NPU 回放：取相同的冻结批次与尾批，逐样本、逐候选概率与已审核的旧预测精确对比。通过后进行
JEV-204 已登记的全量评测。全量资源计划：181，八个单卡进程，CPU 准备及评分不占卡；当前
训练审核为前置。验收沿用实验 ID，原有评测包不改写。

效果以同数据、同检查点、同输出范围比较从准备到评分审核的总耗时；报告留出推理关键路径、
每卡领取数和末端空档。历史推理卡分钟均摊只是排程估算，不是加速实测。

单知识卡评测的并发候选由 `sample_blocks.replicas_per_device` 指定每张物理卡的 worker
数。容器仍只租一张卡；多个独立进程共享同一块队列，各自绑定模型、策略和本地缓存。
进程数不改变块内输入形状。评测专用的 `eval_single_validation` 可在判决 head 内对完整批
做一次检查，保留逐行计算及逐值准入。有限 HF 检查仍每卡一个进程。既有运行包默认值保持为
单进程和原 head 路径，候选在独立包评估。

筛查入口是 `tools.reports.screen_card_evaluation_replicas`，使用
[`card-evaluation-concurrency-screen.json`](../../configs/portable/operations/card-evaluation-concurrency-screen.json)
固定对照、物理卡和样本范围。它按冻结的块工作量均匀选择已登记块，两个检查点、所有面板均
参与；逐项对比封存概率。设备采样取同一主机的时间戳，AI Core 和 HBM 按真实评分区间报告，
吞吐以同一面板的完整候选数除以经过的时间，另外给出包含容器启动与容器内校验的耗时。
切换对照使用固定的 3,000 条音频，按数据集、候选数和批次工作量选取完整块。同一批音频分成
互不重叠的面板，旧版与新版各用四卡，每张旧卡与一张新卡处理同一个面板。对照门槛为逐候选
概率零差异、AI Core 和 HBM 平均均至少 70%、评分吞吐和计入容器启动的吞吐均超过两倍。
固定样本对照结束后直接进入正式评测，旧版无需全量复跑。

只报告原始概率、Top-1 与 F1 的配对评测可设置 `fit_harness_thresholds: false`。这会省去
TRAIN 阈值诊断，概率映射的既有参数及主指标定义均不受影响。已有同一策略的预测可以独立复用。

同一 Stage1 唯一检查点进入新的配对评测时，可以给封包器提供
`reuse_stage1_evaluation`，引用通过审核的旧任务终态、指标收据、TRAIN 阈值文件、已冻结的
部署和远端块计划。封包器核对镜像、父策略、输入端口、打分几何和 TRAIN roster。新队列逐块
验证并导入原 Stage1 概率，留出集仅推理新 Stage2 端点。启用 Harness 阈值诊断时才对新
Stage2 拟合源 TRAIN 阈值。210 正式模板显式关闭该诊断，沿用已冻结的概率映射。
待复用端点、输入或拆块发生变化时拒绝复用；复用节省的工作量和单次推理的吞吐提升分别统计。

JEV-210-CAL 通过根目录 `run_experiment.py` 启动新版正式评测，复用已审核的 Stage1
预测，并用八卡对 Stage2 的完整留出人口评分。正式评分审核全量块的身份及覆盖；逐项比对使用
旧版已提交的固定 CAL 样本块。报告分别记录固定对照的吞吐倍数，以及新版全量的八卡利用率、
实际吞吐和总墙钟。全量设备平均包括先完成的卡在尾段的空档，不从固定样本倍率推算旧版全量
耗时。研究指标仍按完整评测人口统计。
