# 实际训练日程的类别权重审计

2026-11-12 UTC。原监督权重为`w_i=N/(C*n_class)`，N=89、C=56；全人口
加权平均确实让56个有来源支持的类各占1/56。但每次optimizer更新使用
`sum(w_i*L_i)/sum_batch(w_i)`，固定12步日程有尾部循环，不能据全人口权重
直接声称每批或累计训练严格类别均衡。另4个候选类没有学习来源，未补造监督。

本次重新认证原监督发布与实际actor日程，计算
`c_k=(1/T)*sum_t sum_{i in batch_t,class=k}(w_i)/sum_{i in batch_t}(w_i)`。
这是把各步目标在同一个假设策略处等权平均的系数；真实参数逐步变化，
它不是梯度贡献、Adam位移，也不能作为学习退化的因果归因。

| 固定96次来源使用、89个来源 | batch8 ×12步 | batch32 ×3步 |
|---|---:|---:|
| 最小类别系数 | 0.01388889 | 0.01626016 |
| 最大类别系数 | 0.03333333 | 0.03292683 |
| 最大/最小 | 2.4 | 2.025 |
| 相对56类均匀分布的TV | 0.07116402 | 0.06602787 |

均匀目标为每类0.01785714。82条来源使用1次、7条使用2次；12个batch8
各覆盖7或8类。将所有使用次数的原始权重合并后统一归一化，TV仍为0.06641086，
说明重复来源本身也改变了有限预算的类别系数；该值不是待实施的新Loss。
batch32使用既定控制的相同来源顺序，逐条核对登记的96次使用完全相同。
这里只计算配置的反事实系数，没有运行batch32训练。

由此修正实验解释：

- 现有D/Q/P的源日程和权重相同，该不均衡不会破坏三臂之间来源系数匹配。
- “逆频率权重”不等于“均衡batch”，不能声称当前满足每类等量抽样。
- batch32同时改变更新次数、累积噪声和按批归一化后的类别系数，结果不能
  全归因于方差变化。参数位移与Adam也不由上述系数确定。
- 后续新版本若要求严格的宏类别目标，可预先采用类别均匀抽样配等来源权重，
  或均匀来源抽样配固定总体归一化的权重估计；二者不能叠加重复补偿。
  有限日程仍须实算来源/类别使用量，不承诺每批含全部56类。

不在已冻结曲线中更换采样、分母或尾部规则。仍以完整分类曲线检验收益。
当前修复的是研究口径，不宣称新的算法已经提高准确率。
