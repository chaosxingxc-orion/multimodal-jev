# 常驻训练的跨rank验收证据一致性

2026-11-12 UTC。`SpanTrainingSession.accept`此前只要求各rank处于相同策略和步数，并分别返回passed。不同rank可能读取不同验收文件，但仍同时前进。现在对完整JSON验收回执做canonical SHA256，将摘要加入集体状态一致性检查；不同证据、非有限值、不可序列化字段或Boolean冒充整数步数均拒绝，保持原actor策略身份并将会话置为failed。

本地会话测试11项通过。固定镜像`sha256:52ba94e1b6ba35f09066a92222f013ce9563fdbd83a6a5e7a60d209ac29f756c`下，CPU容器`0c6184fbb423d717eb3591541c0aafb365c69581b174a46664ed252cd112f67a`实际退出0。真实四个Gloo rank各运行原生verl actor的8步合成更新，常驻路径与第4步保存恢复路径逐项一致，与独立加权参考最大误差2.98e-8。新增反例让每个rank提供相同policy/step、不同gate_hash，四rank均拒绝，未更新已接受策略身份。

完整证据见`span-finite-session-dp4-cpu-v2-verified.json`。这是FP32合成CPU证据，不是实际音频、BF16、FSDP/NPU或vLLM常驻热更新验证。已有排队快照不受工作树更新影响。

真实常驻路径的下一项工程约束是验收资源交接。当前生产验收入口要求训练容器已退出，资源观察器也会拒绝活跃训练占卡。常驻四rank不能直接复用这一条件，也不能通过禁用资源检查绕开。需要单独实现并验证：所有rank进入无更新的publication边界；以明确的父子设备所有权启动验收；为HF/vLLM提供已释放的设备内存或经实测可容纳的共存预算；验收时冻结FP32 master/Adam与导出身份；验收后认证完整概率及实际子进程退出，再恢复同一个actor/optimizer。任何卸载/恢复操作都要检查参数对象、优化器引用及FSDP分片身份，不能调用普通model.to后假定一致。

在这些条件实现前，现有逐步容器链继续作为真实训练证据，不能称为常驻trainer或完整Ray trainer。新的证据摘要检查是必要前提，不替代上述资源与后端工作。
