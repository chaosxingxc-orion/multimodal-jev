## 干预与直接证据

保留完整输入维度投影的输入/输出 all-gather；为每个语言层的 Q/K/V、
gate/up、o/down 的本地输出权重分片补零，暂时恢复原完整输出宽度，
以 BF16 F.linear 计算后提取本 rank 的行区间。LoRA 使用原生调用与原始输入，
未合并 adapter；LM head 未改变。诊断接口拒绝非 TP4、复制 KV shard、bias
或未安装完整输入维度投影的模型。

每 rank 的 56 个 QKV/MLP 计数均为 53；另 56 个 o/down 模块均为 53
（五次重复请求加完整 48 条）。固定首条请求在同一引擎的五次控制调用和
第六次 suite 调用 logits 逐位一致，包括 trace 开启的调用。
该重复性不能外推到其他请求或跨引擎稳定性。

首条录音的真实 trace 与独立 HF trace 的输入及文件哈希已核验：

本轮消除了该首条输入中最早的 Q/K/V 投影差异，但其后 attention 输出仍
出现差异并经后续层放大。当前 trace 只能把最早观察差异缩小到 QKV 输出
至 o_proj 输入之间，尚不能断言具体是 RoPE、attention 计算或哪个 kernel。
也不能据单个输入证明其他层 QKV 全部精确。

## 成本与后续优先级

每个 o/down 模块仍常驻四分之一权重，合计每 rank 70 MiB；单次补零权重
最大 6 MiB，聚合输入最大 4,165,632 字节、输出最大 1,388,544 字节。
这是张量大小，不是峰值 HBM 或通信流量测量。全宽计算增加工作量，不能
将该诊断方法当作有吞吐收益的生产 TP4 实现。

相关 CPU 测试（形状、原生 LoRA 路径、拓扑拒绝、连续训练控制）33 项通过。
