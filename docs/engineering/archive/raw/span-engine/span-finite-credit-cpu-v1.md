# 多分类有限支持信用分配：真实 verl CPU 验证

2026-11-12 UTC。新增 `span_finite_credit.py`，在不修改既有固定训练源码的前提下，把加性正确性奖励的精确条件信用扩展到任意有限候选数与混合 Span。

每个有效判决的优势为 `w_j * (1[a=gold_j] - p_old_j(gold_j))`，不进行组内方差标准化。缺失标签仅使用 mask，不填 false；缺少任何有效奖励项的请求从损失分母中排除。外部 request weight 控制跨样本加权平均，保留类别平衡作用。调用方固定各 Span 的 reward 权重；本模块不自动把并列任务中的最后一项命名为 Final。

ragged 候选按完整旧策略概率积分。为适配 verl token-mean，积分权重乘以展平候选总数并除以有效请求权重和，避免60类与2类候选、附加无监督 Span 或全缺标请求改变有效任务的相对权重。该权重是有限支持积分，不能修补 actor/rollout 后端漂移。所有身份与全候选概率 gate 仍由训练调用方负责。

固定镜像 CPU 容器退出0；12项测试通过，包括60类/2类/5类混合候选的精确期望奖励梯度、3×2联合枚举的条件信用、无监督位置零梯度、添加无效问题不稀释 Final、类别权重不被中心化抵消、60类零信号采样风险，以及非法监督/概率拒绝。另有15组真实 verl 对照：候选宽度 `[60]`、`[60,2,5]`、六个 Boolean，各使用0、0.1、1、8、30的 logit 偏移，覆盖裁剪和 log-ratio clamp；损失均一致，最大梯度误差0。

证据见 `span-finite-credit-cpu-v1-verified.json`、启动见 `span-finite-credit-cpu-v1-launch.json`。结果只证明合成 FP32 CPU 的数学与真实 verl 损失兼容，不是音频/NPU更新或任务收益。现有原生 typed actor 仍消费采样联合动作 GRPO，本模块尚未接入该 actor；必须另建有限候选动作传输与原生更新验证，不能直接替换 loss 后宣称实现完整训练。

分布式/微批集成必须保持全局有效请求权重分母；逐微批各自归一化再等权平均会在类别权重或有效样本数不同的时候改变目标。本次函数只处理完整本地目标，未验证该目标的分布式调度。耦合关系奖励和集合F1也不在本次加性信用范围内。
