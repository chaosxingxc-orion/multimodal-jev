# TP4 首条真实语音逐层诊断

同一 Qwen3-ASR-0.6B / BF16 adapter，固定48条输入，先独立HF，再四卡TP4。
仅第一条录音 `slurp:audio--1504190766-headset.flac` 记录中间状态；
记录只用于离线比较，不回填模型。两容器退出0，完整48条均完成。

## 输出稳定性限制

HF 的48条输出与历史独立参考完全一致。TP4 的48条输出均与上一轮HF-order TP4不同，
两轮最大候选logp差为0.3609292507。本轮对HF的概率gate为0/48通过，
最大logp误差0.3686215878，联合动作概率比[0.5476730639,1.3702362759]，
4个Span首选候选变化。仍不准入训练。

因此本轮**未通过TP4记录无扰动检查**。首次严格比较程序检测到差异并拒绝继续；
随后改为显式记录稳定性失败，再输出带限制的层诊断。
没有把记录钩子无扰动当作已验证结论，也未更改训练概率阈值。
暂不能区分跨运行归约/执行差异与trace同步及内存布局变化的影响。

## 实现与验证

- SpanTrace新增投影输入/输出钩子，保存所有token，未用最终分类结果推测中间一致性。
- 分布式trace强制rank专属文件名，独占创建；旧单文件RPC在TP>1时拒绝运行。
- 离线比较器校验启动/源快照/模型输入pins、request身份、四rank覆盖与文件哈希。
- 完整48条输出稳定性显式记录；HF稳定为true、TP4稳定为false。
- 相关CPU测试18项通过，包括分片重建、rank路径隔离、非rank0复制状态差异检测。

证据：`span-tp4-layer-trace-v1-hf-launch.json`、`span-tp4-layer-trace-v1-launch.json`、
`span-tp4-layer-trace-v1-verified.json`。verified表示诊断证据已复算，不表示概率准入通过。

下一步先在同一引擎内做无trace→有trace→无trace重复请求，且禁用音频特征缓存，
再与独立无trace运行比较，确认记录扰动与重复性。之后对最早偏差投影做受控干预，
保持BF16矩阵执行和原生LoRA，不以FP32主执行或放宽阈值换取准入。
已验收的四卡训练接TP1推理保留；学术基线、RL收益和泛化目标仍未完成。
