# 规则输入 HF/vLLM 验收

原 v1 容器退出 1：父进程在 `__main__` 分支内导入注册 Span 模型的模块，
spawn 创建的 engine 子进程没有执行该导入，模型 registry 因而拒绝
`Qwen3ASRForSpanDecisions`。将 runtime suite 导入移至入口模块顶层，使
spawn 重执行时也注册架构。保留原运行及失败记录，新目录 v2 重跑。

v2 正常退出并通过独立验收：216/216 请求，最大候选 logp 误差
`1.1920928955078125e-7`，联合动作概率比范围
`[0.9999998807907176, 1.0000001788139503]`，首选答案变化 0。
输入来自九类规则各首个均衡 batch、三种问题 arm，共 27 条 learning 录音。

相同 Qwen3-ASR-0.6B、SFT BF16 未合并 adapter，物理 NPU5、TP1、原生 LoRA，
完整 token/音频特征/位置/候选/策略身份与原独立 HF 输出逐条核对。
仍采用 0.02 候选 logp 误差、[0.98,1.02] 完整动作概率比阈值，未放宽。

这只验证一个不可变策略和 216 个输入；不自动准入整个 99-batch schedule，
也不准入新训练版本。后续小规模训练必须以独立协议限定这些已验收输入，
新版本重新完成独立 HF 重载及 HF/vLLM 验收后才允许消费。
