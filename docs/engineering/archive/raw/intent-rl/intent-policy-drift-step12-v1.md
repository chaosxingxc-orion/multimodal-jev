# 前两步RL的更新后策略偏移

2026-11-12 UTC。工具`diagnose_intent_policy_drift.py`读取实际退出0并通过全候选验收的step0/1/2策略，按同一89来源名单及各步真实8来源batch计算。没有改变Loss、学习率、概率或已冻结训练协议。六项数学测试通过，覆盖同策略零偏移、正确性surrogate的精确期望、裁剪方向及非法候选。

第2步的D训练batch平均KL为0.05509，旧概率质量越界68.56%；其余81学习来源也有KL0.04556及67.60%越界。相同adapter在Q模板上的全89来源Final KL为0.01059、越界16.60%。这些是每条请求全候选概率的精确求和，先在请求内求概率质量再平均，不是把候选个数当概率质量，也不是实际训练日志中的clipfrac。

第2步四rank日志中的`actor/pg_clipfrac`全部为0，`actor/ppo_kl`接近0，梯度范数1.80557（配置grad clip=1）。这与上表并不冲突：当前只做一次optimizer更新，算梯度时新旧策略相同；裁剪项约束损失表达式，不给更新后的参数提供硬信赖域保证。梯度范数裁剪也不保证策略KL或每候选ratio有界。训练时pg_loss近0与reward梯度存在同样可以同时成立。

纯正确性优势的未裁剪surrogate在没有数值ratio截断影响时等于`p_new(y)-p_old(y)`。本报告另外复算clip=0.2、dual clip=3、log-ratio数值clamp[-20,20]，与现有reference一致。诊断先去除FP32 log-softmax总质量舍入残差，训练概率未改。真实日志仍保留原始值。

后续稳定性实验的优先级：

1. 保留D12原协议完整结果，再从同一起点另开固定较小学习率对照，先改变一个因素，匹配来源、权重与更新数。不据FSC TEST选择学习率。
2. 若引入相邻行为策略KL约束，单次同策略点的KL梯度本身为0，简单加beta不能约束第一步。真正控制更新需要更新后检查、具备精确master/Adam恢复的拒绝/回退机制，或多次优化中的KL控制。每次试探都应恢复同一optimizer状态，避免失败尝试暗中累积Adam步数；这些机制尚未实现，不描述成当前能力。
3. 固定起点参考KL在后续步可产生约束，但也可能锁住低质量初始策略；需独立记录参考身份、系数及Final损益。它与行为KL监测不可混用。
4. 奖励信用集中与更新步幅分别消融。直接除以正确类概率会改变效用、放大噪声，不应和学习率/过程奖励同时修改后归因给单一因素。

现有证据证明更新造成明显策略偏移，尚不能将其单独认定为全部退化的因果原因。独立开发名单仍未完成音频语义准入；上述都是学习集诊断，不能代替泛化评测。D12的第三步由原控制器定时接续，不手工重复派发。
