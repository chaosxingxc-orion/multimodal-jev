# 真实音频共享LoRA梯度诊断

2026-11-12 UTC。固定step0权重与P模板，在无NPU设备挂载的固定镜像中
执行CPU BF16前向与反向；没有优化器或权重更新。启动收据见同名launch JSON。
该实验用于补足独立输出logit范数无法判断共享参数梯度冲突的限制。

完整89条准入人口及已验收178输入gate先认证，再选择seed317日程的batch1
和batch6，各8来源。选择依据是此前输出logit诊断中的不同过程/Final比例，
属于探索性选择，不能估计全人口冲突率。不得根据结果重新选择更有利batch。

每条音频与问题模板按已验收request identity重新编码；模型直接消费音频。
分别对负Final期望正确性和负过程期望正确性求共享112个LoRA参数梯度。
过程权重保持0.1/0.1，Final权重1；跨来源按原类别均衡请求权重平均。
同时保留逐来源结果和整个batch梯度求和后的结果，不能用逐来源norm均值
替代batch梯度norm。报告范数、内积、余弦和组合梯度与Final梯度的内积。

在同策略点、无正则且裁剪未激活时，负期望奖励与中心化全候选PPO具有
相同梯度，loss数值本身不同。另以合成共享参数模型检查当前真实verl算子
是否满足此关系；还检查完全相反梯度、零梯度和非法坐标的解释。

执行与参数梯度为CPU BF16，跨请求累加为FP32，几何汇总为FP64。
NPU训练使用FSDP及FP32归约，故此CPU诊断不能代替NPU共享梯度测量；
每条CPU输出与已接受NPU候选概率的最大差异均需报告，不因dtype相同宣称
一致。没有Adam实际位移，梯度冲突也不能直接证明实际训练必然退化。
