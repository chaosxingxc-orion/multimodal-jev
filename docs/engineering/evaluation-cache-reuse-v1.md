# 跨实验复用数据和缓存

每次从台账领取任务时，先按内容身份查找已审核的源数据、训练视图、固定参考和评测缓存。训练视图复用要求划分、候选、人口、种子、批次与采样规则一致。固定参考还要求检查点、输入和推理运行时一致。只改奖励的实验复用录音、批次和适用的固定参考，单独更新目标矩阵。评测成绩继续绑定具体检查点。

通用 TPO 评测模板默认启用 `evaluation_cache_reuse`。封包按 seal、数据集、processor、provider、稳定前缀和编码参数查找 catalog。已登记的缓存以只读方式挂载。在取得设备租约前，CPU 核对 seal、完整录音顺序、缓存索引和每个张量文件的摘要。新面板按同样的输入身份、镜像、编码和审核脚本身份确定缓存地址。实验 ID、模型权重和设备分片不进入该地址。设备读取仍逐条检查缓存身份。

新缓存通过本地宏 `TPO_EVALUATION_CACHE_STORE` 绑定到目标机本地持久盘，独立于实验输出目录。同一地址只有一个 CPU 写入者。中断后复用已写入的条目，仅补缺失部分。完成独立校验后原子发布，后续进程只读。已发布缓存或其审核收据不一致时直接停止，保留证据以便核对。跨机使用时，先单独发布和登记已审核的只读资产，保持 seal 音频在容器内的路径一致。构建和断点状态留在本地盘。

181 的 catalog 登记了 SLURP TEST、MINDS native14、SIB-FLEURS 英语话题和 MMSU 多义词的完整缓存。由独立宏 `TPO_EVALUATION_CACHE_CATALOG_HOST` 绑定登记主机；切换实验主机时不会将旧目录当成新主机上的命中。新实验可用 `catalog_cache` 声明 seal 和 processor 等身份，无需借用上一次评测的运行配置。正在使用的历史缓存保留原位置与身份。

台账的评测步骤将缓存预检或发布收据登记到 `checks`。收据包含 `manifest_sha256`、`recordings` 和 `cache_action`（复用、续建或新建）；按内容地址发布的缓存还包含 `publication_key`。缓存命中仅证明输入可复用，模型预测与评分仍按本次端点单独收集。

本次核对发现，九个历史评测包共用 SLURP TEST 和 MINDS 缓存；JEV-201 的 SIB-FLEURS 和 MMSU 首次编码失败，重试使用同一 seal 与 processor 重新编码。四个面板现均有审核收据，181 上已复核共 21,577 条录音及对应张量。训练侧的相同 `rows.json` 多数来自冻结封包复制，不能据文件份数推断构建次数。双向目标编译器可用 `reuse_manifest_sha256` 显式复用已审核目标；奖励改变时重新投影，继续读取原训练视图及固定参考。
