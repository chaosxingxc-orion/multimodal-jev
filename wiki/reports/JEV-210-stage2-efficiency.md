# JEV-210 Stage2 训练效率审查

核对时间：2026-11-26 09:52（北京时间）。按工程性能指南的 T1–T5 拆分。历史基线为 181 的 JEV-209 固定批、6 张训练卡；同人口离线重排使用 JEV-210 候选 `fdd13c1`。截至核对时，JEV-210 全 TRAIN 评分已提交 92,096 / 109,610 条录音，Stage2 尚未开始。下文的候选数据是工作量复算，不是 NPU 加速成绩。

## 同人口重放：每项优化减少什么

在真实 26,558 条 JEV-209 Stage2 录音上，逐条核对当前只读声学索引中的音频摘要，使用冻结规则卡的 68 个长短不同的输入。取每条最长完整请求，四个桶分别有 20,575 / 4,553 / 1,231 / 199 条。保持全部 1,805,944 个有效录音×卡目标，只改变优化器排程；下表按 6 rank 加总模型调用与输入行。每次前向内语言矩阵补到实际最长序列。声学行指交给声学塔的录音输入条数；按音频帧补齐开销与算子耗时仍需实测。

| 工作量 | 历史固定批：每卡 64，每次前向 1 条 | 仅声学去重，保留历史批序 | 候选分桶：每卡更新 32/24/16/8，前向 4/3/2/1 |
| --- | ---: | ---: | ---: |
| 优化器更新 | 70 | 70 | 257 |
| 模型前向调用总数 | 26,880 | 26,880 | 10,080 |
| 声学输入行 | 1,827,840 | 26,880 | 26,916 |
| 语言输入行（含补位） | 1,827,840 | 1,827,840 | 1,830,288 |
| 补齐后的语言 token 格数 | 1.995 亿 | 1.995 亿 | 2.121 亿 |
| 逐步最慢 rank 的语言 token 格数之和 | 3,408 万 | 3,408 万 | 3,607 万 |

直接复用同录音的冻结声学输出，理论上把这部分的输入行缩到约 1/68；68 个语言骨干和决策头的判决依然存在。当前分桶把前向调用减少 62.5%，但在每次前向混入多条录音后，语言 padding 总量比旧版逐录音前向高 6.3%，最慢 rank 的格数代理高 5.8%；因此不能从调用次数推导总时延。候选补位槽共 358 个，旧版 322 个；尾批瘦身被多个半空桶的跨 rank 补位抵消。

分桶窗口以最大桶的全局容量为单位。窗口为 2 时，6 卡只能往前看 384 条，长桶在历史视图中占约 0.75%，经常只有几条。实测复算更新数：窗口 **2 / 8 / 16 / 32 → 257 / 170 / 161 / 158**。窗口为 2 时，中、长三个桶没有一次达到各自更新上限。Stage2 的目标已冻结，扩大编排窗口没有 Stage1 在线 EMA 的滞后成本；仍会改变批序。窗口 16 足以作为容量候选，最终应以 JEV-210 真正选出的难例/回放分布重算。“32”更新窗口与 CPU 的预取深度各自独立。即使窗口为 16，更新数也仍是旧版的 2.3 倍；需要保留端点评测，并按实际工作量设 checkpoint 间隔。

## 根因与工程优先级

| 审查点 | 证据及优先动作 |
| --- | --- |
| 候选准入阻塞 | [训练器](../../tools/reports/train_tpo_stage2.py) 把每步仅一条的 `jev/peak_bytes` 纳入了按累积次数校验的指标。只要有多个 microbatch，有限更新就会被错误拒绝。本次已在独立候选修复：显存及计时与目标指标分开归约，保留原始指标的累积数校验。 |
| T3：同音频的重复声学计算 | 旧版每条进行 68 个输入的声学计算；拆成一次冻结声学编码加 68 个独立语言判决，收益路径明确。先用相同视图、更新分组、排序与 microbatch 验证同考题工程 A/B。旧概率与新概率必须按录音和候选逐值比，保留原声学窗口、mask 和 BF16 数值路径。 |
| T4：语言反向与同步 | [Stage2 actor 构建](../../tools/reports/stage2_view_actor.py) 没有指定 Stage1 已验证的 `attention_and_projection_shared_splits_v1`；这版分桶候选也没打开。原图的行切片在较宽 batch 的反向上曾显著退化。需要单独开关 A/B，再与声学复用组合。6 卡 FSDP 按层分片，旧版每卡每步执行 64 次前后向；每个 microbatch 还会把 loss/计数从设备转成 Python 标量，步头尾均有对象集合通信。需区分 H2D/D2H 等待、HCCL 自身耗时和最慢 rank 到达滞后，再决定是否合并指标传输或改累积同步。 |
| T2：分桶与每卡容量 | 把 `microbatch` 容量和优化器更新宽度分别定标；优先比较 68/136/204/272 个卡片对的实际吞吐与显存。普通、长尾、尾批都需覆盖；额外记录有效/补齐音频帧和文本 token。通过容量后再选更大的窗口和全局更新布局。可另测固定更新分母、仅重排每步内部的长度组，作为区分“扩前向省调用”和“改变优化步数”的控制。 |
| T1：输入与 H2D | 候选将读取和 CPU 拼批放到有界预取，并复用 Stage1 mmap 声学缓存。旧日志没有等待细项，不能从全程曲线判断输入是否已经很轻。候选报告的 `train_seconds` 仍含 H2D、通信、AdamW；分段 profiling 应另计预置 NPU 输入后的设备更新耗时。 |
| T5：参考准备及落盘 | Stage2 已离线冻结参考和 TPO 投影，正式训练不启动在线 rollout。全 TRAIN 打分仍是构建难例视图的上游成本：JEV-210 每次为 745 万对。当前视图构建先重审全部分块、随后再读同一分块取概率，可考虑在一次完整校验中返回已校验的概率，保留全部身份和覆盖核验。JEV-209 的落盘不是历史主瓶颈；JEV-210 候选每 32 步做恢复存盘，动态批次后应测它的真实墙钟和每个断点覆盖的录音数。 |

最小验证顺序：在相同真实批序上测试“原生 → 声学去重 → 声学去重加组合反向图”，再测容量和分桶参数。对照固定同一检查点、候选顺序、输入、精度与并行拓扑；预热后分别记输入等待、H2D、声学、语言/头前向、反向与 HCCL、裁剪/AdamW、记录与恢复。细粒度设备事件只用来定位，不把嵌套区间相加；主结果报真实录音/秒、配对/秒、P50/P95、峰值内存和全局分母。逐候选验证概率、loss、逐参数梯度和更新后权重；改变批组的正式版本再评测源域和迁移表现。
