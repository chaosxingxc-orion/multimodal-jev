# JEV-210：NPU 分桶宽度探测

181 的 8 张 910B4 各跑一个独立进程，使用历史运行包实际加载的 Qwen3-ASR-0.6B、LoRA r128、冻结声学塔复用、BF16 和梯度检查点，测前向、双向 InfoNCE 反向、梯度裁剪与 AdamW。输入为合成 mel 特征和 token，每锚点 14 个配对（1+3+5+5），实际右 padding 和 attention mask。每组预热一次，统计三次更新中位数；耗时不含主机组批和 H2D。未测 1.7B、真实样本分布、DP8 梯度同步、训练效果或超长尾部。本轮未派发正式训练。第一次探针因 FSDP 没有对齐训练侧 BF16 输入转换而退出；下表只取修正后退出码为 0 的两轮。

|112|8→1.104，16→1.210，24→0.972（复测 0.957），32→0.767|16|5.94|
|144|16→0.661，24→0.526，32→0.418|16|8.02|

|320|8→0.540，16→0.344|8|10.09|

推荐下一次真实 TRAIN 有限窗口先验证 ≤144 用 16、145–320 用 8；若保留更多分桶，同宽的相邻桶可以保留，以减少短长混批。144 与 192 之间未测，不把 144 当成已证实的最优切点。>320 单独做压力检查。不能用不同长度的每步耗时比较宽度；应在同长度下对比每秒处理的真实锚点数。两轮共 16 个测量，15 个不同组合，未见 OOM。较宽的 batch 可以装下但吞吐下降，尚未通过算子跟踪确定原因。

八组均正常退出。112 token 同轮从 16 扩到 48、64，吞吐分别下降约 53%、62%；144 token 从 16 扩到 48 下降约 54%。192、256、320 token 与前轮同长度的 batch 8 对照，分别扩到 32、24、24 后下降约 57%、46%、52%。这些是已跑通的容量点，不是显存上限。以计算吞吐为目标，保留短桶 16、长桶 8 作为真实训练的验证起点。输入已经在卡上，因此主机数据准备不能解释这次降速；具体瓶颈需对同长度快慢两档做算子计时才能定位。1.7B/r256 需用目标模型验证，不能直接采用本表作为正式配置。
