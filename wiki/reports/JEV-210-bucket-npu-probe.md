# JEV-210：NPU 分桶宽度探测

181 的 8 张 910B4 各跑一个独立进程，使用历史运行包实际加载的 Qwen3-ASR-0.6B、LoRA r128、冻结声学塔复用、BF16 和梯度检查点，测前向、双向 InfoNCE 反向、梯度裁剪与 AdamW。输入为合成 mel 特征和 token，每锚点 14 个配对（1+3+5+5），实际右 padding 和 attention mask。每组预热一次，统计三次更新中位数；耗时不含主机组批和 H2D。未测 1.7B、真实样本分布、DP8 梯度同步、训练效果或超长尾部。本轮未派发正式训练。第一次探针因 FSDP 没有对齐训练侧 BF16 输入转换而退出；下表只取修正后退出码为 0 的两轮。

推荐下一次真实 TRAIN 有限窗口先验证 ≤144 用 16、145–320 用 8；若保留更多分桶，同宽的相邻桶可以保留，以减少短长混批。144 与 192 之间未测，不把 144 当成已证实的最优切点。>320 单独做压力检查。不能用不同长度的每步耗时比较宽度；应在同长度下对比每秒处理的真实锚点数。两轮共 16 个测量，15 个不同组合，未见 OOM。较宽的 batch 可以装下但吞吐下降，尚未通过算子跟踪确定原因。

八组均正常退出。112 token 同轮从 16 扩到 48、64，吞吐分别下降约 53%、62%；144 token 从 16 扩到 48 下降约 54%。192、256、320 token 与前轮同长度的 batch 8 对照，分别扩到 32、24、24 后下降约 57%、46%、52%。这些是已跑通的容量点，不是显存上限。以计算吞吐为目标，保留短桶 16、长桶 8 作为真实训练的验证起点。输入已经在卡上，因此主机数据准备不能解释这次降速；具体瓶颈需对同长度快慢两档做算子计时才能定位。1.7B/r256 需用目标模型验证，不能直接采用本表作为正式配置。

**根因对照：112 token，batch 16 与 32。** 同一 181 镜像、0.6B/r128、固定种子、合成输入与 AdamW 更新；每个宽度分别跑原实现及三个单因素变体，均为单卡。分段末尾同步 NPU，计时不含数据准备。预热一次，表中取后两次平均值（秒）。对照在 batch 16 的更新用时 12.88 秒，与上轮无分段同步的 13.09 秒接近。

| 唯一改动 | batch 16 反向 / 整步 | batch 32 反向 / 整步 | batch 32 锚点/秒 |
|---|---:|---:|---:|
| 原实现 | 8.72 / 12.88 | 34.02 / 41.21 | 0.777 |
| 注意力 Q/K/V：先 unbind，再按有效长度取每行 | 6.36 / 10.49 | 15.78 / 23.62 | 1.355 |
| 线性投影：先 split，再按原形状逐块 bmm | 7.58 / 11.84 | 25.80 / 32.85 | 0.974 |
| 判决头：先 split 隐状态，保留逐行读出 | 8.79 / 13.03 | 34.04 / 41.53 | 0.771 |

对照从 16 到 32：到声学塔输出为止 1.08→1.95 秒；其后到语言骨干输出 2.35→3.81 秒；到 head/FSDP 返回 0.64→1.25 秒；InfoNCE 前向 0.06→0.14 秒；裁剪与更新 0.02→0.04 秒。反向增加 25.30 秒，占整步新增 28.33 秒的 89%。三处对照均保留前向的数学运算和每行有效长度。每锚点 14 行，扩批时语言注意力每层处理的配对行数从 224 增至 448。原实现让各行 Q/K/V 切片分别连接到整批张量；先拆行再截长度，使梯度可通过共享拆分节点合回批张量。实测支持切片自动求导路径是主因，投影分块切片是次因；未做内存带宽或逐 kernel 计数，不能把全部差异归于某个底层 kernel。两项收益不能直接相加。

同宽度下三次前向（含预热）的完整 logits 哈希、标量 loss 和全局梯度范数均与各自对照一致。没有验证逐参数梯度、真实数据、1.7B、DP8 或长期效果。注意力改动后 batch 16 仍比 32 有更高锚点吞吐（1.525 对 1.355）；先验证组合候选的数值与吞吐，再为目标模型重新选桶。此次仅诊断，未修改训练基线。[逐次测量、配置及隔离变体源码差异](JEV-210-bucket-cause-npu.json)。
