# JEV-209：对齐版推理耗时

登记口径见[实验协议](../../experiments/jev-209-inference-latency.md)。这是端点评测的工程验收，不产生新训练版本。以下时间是每个原始批次所有候选输出回到 CPU 的累计时间；不含样本加载，不等于首条录音可以决策的时间。

| MINDS 固定重放 | 候选输入对 / 核对分数 | 标准混合批 | 复用音频、文本混批 | 复用音频、按文本长度分组 |
| --- | ---: | ---: | ---: | ---: |
| Stage1 第 286 步 | 1,219 / 108 | 54.16 秒 | 31.96 秒，14 项有差异 | 96.95 秒，0 项有差异 |
| Stage2 第 70 步 | 353 / 24 | 16.54 秒 | 11.40 秒，2 项有差异 | 34.16 秒，0 项有差异 |

同批中的每条录音只算一次音频编码，仍让每张知识卡独立评分。混批在两个端点都更快，但未消除分数偏差；按文本长度分组通过有限数值对照，分别慢 79.0% 和 106.6%，也未通过验收。结果已与先前独立 HF 参考逐项复核，包含样本身份、邻近样本形状、端点及原始分数。调度端证据：`jev-card-eval-209-perf-v0.0.9/performance-audit.json`，SHA-256 `0f9c7c826496c5a2f8f06882812bba4b66852142559c5ba20bf1091aca04a736`。

后续步骤仅使用两张独立的 NPU。正式基线不变；待收齐逐值对照、首条判决延迟和全流程 wall time 才可宣称“最多慢 10%”。

两卡复测中，仅注意力运算按有效文本长度分组，音频编码继续在同录音内复用，语言模型其余计算仍混批。固定 31 块协议中的 MINDS 结果如下：

| 检查点 | 核对的 HF 单对分数（logit 和概率） | 标准累计前向 | 新版累计前向 | 耗时比 |
| --- | ---: | ---: | ---: | ---: |
| Stage1 286 | 108 项，0 差异 | 60.37 秒 | 45.26 秒 | 0.750 |
| Stage2 70 | 24 项，0 差异 | 16.01 秒 | 13.58 秒 | 0.848 |

证据：`jev-card-eval-209-perf-v0.0.11/performance-audit.json`，SHA-256 `79018310c74d1b6a9eb96734c14cfe269aac5cb3b1291b416652fdf7aa2f9900`。在两个旧失败块的逐层检查中，混批首次观测到的差异均在首层注意力输出，后续层的差异增大。这个定位只针对这两个块；132 个分数的有限复核也不证明全量一致。

首条判决的进一步验证固定为 MINDS 每个端点 20 块，按估算计算量排序后在首尾之间等间隔取样，不使用标签或模型分数。每块包含标准和候选两个顺序对调的计时回合；P50/P95 按所有温态块遍历的最近秩分位数计算。计时从创建预取器之前开始，至首条完整候选向量回到主机。全量端到端计时另计。

在相同的 MINDS 40 块上回查旧对齐版的八卡运行日志，每端点 20 块。Stage1 从领取块到读出首个输入的中位数为 0.052 秒，从首个输入到提交整块为 63.77 秒。Stage2 对应为 0.047 秒与 63.71 秒。首个输入之后仍有其余输入预取、模型计算和落盘开销。该记录只能定位到这一区间，首条录音全部 14 个概率何时就绪由新的两卡测量给出。

| 端点 | 原批数 | 输入对 | 不同录音数之和 | 按完整形状拆模型的组数 | 仅按文本长度拆注意力的组数（每层） |
| --- | ---: | ---: | ---: | ---: | ---: |
| Stage1 | 36 | 1,219 | 106 | 461 | 444 |
| Stage2 | 8 | 353 | 30 | 127 | 119 |

每层分组数仍多，已开发第二个候选。在同一前向内复用每组的行索引，将逐行截取、补齐、拼接改为分组收集和按索引写回。原始顺序、有效 token 范围、BF16 TND 内核和混合精度策略保持一致。组内含不连续行、不同长度和补齐位置的 CPU 复核通过。设备耗时与精度需由 NPU 重放确定。

包 `jev-card-eval-209-perf-v0.0.16` 使用设备事件分别记录卷积、音频编码器各层、声学投影、语言模型各层的注意力与 MLP、决策 head，并对分组候选记录 Q/K/V 搬运、TND 调用、恢复行顺序。嵌套区间分别报告，多级时间不能相加。每个被插桩前向与同输入未插桩前向逐值核对。本轮只验推理引擎：原排队的训练端前向检查及其条件重放均已撤销，未执行 FSDP 前向。全量推理对照 `jev-card-eval-209-perf-full-comparison-v3` 在抽样精度与首条判决时间通过后才放行；用卡限于 181 的 0、1 卡。

同一份 HF 参考还允许把原对齐版与新候选落实到慢批。下表按每个原始批只计一次，单位为毫秒，P50/P95 用最近秩；数值是整批前向至结果回到主机。两个版本各有同轮标准对照。原版在八个并行 worker 的历史诊断中采得，新版在两个 worker 上采得，不能以两轮耗时之差作为单个算子的净开销。

| MINDS 端点 | 原版同轮标准 P50 / P95 | 原对齐版 P50 / P95 | 新版同轮标准 P50 / P95 | 新候选 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |
| Stage1 286，36 批 | 1,478 / 2,825 | 2,820 / 8,968 | 1,573 / 2,820 | 1,030 / 2,524 |
| Stage2 70，8 批 | 1,540 / 2,963 | 5,940 / 10,268 | 1,644 / 2,865 | 1,350 / 2,655 |

两端点原对齐版累计前向分别为同轮标准的 2.50、2.96 倍；新候选为 0.75、0.85 倍。Stage2 只有 8 批，其 P95 就是这 8 批的最大值。重放的请求邻居、顺序、检查点、单对参考与比较人口已由同一审核程序核实。证据为 `jev-card-eval-209-parity-v0.0.6/batch-forward-percentiles.json` 和 `jev-card-eval-209-perf-v0.0.11/batch-forward-percentiles.json`。

两个原失败块的首个异常样本在第 0 层的旋转位置编码、输入归一化及 Q/K/V 投影观测点均相同。注意力输出进入输出投影前，Stage1 有 1 个元素发生变化（最大绝对差 0.0001220703125），最终 logit 从 −0.984375 变为 −0.9453125；Stage2 有 3 个元素发生变化（最大绝对差 0.0009765625），最终 logit 从 −0.412109375 变为 −0.421875。该区间包含应用旋转位置编码、打包、注意力和恢复行顺序，不足以定位到某条更细的硬件指令。公开结论保留到这一粒度。

对正式对齐版 1,938 个块按归属、两端点和录音数与封存计划逐块核对。MINDS 每端点 256 块，领取至首输入可读的中位数分别为 48、47 毫秒；首输入至整块提交的 P50/P95 分别为 63.91/68.47 秒与 64.03/68.61 秒。MINDS 只占两端点累计 worker 工作时间的 29.4% 和 29.3%；SLURP clean TEST 与 selection 合计约 70%。该比例不是墙钟占比。若目标是降低整个任务时长，MINDS 的修复不会消除 SLURP 的成本，需分别看其余面板的首条判决和每录音工作量，再决定是否扩展音频复用。现有包只在 MINDS 切换计算路径。

同录音的各张卡共用原始特征张量。音频复用版本此前仍逐卡扫描整份特征、填充并拼接组批后的特征和掩码，随后只从原始录音张量计算声学输出。独立候选改为同一批内按特征与掩码对象的身份各验证一次，只拼接模型需要的文本输入。每个请求仍检查占位符数、判决位置和可见音频窗口。该改动可以独立于注意力分组进行验证。

在工作站单线程重建上述 44 批的 token 数、录音归属、有效帧和填充帧，用合成 float32 特征测量 CPU 组批。逐批核对文本 ID、掩码、位置 ID 与判决位置，四轮交换新旧顺序。下表按物理批列出组批时间分布。累计字节只计两种不再构造的输出张量。

| 端点 | 原组批 P50 / P95 | 新组批 P50 / P95 | 每次遍历少构造的音频张量 |
| --- | ---: | ---: | ---: |
| Stage1 286，36 批 | 49.25 / 64.84 ms | 9.76 / 18.28 ms | 1.217 GB |
| Stage2 70，8 批 | 51.04 / 65.86 ms | 12.32 / 20.03 ms | 0.275 GB |

该计时覆盖主机内存中的组批函数。设备模型前向、磁盘读取与线上首条判决各自采用单独计时。CPU 功能回归 31 项通过。待设备逐值审核后才能采用此候选。证据为 `jev-card-eval-209-perf-v0.0.11/host-collation-shape-replay.json`，SHA-256 为 `64bc374b5d262efeaa45baa91dae03f54fd72751025c98e751e2fa59e1c4a1e1`。

设备事件另测每个 checkpoint 的 2 批、40 个输入对。Stage1 和 Stage2 的音频编码区间累计分别从原生的 834、897 ms 降到 201、211 ms。语言 MLP 仍各调用 56 次，累计耗时从 235、235 ms 变为 240、241 ms。分组注意力每端点分别调用 420 次 TND，累计 95、103 ms。只给注意力分组，能保留其他语言层的批处理效率，同时利用同录音的音频编码。索引搬运候选的 QKV 收集区间从 99、104 ms 增至 129、139 ms，目前保留已通过温态对照的实现。插桩与未插桩输出一致，设备事件只用于定位。

证据为 `jev-card-eval-209-inference-first-output/first-output.json`（SHA-256 `bc0fb869a6807e56654265731aa18007e7fcb0ff8172ca630b96ca74fb15110a`）和 `jev-card-eval-209-perf-v0.0.16/operator-audit.json`（`f1e4201e2f4fa777735e02bd579c303bfbf820e66f29bc62ade918d2a14c2ea8`）。全量对照已排队。标准组在封包后遇到设备租约等待，直接使用包含外部排队时间的标准组墙钟会低估耗时比。最终审核须排除该偏差，并保留原始墙钟。
