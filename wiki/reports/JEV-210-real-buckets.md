# JEV-210：真实 TRAIN 的分桶与采样开销

0.6B、LoRA r128、181 单卡独立更新；正式训练未恢复。第一个 epoch 的 109,610 个 TRAIN 锚点（自然录音 40,513，合成录音 69,097）均参与长度统计。按冻结的初始 EMA 分布及原批序步号，分别用正式采样器生成配对；未使用 selection/test。后续动态 EMA、分桶后的实际批序会改变抽样长度。

单条序列由一张卡的前后缀和一段音频的展开 token 构成；每个锚点取其全部配对的最大长度分桶，每批按实际最长序列补齐并传 attention mask。两种配方的单条配对长度 P50/P95/P99 都是 97/129/150，增加配对数主要改变锚点内的最大值。

同一配方、同一档共享面板，较小 batch 取相同锚点列表的前缀。每档强制包含达到上界的样本，其中最长一档是压力测试；它的吞吐不能代表整段长尾。NPU 运行真实声学特征、双向 InfoNCE、注意力和投影的组合优化。一次预热、两次计时取中位，计入前向、反向、裁剪、AdamW 和 NPU 同步，排除数据准备与 H2D。正式八卡通信、在线采样和 EMA 更新不计入。

40 个形状完成 39 个。14 配对、batch 32、390 token 的更新请求再分配 24.47 GiB，设备仅余 12.13 GiB，触发 NPU OOM。全部容器已退出，181 的八卡均已释放。按四档方案，轻配方每秒覆盖的锚点增加约 69%，每秒处理的配对约为 19.6 对比 20.2；主要收益来自减少每个锚点的计算，尚无下游效果对比。

在已测五个边界枚举连续、宽度不增的方案，按各档锚点数除以实测锚点/秒求和，以估算用时最短者作为候选。末桶的 null 是配置兜底，超过实测最大长度的容量仍未知。一档只用一个面板和两次计时，小幅差异不能用于锁定最佳切点。吞吐不代表效果；配对数减少同时改变每个锚点获得的监督。

复现：将相同的 TRAIN 源配置、声学包和知识卡绑定为只读，运行 `python -m tools.jev.card_real_bucket_panel SPEC TRAIN_CONFIG OUT`；遍历 SPEC 中的 recipes 和 widths，给每份 SPEC 添加 `real_lane = {recipe, width, panel}`，其中 panel 指向 OUT 下对应 panel 文件。每份独占一张 NPU 执行 `python -m tools.jev.probe_card_bucket_shapes LANE_SPEC TRAIN_CONFIG CASE_INDEX`。收集 BAND 行、docker wait 和 inspect 后，使用 `tools/reports/audit_card_real_buckets.py` 复核。
