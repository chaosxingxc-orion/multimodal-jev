# 一次实验包怎么交付

每个实验包以台账中的一条研究记录为起点，以同一条记录的状态更新和完整报告为交付。研究 ID 贯穿全程，使用版本化配置与证据索引串起各阶段。假设、预算和运行配置先写入实验目录，台账行引用已提交的协议。[实验配置入口](../experiments/README.md)开工前同步主线，优先处理已有实验可继续的阶段，再从待开展的记录中选取一行。[实验队列](experiment-ledger.md#实验队列)

| 阶段 | 做什么 | 台账要留下什么 |
| --- | --- | --- |
| 1. 读取一行 | 从已提交的台账取一条待开展记录，核对依赖、研究假设、对照、训练预算、评测清单和派发范围 | 研究 ID、台账提交、选中行和预登记协议的 SHA-256，以及对应的配置版本 |
| 2. 构建或复用数据 | 优先复用已发布并审核的源数据、训练视图、评测面板和共享音频、特征及固定参考。只构建新增或发生变化的部分 | 数据版本、split、样本数、候选与模板、种子、manifest 及审核收据。按产物记录复用、增量或新建及原因 |
| 3. 模型训练 | 走现有冻结包、有限验收、设备租约、正式训练及独立收集。记录初始策略、真实曝光、更新与 checkpoint | 包版本、配置和初始化身份、确切句柄、阶段耗时和卡时、终态及独立训练收据 |
| 4. 模型评测 | 预先封存评测人口、检查点、基线与规则。训练审核后再加载端点推理，使用固定评分器独立复算，源域和每个迁移目标达到各自的预登记覆盖要求 | 原始预测索引、评分和审核收据、实际分母、缺失项、每个评测集的基线、结果、配对差和结论 |
| 5. 更新台账 | 将状态、成本、结论和后续动作写回同一研究行，将完整报告存到 Wiki 并同步主线。后续规划引用报告内已审结果 | 报告链接、证据身份和修订记录。训练通过后仍保留评测状态，直到各项验收完成 |

数据复用按层判断。源数据身份与划分一致时复用音频。预处理、编码器与输入身份一致时复用其特征。模板、候选、人口、标签版本、随机种子和构建规则共同决定视图或评测面板的身份。固定参考还要求策略、运行时和精度相容。对复用产物校验内容及对应审核器收据。已有分片通过身份与完整性校验时，续跑仅补缺失分片。TRAIN 用于构造训练视图与校准。selection、TEST 和迁移数据按各自的封存用途消费。通用 TPO 评测在申请设备前核对[可复用的缓存](../docs/engineering/evaluation-cache-reuse-v1.md)，并在报告中记录命中、续建或新建。启用[共享样本块调度](../docs/engineering/tpo-evaluation-sample-blocks-v1.md)时，各卡共用评测队列，仍以每个数据集的全量审核发布结果。

评测报告按数据集、接口、检查点和对照给出结果。单标签意图主报 Top-1 macro-F1、准确率和平均 Top-1 原始概率。对相同人口给出基线、差值、分母及预先约定的不确定性。Choice 有拒选动作时，分报命中条件下的误拒与缺席条件下的误接，并列各自分母。每个跨数据集目标给出独立结论和适用边界。MINDS 意图结果归入同任务跨数据集迁移，话题等新判决另列。缺失数据或失败分片在报告中保留原状态，整体实验的收口依据预登记必跑项和独立审核。

操作员只调用仓库根目录的 `run_experiment.py`。默认先选择仍在进行的实验；没有在途项时，按优先级领取一条 `planned`。用 `--experiment JEV-204` 可以指定一行。开始前同步主线，并核对已登记的运行资源。

| 命令 | 行为 |
| --- | --- |
| `./run_experiment.py plan` | 只读，显示选中的台账行和准备情况 |
| `./run_experiment.py status --experiment JEV-201` | 只读，展示审核收据和评测覆盖；输出反映已落盘证据 |
| `./run_experiment.py run --publish` | 领取一行，调用已登记的阶段脚本，回填 Wiki 并同步到远程主线 |
| `./run_experiment.py resume --experiment JEV-201` | 从已有审核收据接续并更新本地 Wiki |
| `./run_experiment.py publish --experiment JEV-201` | 将同一实验的 Wiki 报告和队列行同步到远程主线 |

长任务在调度机的持久会话中调用 `run` 或 `resume`。两者均可加 `--publish` 自动同步；省略时只更新本地。领取记录、已解析绑定、阶段日志和审核摘要保存在本地状态目录。运行中断后，若已有派发记录而审核收据尚未落盘，入口保留等待状态；后端恢复后继续读取审核产物。独立审核或依赖缺失时保留具体缺项。同一批评测的分数据集结果与对照差值写入该实验报告；只有登记项全部审完才写 `complete`。[执行配置](../experiments/pipelines/README.md) · [报告模板](TEMPLATE.md)

领取时冻结实验协议、流水线配置和执行提交。分阶段执行及 `resume` 从冻结提交取代码和模板，并校验已派发命令、绑定和审核收据；Wiki 里程碑或无关代码提交可以在实验期间正常更新。修改实验协议或流水线需要登记新修订并显式引用已审核的前序产物。旧领取记录继续使用已有命令的提交收据，无需迁移历史状态。

台账写回发生在阶段执行之后。远端主线若已有其他实验的新记录，发布只应用本实验的行与报告；同一行或报告有冲突时保留执行收据及本地报告，处理冲突后用 `publish` 重试。若本地报告尚未生成，可用 `resume` 从收据重建。发布失败会单独显示在 `report_error`，可据此区分计算失败与同步失败。
