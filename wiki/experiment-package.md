# 一次实验包怎么交付

每个实验包以台账中的一条研究记录为起点，以同一条记录的状态更新和完整报告为交付。研究 ID 贯穿全程，使用版本化配置与证据索引串起各阶段。假设、预算和运行配置先写入实验目录，台账行引用已提交的协议。[实验配置入口](../experiments/README.md)开工前同步主线，优先处理已有实验可继续的阶段，再从待开展的记录中选取一行。[实验队列](experiment-ledger.md#实验队列)

| 阶段 | 做什么 | 台账要留下什么 |
| --- | --- | --- |
| 1. 读取一行 | 从已提交的台账取一条待开展记录，核对依赖、研究假设、对照、训练预算、评测清单和派发范围 | 研究 ID、台账提交、选中行和预登记协议的 SHA-256，以及对应的配置版本 |
| 2. 构建或复用数据 | 优先复用已发布并审核的源数据、训练视图、评测面板和共享音频、特征及固定参考。只构建新增或发生变化的部分 | 数据版本、split、样本数、候选与模板、种子、manifest 及审核收据。按产物记录复用、增量或新建及原因 |
| 3. 模型训练 | 走现有冻结包、有限验收、设备租约、正式训练及独立收集。记录初始策略、真实曝光、更新与 checkpoint | 包版本、配置和初始化身份、确切句柄、阶段耗时和卡时、终态及独立训练收据 |
| 4. 模型评测 | 预先封存评测人口、检查点、基线与规则。训练审核后再加载端点推理，使用固定评分器独立复算，源域和每个迁移目标达到各自的预登记覆盖要求 | 原始预测索引、评分和审核收据、实际分母、缺失项、每个评测集的基线、结果、配对差和结论 |
| 5. 更新台账 | 将状态、成本、结论和后续动作写回同一研究行，将完整报告存到 Wiki 并同步主线。后续规划引用报告内已审结果 | 报告链接、证据身份和修订记录。训练通过后仍保留评测状态，直到各项验收完成 |

数据复用按层判断。源数据身份与划分一致时复用音频。预处理、编码器与输入身份一致时复用其特征。模板、候选、人口、标签版本、随机种子和构建规则共同决定视图或评测面板的身份。固定参考还要求策略、运行时和精度相容。对复用产物校验内容及对应审核器收据。已有分片通过身份与完整性校验时，续跑仅补缺失分片。TRAIN 用于构造训练视图与校准。selection、TEST 和迁移数据按各自的封存用途消费。

评测报告按数据集、接口、检查点和对照给出结果。单标签意图主报 Top-1 macro-F1、准确率和平均 Top-1 原始概率。对相同人口给出基线、差值、分母及预先约定的不确定性。Choice 有拒选动作时，分报命中条件下的误拒与缺席条件下的误接，并列各自分母。每个跨数据集目标给出独立结论和适用边界。MINDS 意图结果归入同任务跨数据集迁移，话题等新判决另列。缺失数据或失败分片在报告中保留原状态，整体实验的收口依据预登记必跑项和独立审核。

在主线运行 `python3 -m tools.reports.experiment_ledger plan` 读取下一条待开展实验。领取记录放在新实验的本地证据目录，和数据、训练、评测各阶段已解析配置一起留存。数据、训练和评测沿用对应实验族的发布入口。已有运行从最近一个经过独立审核的阶段接续。每阶段完成后用固定工具核验收据，再把状态和报告同步到台账。[报告模板](TEMPLATE.md) [运行规范](../docs/engineering/context-prob-v1-baseline.md#日常任务执行规约)
