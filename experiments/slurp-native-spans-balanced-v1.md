# 均衡分类调试轮 v1

用户要求分类更均衡。已审核 48 条中，date/timeofday 各正负 24/24，time 为 24/22；八个完整标签组合为 5 或 6 条，另两条有 time 缺标。为每次更新平衡，而非只看总体比例，固定每种完整组合各取 5 条，共 40 条、120 项监督。用 seed 17 在学习集中确定性选取，并将三位互补的组合配对成 20 个 batch，每批两个录音，三个任务各有一个正例一个负例。无重复过采样，不恢复排除标签。

从同一本地原始基座开始，其他训练条件与 native-spans-sft-v1 相同：q/v rank4 LoRA、lr1e-4、全词表 CE、一个 epoch，原始音频。前处理暂不叠加，以便隔离均衡策略；之后各前处理配置独立对照。

诊断仍在原 48 条、142 项标签上记录训练前后和静音对照，增加每任务混淆矩阵、正负召回与 balanced accuracy。这不是 held-out 评估，不能声称泛化收益。与旧轮样本数/更新数不同，差异不能仅归因为 batch 均衡；后续因果比较须同 40 条、同更新预算的随机 batch 对照。

根目录 `slurp-native-spans-balanced-v1`，物理 NPU 4，硬截止 3600 秒。固定镜像和本地模型，无新下载。

完成：容器退出 0，20 次更新、40 条不同录音、120 项监督；独立重算 batch 表，确认每个 batch 的每个任务正负 1/1，八种组合各 5 条。适配器文件哈希通过。原 48 条录音诊断仍为 70/142、完整全对 5/46；三个任务均预测 false，balanced accuracy 均 0.5。静音结果相同。均衡采样已经生效，但不足以解决当前模型/训练的类别偏置，不能据此宣称准确率收益。后续需在固定这 40 条及预算下分析候选归一化目标与全词表目标差异；尚未进行该对照。

验收补记：逐项核验发现新加 per_span 指标循环的变量 `name` 覆盖了评测阶段名，三份逐样本文件均写成 `timeofday.json`，后写覆盖前写。result.json 的阶段汇总独立保留，但无法独立复核训练前后逐样本记录，因此 v1 不作为完整验收。已修复变量名，另建 balanced-v2 重跑相同固定配置；不覆盖 v1，重跑不用于选择超参数。

v2 重跑完成退出 0；独立 verifier 逐条重算 3 份记录、混淆矩阵、训练 schedule 和适配器哈希，全部通过。结果与 v1 汇总相同：before/after/silence 均 70/142，各任务 balanced accuracy 0.5。见[验收凭证](../docs/engineering/slurp-native-spans-balanced-v2-verified.json)。当前事实结论是“分类与 batch 已均衡，模型仍塌缩到负类”，不是“均衡解决性能问题”。
