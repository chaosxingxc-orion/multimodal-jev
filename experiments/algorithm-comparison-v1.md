# Fixed data schedules for the algorithm comparison

This registration fixes data exposure opportunities before the first updated
policy development results are available. It does not yet establish matched
token/compute budgets or authorize a result to be called budget-matched.

Use the exact31 FSC TRAIN recordings (186 views) from the completed initializer.
No additional selection by reward, duration or development correctness. Each
iteration contains one complete six-view recording group. Shuffle the sorted
group list with a local RNG, seeds17/29/43, for six full epochs:186 update
opportunities,1,116 prompt exposures per seed. RL samples n4:4,464 responses
per trajectory. Complete all scheduled groups; zero-advantage no-ops count as
opportunities, never as optimizer updates. No early stopping or replacement
of uninformative recordings. Record actual updates separately.

All arms begin from the same immutable SFT adapter/export and fresh AdamW,
original Qwen3-ASR base, rank4/alpha8, LR1e-5, zero weight decay, gradient clip1.
The five arms per seed are continued SFT, GRPO standard, pair-GRPO standard,
GRPO center-only and pair-GRPO center-only. Pair weight is.2; reference KL is
disabled. Standard normalization remains a required control despite the weak
signal seen in the two-recording diagnosis. No winning normalization is selected.
Raw-policy decoding stays temperature1/top_p1/top_k-1/max_tokens32 with explicit
actor_features. Within-seed arms use the identical schedule, but each RL policy
generates its own on-policy outputs after divergence; later rollouts cannot be
shared across changed policies. Export roots remain separate per arm/seed.

Current candidate configs use full projection, full response batches, CPU float32
and the verified .02 probability gate. They are executable static inputs, not
launch receipts. Before launching the full matrix, require successful two-step
real-engine optimizer continuation, mixed-audio checks and allocated resources.
Any accelerator/dtype/projection change requires a separately recorded numerical
validation and revision before all compared arms start. Do not launch the entire
matrix on busy hosts or silently substitute short probes for this study.

Budget limitations are explicit: SFT sees one gold response per prompt whereas
RL sees four sampled responses; response lengths and no-op counts differ.
Matching schedules does not match tokens, actual updates or FLOPs. Persist
effective training tokens/audio frames, parity/reference work, generation tokens,
engine times and export costs. A separately registered budget-controlled
comparison (including normalization scale/LR sensitivity) is still required to
answer the main same-budget efficacy question. Do not change histories or claim
this opportunity-matched matrix alone answers it.

Use the already frozen FSC and SLURP development manifests and common strict
metrics, paired speaker bootstrap and constant/null controls. Preserve each seed
and arm result; report native semantic decisions, non-null transfer, false
refusals, Noul balanced accuracy and paired both-correct separately. Do not
average task types into a single claimed gain. Independent external task and
final test evaluation remain required after development choices are frozen.

The15 candidate configs are under configs/experiments/algorithm-comparison-v1.
The [static receipt](../docs/engineering/algorithm-comparison-v1-preflight.json)
checks each seed's full pair-standard schedule against real model/adapter/audio
assets and checks SFT's identical batch IDs and initializer. Other RL arms are
generated by the same function and differ only in reward/normalization/export
root. Every arm must still pass its own runtime preflight before allocation.

Reproduce the config matrix with tools/jev/build_comparison_configs.py, supplying
the saved initializer identity, rl-schedule-sft-smoke.json and
sft-continuation-runner-smoke.json templates, a new output directory and the
registered shared export root. Rebuilding in a temporary directory produced
exactly equal parsed JSON for all15 committed configs. The builder refuses an
existing output directory and validates the initializer manifest hash.
