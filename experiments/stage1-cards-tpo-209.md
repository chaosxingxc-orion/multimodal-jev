# JEV-209　真人与合成语音的知识卡 Stage1

**研究问题。** 增加同文不同音色的录音和对话意图的正例，是否能改善逐类概率、源域排序和迁移表现？同一实验编号下，上一版真人模型作为直接对照。两版同时改变录音数、候选数和更新步数，收益归于整套方案。[真人版归档](../wiki/archive/JEV-209-real-only/report.md)

**数据。** 真人 clean TRAIN 40,513 条，合成 clean TRAIN 69,102 条。来源 4818 的 5 条录音在 scenario/action 与 intent 字段上冲突，登记为 annotation_error。其余 69,097 条合成录音全部进入训练。68 个训练标签包括 8 个新增对话意图，合计 24,335 个正例。同一文本有多个录音时，每个录音各计一次。训练清单、源标注和勘误均有内容哈希。[准入配置](../configs/portable/operations/card-synthetic-admission.json)

**已停止版本的 Stage1 预算。** 181 上以 0.6B 基座和本实验原始 r128/alpha256 初始化训练，DP8、global batch 512。109,610 条录音每轮各曝光一次，尾批 42 条有效，补位权重为零。每轮 215 步，两轮 430 步。固定 step 0、215、430，以 430 为端点。模型直接听音频，每个候选返回独立概率。沿用 InfoNCE、概率间隔和双侧约束，学习率峰值 0.0001，warmup 8 步。每类按种子从 TRAIN 文本标注抽示例，避开查询自身、同组及同文示例。两轮分别使用规则版和带示例版。训练前逐条检查输入长度，完成四次推理和两次更新的有限验收。[运行配置](../configs/portable/operations/card-stage1-mixed.json)

**评测。** 修订路线按重新登记的端点评测；旧协议中的 Step 430 与真人版在相同 60 类 SLURP 面板上配对。完整官方 TEST 的 13,078 条按录音报告 Scen_Act Top-1 accuracy，clean-v7 的 12,991 条与 selection 的 9,226 条分别报告 Top‑1 macro-F1、accuracy、最高原始概率和概率误差。披露训练候选数、推理候选数和同文覆盖。MINDS native14、SIB-FLEURS topic7、MMSU polysemy 使用各自原生候选，单列迁移结果及分母。八个新增类在官方 TEST 中没有金标，源域主表只能验证它们对原任务的迁移收益。沿用源域 selection 的配对 bootstrap 和概率退化检查，测试集只作最终报告。

**Stage2。** Stage1 端点评测后，使用本轮策略作为固定参考，八实例打分，按分层难例和正确回放构造一份视图。融合 206 的双向 TPO 与 208 的动态间隔，在实际视图上以 DP6、global batch 384 跑一轮，另两卡做推理。挖掘范围、实际候选数与预算在派发前冻结，收齐终点评测后回填本台账。[融合目标和采样说明](../wiki/archive/JEV-209-real-only/protocol.md)

统一入口为根目录的 `run_experiment.py`。[执行台账](../wiki/reports/JEV-209.md)

**已停止的 68 对展开版本（仅用于容量对照）。** 每个模型输入只有一条录音、一张候选知识卡和一个音频后的概率读出。不同录音或卡片占独立的 batch 行，注意力互不可见。训练器在 loss 层按录音重组全部 68 个 logit，沿用原 InfoNCE、真类与最高错类的概率间隔及双侧约束；推理只取该卡 sigmoid。两轮抽样和声学特征沿用冻结清单。每步仍为 512 条真实录音（尾批除外），每个完整更新包含 34,816 次独立判决。源域及迁移评测也须逐卡独立打分，同屏版的训练 loss 不作为本轮结果。

**修订版 Stage1。** 一个样本是一张知识卡加一条语音。以当前样本为锚，另取同标签的不同录音作为正样本，再从不同标签抽一个样本作为负样本，三者组成一个训练组。卡片按样本构造，跨组不固定卡，不对每条录音穷举 68 张卡。三个样本各配自己的正确卡。异类样本在表示对比中是相对于锚点的负例，对自己的卡仍是成员正例。表示对比建议使用归一化向量上的 InfoNCE。成员概率的负监督来自显式错配，例如将异类录音配给锚点的卡。需用固定卡、换录音的诊断检验模型是否利用了音频。推理仍对单张卡与单条语音返回成员概率。

采样仅使用 TRAIN，两轮分别打乱，每条录音每轮恰好担任一次锚点，不按文本去重。抽样器已做 CPU 全量核对；卡片配对、梯度定义与新训练预算需在派发前冻结，同时登记每步锚点数和实际模型输入行数。旧版 430 步、端点和容量收据不自动沿用。

三元组版用 DP8，每卡每个微批 24 个锚点，累积 4 次得到 96 个锚点。八卡合计 768 个锚点，完整更新处理 3,072 对输入。每轮 143 步，尾批 554 个有效锚点，两轮共 286 步，评测点为 0、143 和 286。三个正确配对在音频后的 marker 表示上计算余弦 InfoNCE，温度 0.1。错配复用异类录音与锚点卡，使用原概率间隔和双侧约束。

初轮按种子从每类至多取 4 条 TRAIN 录音，用初始模型对全部候选卡推理。每个正式 epoch 结束后用该轮新权重对全 TRAIN 的 109,610 条录音与 68 张卡打分。两类之间的混淆度为双向误配概率的均值，各方向按真实类别录音数归一化。对每个锚点类，将其余 67 类按混淆度排序，依照 Zipf 分布抽取负类，权重为排名的倒数，同分均摊，类内均匀抽录音。按 epoch 冻结概率表和种子，保存各类分母、原始混淆表和 checkpoint 身份。


**第一轮交接修订。** 181 的正式训练在全部八个 rank 提交第 143 步记录并校验该轮检查点后停止。统一入口复用冻结 TRAIN、声学缓存和已停机的检查点，以八个独立 NPU 实例计算规则卡 sigmoid 概率。容器内存上限 1 TiB，每卡批大小 128、8 个读取线程、有界预取 16 条录音。全量前在八卡用旧 FSDP 前向和独立实例分别打分，要求概率误差不超过 0.000002，Top-1 和类别混淆排序一致；独立实例的 32 行逐录音对照与 128 行合批还须逐值相同且每卡至少有一个满批。

按冻结的录音 ID 排序并切八份，每个进程只加载自己的清单，将共同的特征缓存描述与录音信息合并。每卡每 64 条录音原子提交一个块。打分块按实际 JSON 键类型计算摘要。断点重跑逐块核对前序包的冻结身份、样本顺序及内容，只复用通过校验的完整块；跨包只允许断点序列化兼容修复，打分输入和模型执行保持一致。完整审核按标签重算混淆统计，绑定第 143 步 checkpoint 的哈希，供第二轮负类采样使用。第二轮先验收优化器恢复，再启动第 144 步；第 143 步与第 286 步分别登记。
