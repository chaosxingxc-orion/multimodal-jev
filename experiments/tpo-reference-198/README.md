**确定的输出原因。** 正类项平均改善，被负类项的恶化抵消并超过。分项使用原始评分的同一分母 N×K，可以直接相加；跨数据集的 K 不同。SLURP 回退中有 22 条真类并列第一，MINDS 有 4 条；固定顺序打破平分并非主要原因。SLURP 有 630 条回退的错类比真类高至少 0.1，MINDS 有 537 条。两类失败都存在：高分相撞，以及明显选错；统一调阈值或单调温度变换不能恢复变化的类内名次。

**例证。** SLURP 的 datetime_query → qa_factoid 有 148 条新增错误，中位代表录音的真类为 0.4012 → 0.9931，两版各自最强错类为 0.1128 → 0.9993；general_quirky → qa_factoid 有 126 条，中位代表真类 0.3794 → 0.0031，名次第 1 → 11。MINDS 的 cash_deposit → direct_debit 有 166 条，中位代表真类 0.4822 → 0.6316，最强错类 0.0474 → 0.9230。具体 ID 与完整对照见 JSON；这些是观察到的标签混淆，不是音频含糊或标注缺陷的证据。

**Choice 的收益来自哪里。** 从完整 Choice 分数中暂时排除 NONE，再算候选内部准确率，SLURP 为 84.47% → 75.01%，MINDS 为 71.66% → 65.63%。与此同时 NONE 误拒率从 99.87% → 0%、100% → 19.88%。模型明显更肯选，但选项间辨别力在这个口径上下降。此面板没有正确类缺席的请求，不能判定 198 的真实拒选精度。

**这次究竟优化了什么。** Noul 奖励是在初始 TRAIN 概率上离线生成的每候选 yes/no 效用差 A。真类有按类频率倒数缩放的 utility（权重 1）；排序项（1）在加入 utility 后，用真类与最强负类 logit 的 ln(2) 间隔不足量，抬高真类、压低近邻。概率间隔为 0.1（权重 1）；存在性与最强错类成本各 0.3，跨录音混淆对比 0.3、同义配对一致性 0.1。后五项取初始概率处的负成本导数，逐项截断到 ±1 再加权，不是在每一步直接优化这五个 loss。198 训练用 q=sigmoid(stopgrad(z_current)+A/τ)，τ=1；197 用冻结初始先验。每条 Noul loss 是 60 个 Bernoulli KL(q||p) 的均值。Choice 命中时给真类的条件 softmax logit 加 1，用 KL 投影拟合；缺席时不做条件排序。覆盖 marker 的目标 logit 在命中时 +1、缺席时 −1。这个目标校准的是列表是否覆盖答案；条件 softmax 对所有候选同时加常数不敏感。

**机制解释及证据边界。** 4,224 次 Noul TRAIN 曝光上，真类、旧最强负类、全部负类的奖励 shift 中位数分别 +2.529、−1.484、−0.005。只有 0.31% 的负项 shift 为正。负奖明确存在，但最强的惩罚针对原始对手；新冒出的高分错类未被动态重选。动态分支刷新的是先验，A 保持冻结，因此没有固定先验将整体概率拉回。单候选的 logit 梯度（未计批权重）是 (p−q)/K。例如 p=0.99 且错类 shift 为 −0.005，q≈0.98995；虽明确该压低，此步梯度约 8.3×10⁻⁷（K=60）。这是解析例子，不是实测某条录音。两臂都有 23 步 Choice、11 步 Noul；198 两任务的裁剪前梯度范数中位数为 1.809 和 0.0806，超过 1.0 的分别 23/23 和 0/11。197 为 1.854 和 0.1344。与共享参数中 Noul 对漂移修正较弱相符；这些范数不是梯度方向或 Adam 参数更新贡献，不能据此证明 coverage 梯度推高了每个错类。也没有证据单独归因于声学、LoRA 容量或少数词。

**下一项区分原因的实验。** 保留 198。先仅在 clean TRAIN 上用初始与 198 在相同请求上标出新旧最强负类是否更替，关联旧 A、当前 p−q、概率间隔；同时测 Choice 条件排序、覆盖与 Noul 梯度在共享 head 和 LoRA 上的方向。若新对手确实拿到近零的惩罚，先做一个变量的对照：沿用 198 的动态先验、数据和预算，仅按当前 detached TRAIN 分数重选负例并刷新 Noul 的竞争项，保留其他奖励；若新对手已有强惩罚而绝对概率仍漂，另做仅增加固定 Noul 概率锚点的对照。每轮同时报告正负 NLL/Brier、真类与最强负类的间隔、候选内准确率、金标在/不在列表时的拒选表现。测试面板只作诊断；SIB-FLEURS 主迁移结果与重复种子仍需独立验证。

**对抗核查：真类缺席时，Choice 会不会直接奖励错误标签？** 对 198 封包中实际调用的 `context_choice.projection` 做 CPU 自动微分，两个候选加 coverage 的初始 logits 均为 0，reference 为其 detached 副本，T=β=reward_gain=1。真类不在列表（gold=-1）时，三个输出的 loss 梯度依次为 [0,0,+0.231059]；真类为第二项时为 [+0.231059,-0.231059,-0.231059]。梯度下降取负号。编译器显式返回 -1；clamp_min(0) 只保证 one_hot 索引合法，奖励和整个排序 KL 都受 hit mask 控制。2,829 个缺席曝光不直接监督任何候选 logit。NONE 是 1−sigmoid(g)，不与候选共做 K+1 softmax。命中时条件排序只识别相对差：对全部候选 logits 同加常数不会改变 loss，而独立 sigmoid 会变化。

198 用同一个浅层 Transformer、输出投影和可训练主干 LoRA 读所有 marker。coverage 位置的损失因此可以经共享参数改变下次 Noul 输出；输出梯度为零不等于共享参数的梯度为零。更新方向取决于两种输入的参数梯度夹角，命中与缺席对 coverage 的方向也相反。没有逐步梯度方向证据，不能归罪于缺席样本。另读取三个真实 checkpoint 的共享标量 projection.bias：初始 −0.005402、197 −0.005341、198 −0.004852；198 与 197 的差仅 +0.000488 logit，单一全局偏置本身也不可能改变名次。大幅、因类别而异的端点漂移必须涉及输入依赖的表示或投影权重。

建议下一版只实施清晰的职责隔离：保留候选成员判决读出，继续用 Noul 和命中 Choice 的排序训练它；coverage 使用单独的小读出，以 detach 后的既有上下文表示为输入。缺席样本只更新 coverage；命中样本的条件排序仍可学习共享语义。独立读出应带角色路由、显式版本并进入 checkpoint / reference / 评测加载合同；旧模型按原合同读取。用混合命中/缺席 macro 的 CPU 梯度路由测试检查 coverage-only 反传对共享 head、候选读出和 LoRA 的梯度均为 None/0，并对冻结音频确认训推一致。此修改排除 coverage 的直接参数串扰，但不会自动修复条件排序对绝对概率不敏感或冻结负奖励过时。若只需锁定现有根因，优先在已有 TRAIN 小批上单次分解梯度，记录 coverage 梯度与 Noul 强错类 logit 梯度夹角，按 hit/miss 分开；无需新训练臂。不得依据测试集挑训练样本或调阈值。
