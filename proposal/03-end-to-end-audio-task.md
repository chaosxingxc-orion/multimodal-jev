# 端到端语音任务路线修订

> 本页是仍然有效的路线硬约束。具体任务、训练和评测范围以
> [工程索引](../docs/engineering/README.md)和
> [协作指南](../docs/collaboration/simple-task-rl-engineering-guide-v1.md)为准。

用户明确要求：音频与业务任务定义 → 同一个语音多模态模型 → 任务结果。
不经过显式转写再调用独立文本语言模型。此要求覆盖此前串联路线设计。

已停止串联FSC测试容器，取消FSC-p1测试和SLURP串联探针的监督进程。
已有串联结果、远程教师成本和失败证据保留，但不计入端到端收益。
SLURP全量音频校验、原生数据导出及官方评分器工作继续，均与推理路线无关。
工程入口拒绝串联配置，旧转写教师与复用调度入口已停用。

后续先在Qwen语音骨干上锁定直接音频任务接口，原生FSC/SLURP和Jev六视图
均让actor直接消费音频。已有Qwen3-ASR-0.6B音频直读完整FSC测试的
0/3793严格任务正确率保留：它说明当前checkpoint与提示不能满足该输出
协议，不表示转写能力为零，也不能通过附加文本模型把此缺口绕过。

需要区分三种端到端实现：原生语音多模态模型生成任务JSON；冻结骨干直接
对任务给定的有限标签读取下一token分数；在语音骨干之上训练任务读出/typed
Jev头。第二种不训练，但格式由程序保证、概率只在候选内归一化，不能替代
开放槽位生成；第三种需要任务训练，不得称为无训练基线。
Qwen ASR仍是主要参考骨干；其他直接听音频的指令模型只能作为显式注明的
外部对照，不能无说明地替代主模型。

冻结基线与离线教师优化优先级保留。教师应读取直接音频actor的真实学习集
输出、任务定义、评分及必要的离线诊断，不能把转写再送入文本决策模型。
若直接actor无有效组内对比，记录无信号，不虚构提示优化效果。

后续权重训练继续围绕同一个端到端actor：先任务SFT/读出适配，再在固定
预算与同骨干对照下验证verl强化学习、vLLM推理、奖励与跨任务泛化。
历史HF/vLLM概率差阈值与失败仍保留；训练队列不因路线纠正自动恢复。
